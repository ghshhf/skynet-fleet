# RFC：免费外部算力中继（Free Compute Relay）

> 分支 `rfc/free-compute-relay` · 与主线「只用自建节点」不同的发散方向
> 状态：提案（未合入 main）

## 0. 一句话

用户现在用的就是**免费算力**（免 key 的 LLM 端点）。当天网工程编队里**没有任何 AI 节点在线**、或任务很轻不值当开本地模型时，Commander 把请求**中继**到这些免费外部端点，结果回瘦客户端，并缓存进 L3 避免重复打源。

## 1. 已侦察到的免 key 端点（过往积累）

| 端点 | 类型 | 备注 |
|---|---|---|
| pollinations.ai | 文本/图像 | 免 key，GET/POST，限速 |
| llm7.io | 文本 | 免 key 聚合，模型多 |
| kilo.ai | 文本 | 免 key 额度 |
| OVH AI Endpoints | 文本 | 免 key 额度，欧洲节点 |

> 这些是**降级源**，不是主力。主力仍是编队内 AI 节点（手机/电脑），因为：可控、隐私、无限速。

## 2. 架构

```
瘦客户端 → Commander ──py──► [AI节点? 有 → 用]
                              │否
                              ▼
                     free_relay.probe()  选一个活着的端点
                              │
                     POST prompt（不含隐私）→ 文本
                              │
                     L3 缓存（hash(prompt) → result），下次直接命中
```

## 3. 关键设计

1. **多源故障切换**：A 挂换 B，带指数退避；记录每个端点的最近成功率，路由时优先健康的。
2. **隐私闸**：发往外部端点的 prompt 必须过一遍「隐私过滤器」——含本机路径、账号、密钥、个人信息的请求**拒绝外发**，只允许走内网 AI 节点。
3. **缓存**：`sha256(normalized_prompt + model)` 存 L3，命中直接回，减少免费源压力（免费源都限速）。
4. **可关**：默认关闭，用户显式开启才外发；关闭时行为等同主线（无 AI 节点就报错）。

## 4. 最小实现

`free_relay.py`：

```python
def probe() -> list[str]        # 探测活的端点，按健康度排序
def chat(prompt, model=None)    # 依次尝试，成功即返回
def _privacy_ok(text) -> bool   # 隐私过滤器
```

## 5. 风险

- 免费端点无 SLA、可能被墙、可能突然收费 → **永不作为唯一算力**。
- 内容审查 / 数据留存不可控 → 只发非隐私、非敏感的通用请求（如「写段排序代码」）。
- 限速 → 必须缓存 + 退避，不能当高频调用用。

## 6. 与主线关系

主线把算力全押在自有节点；本分支承认「**免费算力也是算力**」，作为**兜底层**。二者不冲突：有自建节点用自建，没有才外发。这正是把过往侦察成果（免 key 端点）接入编队的路径。
