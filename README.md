  - **临时节点下机即清**：节点上报 `session=True` 后断开，自动触发 `session_end` 策略——**真清**而不是打日志：撤销该节点入网凭据（PSK）、作废其配对/卸载令牌、丢弃它的离线排队命令，并写一条流水审计「清了几样」（E-7 可逐条删）。以前这步只 print 一句「已清理」，自检里也看不出来到底清没清。
  - **多控制面仲裁（`arbiter.py`）**：全编队**只有一个领袖控制面能发令**，其它待机——否则两台机器各发各的，状态立刻分叉、她在备用面批的权限主面不认，「一个意图扇出所有设备」就破了产。选举=共享状态文件里的声明（rank 高者优先 → 先声明者 → id 全序），领袖每 15s 续期、45s 不续期即让位；待机面 REPL 仍可看（nodes/her/journal），但 exec/broadcast/compute/ui/intent/enroll 等**发令类命令一律拒绝并点名领袖是谁**；正常退出主动让位，备用立即接管（不等 TTL）。单机常态零配置（一张声明即成领袖）。**诚实边界**：仲裁是协同不是安全边界，跨机器共享盘仍有极小写窗口。
  - **exec 白名单收紧**：三层拒绝——① base 不在白名单 ② 参数含 shell 元字符（`& | ; < > \` $` 换行），因为节点侧 `shell=True`，`echo ok & del x` 这种 base 是 echo 却能干任何事的组合是白名单最大的洞 ③ **解释器默认禁止**（`python/powershell/cmd/bash` 等于任意代码执行，要跑脚本须显式 `FLEET_ALLOW_INTERPRETER=1`）。拒绝理由分类型回执给人看，不再只给 `rc=-1`。
  - **扫码入网（`enroll.py`）**：手机出示一张二维码载荷，设备扫一下即可入网，不用在新机器上敲密码。载荷是 `fleet://enroll?p=...`（约 230 字符），**可离线验签**（HMAC-SHA256 + 共享密钥，不联网、不回调控制面）、**一次性**（兑换落本地账本，截图外流也只是废纸）、**有时效**（默认 10 分钟）、**绑节点**（A 的载荷装不成 B），且**不含用户密码**——装完节点用随机 PSK 认证，明文密码不再写进计划任务参数。载荷寿命与节点凭据寿命**分开**：码 10 分钟过期，PSK 长期有效（否则一重启就失联），撤销走 `enroll_revoke`。REPL：`enroll <节点> [有效期秒]` / `enroll_list` / `enroll_revoke <节点>`；安装侧 `install_windows.py --enroll "<uri>" [--dry-run]`。
  - **分权（`accounts.py`）**：账号是「人」，节点是「设备」，两维分开。**主号唯一**——能发令、能发码、能增删分号、能看全部；**分号只能被控**——没有发令权，只能看到自己名下节点（过滤在控制面做，不在客户端做，否则改个脚本就绕过了）。闸门顺序刻意是**先分权、再仲裁**：分号即使占了领袖位也拒，因为没有权限跟谁是领袖无关；两道闸失败语义也不同（分权是安全、拒绝即拒绝；仲裁是协同、状态文件坏了就放行）。令牌自带角色与过期时间，并带权限版本 `pv`——**吊销分号后旧令牌立刻作废**，不等自然过期。**授权码**（用户要的「密码生成器 / 扫码同步权限」）是**同一枚一次性码的两种呈现**：终端里念 6 位短码，手机上画二维码；6 位用去掉 0/O/1/I 的 32 字母表（≈10 亿组合）+ 5 分钟寿命 + 一次性；二维码载荷 `fleet://grant?p=…` 用账本自带密钥签 HMAC，**伪造载荷在查账本之前就被拒**。与入网码刻意分开：入网码离线验签（装设备时可能没网），授权码必须中心验（改权限不能交给客户端自己认）。**诚实边界**：没有找回密码——主号忘了只能删账本重建（会连带吊销所有分号），因为找回通道本身就是后门。
  - **主动发现（`discovery.py`）**：不问「你是谁」，自己看、自己猜、自己归类。三条路互补——**组播询问**（SSDP M-SEARCH + mDNS 手写 DNS 解析，设备自己举手报名，信息最准）、**邻居表 + OUI**（读 arp/ip neigh，零打扰，靠 MAC 前三字节查厂商）、**特征端口组合**（单端口只能投票，`9000+554+23+8080` 这种**招牌组合**才定案）。实测在真实局域网上认出了具体型号：`HIKVISION DS-2CD2T10FD-I3`（6 台，连序列号都有）、`TPOS/1.0.0 UPnP/1.0 YLWR1200G易展版`（TP-Link 路由）。三条铁律写在代码里：只在本网段活动（跨网段直接拒）、只对 ARP 表里已存在的 IP 敲端口（不做全网段暴力扫描）、**发现 != 入网**（结果只进发现账本，要成为节点仍需在设备上装 agent 并入网）。**踩过的坑**（都是真实误判，已修）：① 9000 端口曾被当成「编队节点」——它同时是 Portainer/海康 SDK 端口，等于把陌生人当自己人；② `192.168.0.255` 广播地址曾被列为设备；③ 一台开 554 的 Windows 电脑曾被判成摄像头，而它的 mDNS 明明写着 `Microsoft-Windows + iVCam`——**设备自报的身份永远压过端口投票**；④ 多网卡机器不显式绑网卡发组播，一个响应都收不到；⑤ 隐私随机 MAC（本地管理位=1）查 OUI 必然为空，不能当「厂商缺失」。
  - **扩散扫描（`sweep.py`）**：把「ARP 表里有的」扩成「整个网段在场的」。上一版只读 ARP，等于只看见**最近跟本机说过话**的设备——这才是「只扫到 30 台」的真因。四条补齐：**ICMP 全段 sweep**（并发 ping 整个 /24，活着的全部进 ARP 表）、**TCP connect 兜底**（IoT 常关 ICMP 却开着端口）、**NetBIOS(NBNS) 名字查询**（Windows 会把机器名报出来）、**mDNS 服务类型枚举**（`_services._dns-sd._udp.local` 让设备自报有哪些服务）。另加两层：**多网段**（本机每张网卡都扫，实测找回被漏掉的移动热点段 `192.168.137.0/24`——手机就在那里）与**环境画像**（摄像头密度、运营商 IPv6 前缀、OUI 批次）。实网 44 台 / 15 秒 / 两个网段。**踩过的坑**：① 本机 `192.168.0.103` 曾被判成「NAS/存储」（因为本机自己开着 139/445）——比漏发现更糟；② 广播地址 `.255` 曾被当成设备；③ 5555 端口曾被判成「手机」，实际那是安卓一体机/中控终端。**边界**：只发 ICMP/TCP/NBNS PTR，不发应用层指令、不试口令；跨网段「跳板扩散」不做——那需要别人机器上的执行权，现在没有也不该去拿。

- **有连接即入网 · 可达层（2026-11-01）**：天网过去的模型是「**先入网，才有网**」——
  装 agent → 密码入网 → 账本里一条记录 → 然后才有能力。这个模型对内网自建是对的，
  对**世界上其他设备**是错的：一台同事的笔记本、主人手机上现成的 App、一块能连上的
  开发板，全都进不来，不是因为连不上，是因为「没走入网流程」。
  这轮把拓扑改成**两个同心圆**：

  | 圈 | 判据 | 能做什么 | 怎么来的 |
  |---|---|---|---|
  | 内圈 · 编队节点 | 入过网（有 PSK、账本有记录） | 执行命令 / 算力 / 改配置 | `enroll` / `install_windows.py` |
  | 外圈 · 可达对端 | **只要连得上** | 传文件 / 读名片 / 被看见 | 组播发现 / 探测 / 发送成功 |

  - **设备身份 = fingerprint，不是 IP**（照 LocalSend `discovery/store.rs` 的语义，
    那套已被上亿次安装验证过）。同一台手机换了网段、换了协议、走了热点，都还是它；
    拿 IP 当身份的话，手机一换 WiFi 就长出一个新设备，账本里全是鬼影。
  - **一台设备 = 多条通道**，每条各自 `available` / `unreachable`。断一条**设备不消失**
    （锁屏 30 秒 ≠ 掉网），全断才从默认列表隐去、账本仍留；再通自己回来，
    且失败计数清零。排序规则同 LocalSend：**可用优先 → IPv4 优先 → 最近确认优先**。
  - 🔴 **这两个圈之间那道墙，是这轮最重要的东西：可达 ≠ 可执行。**
    外圈设备**不会**被注册成一张 `BaseDevice`，所以它们天然进不了 `reg.call(...)`
    的目标列表 —— 不是靠「记得别调」，是**结构上够不着**。
    局域网里能连上我们的东西包括同事的笔记本、访客的手机、打印机、摄像头；
    如果「连上了」等于「可以在我这边执行命令」，这功能本身就是个洞。
    LocalSend 敢做「连上就互传」，正因为它的协议里**只有传文件**、且文件由对面的人
    自己点接受。我们把线画在同一个位置：**外圈只能做「对面人会自己确认」的事。**

  **三个实测踩出来的坑（都修了，都写进代码注释）**：
  ① **只 bind 一个 `0.0.0.0` 的 socket 只能看一张网卡**。「有连接就有网」的前提是
  承认连接可以有好几条（有线 + 手机热点 + USB 共享），另外几个网段的设备一个都听
  不到，表现是「明明连着却扫出 0 台」。改成**一张网卡一个 socket、各自 bind 各自
  join**（LocalSend 也是每个接口一个 `SendSocket`）。
  ② **发现不是「听广播」**。真实链路是「我 announce → 对端**用 HTTP 向我发 register**」。
  只听 UDP 的话，能听到的只有正好也在广播的设备；安安静静开着等被叫的那些，
  回执全打空。所以扫描期间要临时开一个 TCP 收件口。
  ③ **announce 里报的端口必须真的是我们在听的那个**。报 53317 却绑在别处，
  对端照报的端口回 register，直接 `10061 连接被拒` —— 看着像「对方不响应」，
  其实是自己报错了门牌号。

  **诚实边界**：只做 v2（不做 v1 / 不做 download API）；接收端**只支持 HTTP**
  （在本机起 TLS 要管自签证书，没做就是没做）；客户端侧连 HTTPS 对端**不校验证书**
  —— 这是协议本身的设计（首次信任 + 指纹人工核对，指纹会回写在结果里），不是偷懒。

- **跨 NAT 打洞 · 网络层的最后半程（2026-11-01）**：上面那层解决的是「本来就在一张网里」。
  真实世界不是这样：一台机器在手机热点后面，另一台在公司防火墙后面，中间隔着两层
  甚至三层 NAT。打洞的价值不是「能连」——中继也能连；是**流量不过第三方服务器**：
  快、便宜、不被别人看见。

  **本机实测的网况（这是判定的依据，不是猜的）**：

  | 维度 | 实测 | 怎么测出来的 |
  |---|---|---|
  | 映射行为 | **Endpoint-Independent** | 同一个 socket 发往 miwifi / bilibili / hitv / cloudflare 四个不同 IP，外部端口全是同一个（连采 6 轮，6/6 一致） |
  | 过滤行为 | **Address-and-Port-Dependent** | 请求服务器从别的 IP+端口回包，两个方向都收不到 |
  | 综合 | **端口限制锥形** | 能打洞，但**必须双方同时发** |
  | 出口映射 | `111.196.134.83` | STUN 反射地址（联通） |
  | 公网 IPv6 | **有** `240e:404:1900:c780::/64`（电信） | 2026-11-01 复测更正：原先记「只有 fe80」是错的。`ipv6.baidu.com` / `taobao` / `test6.ustc.edu.cn` 三项出网全通（0.21~0.59s） |

  - **判定标准用 RFC 5780 的两维，不用 RFC 3489 的四类。** 那份 2003 年的分类已被取代：
    真实 NAT 不按四类走，最典型的是「映射端点无关 + 过滤很严」被塞进 Restricted Cone，
    于是程序按错误前提打包，怎么打都不通。RFC 5780 拆成**映射行为**与**过滤行为**
    两个独立维度、各三档，组合才是真正的网况。
  - **测试顺序是硬要求**：RFC 5780 规定过滤测试之前不能向备用地址发过包。先做映射
    测试（会往备用地址发 binding）就会污染过滤测试——我第一次实测就得到「换 IP 通、
    换端口不通」这种自相矛盾的结果。所以代码里**固定先过滤、后映射**，两者各自独立 socket。
  - **映射行为必须多轮采样，不能测一次就下结论。** 本机一次采到 `[0,0,0]`（EIM），
    紧接着另一次采到 `[0,3,0]`（看着像对称）。手工连采 6 轮才看清：**6/6 轮内部完全
    一致**，那次是 CGNAT 的瞬时抖动（丢包重传导致映射重建，或负载均衡瞬时切出口）。
    只测一次会把「偶尔抖一下的锥形」判成「对称」，然后所有连接都被送上中继——
    功能能用，但白绕一跳，而且再也发现不了本可以直接打通。所以按轮采样、
    用**轮内一致率**说话（`stability`），抖动用 `unstable` 如实标出，不静默吸收。

  | 能力 | 性质 | 干什么 |
  |---|---|---|
  | `nat.profile` | 只读 | 我在什么网里：映射/过滤行为、能跟谁打通（约 3 秒） |
  | `nat.map` | 要审批 | 跟网关要一个固定对外端口（UPnP / NAT-PMP） |
  | `nat.open` | 要审批 | 开打洞会话，拿到本端候选（含公网映射），**有寿命** |
  | `nat.punch` | 要审批 | 朝对端候选猛发，同时收对方的（**双方都要调**） |
  | `nat.sessions` / `nat.close` | 只读 / 有副作用 | 看会话 / 关掉并释放端口 |

  - **为什么打洞必须双向。** 本机是端口限制锥形（APDF），过滤表只放行「我先发过包的
    地址」。只有一方猛发、另一方干等，等的那方永远收不到——它还没往对方那儿发过。
    所以协议是：各自 `nat.open` 拿候选 → 交换 → **两边同时 `nat.punch`**。少一边
    就打不通，这不是实现偷懒，是 NAT 的规则。
  - **没有内置信令，是故意的。** 「两台机器怎么交换候选地址」天网里已有至少三条路
    （局域网发现、WS 隧道、relay），各自的凭据和生命周期都不一样，硬塞一个进这层
    只会让上层没法复用。这层只认一件事：**你把对端候选给我，我就去打。**
  - **端口映射是提高成功率，不是保证。** 本机网关 `192.168.137.1` 是 Windows ICS，
    既不应 NAT-PMP 也不响应 SSDP——这条路在本机走不通（换个直连家用路由就能用）。
    而且就算映射成功，也只能打穿**自己这一层** NAT；上面的运营商 CGNAT 不归你管。
    真正 100% 的兜底只有中继。

  **三个实测踩出来的坑（都修了，都写进代码注释）**：
  ① **打洞包的 nonce 各用各的，就永远认不出对端。** 早期让两端各自随机生成，收到对方
  的包时拿自己的去比，永远不匹配——表现为「明明打通了却报超时」。nonce 是**会话 token**，
  必须由信令统一。门禁里专门有一条钉住「nonce 不同 ⇒ 打不通」。
  ② **打通后的前几个包全是打洞残留。** 打洞是猛发一批，那一批还有相当一部分在路上；
  直接当业务数据解析，就会在「刚连通时恰好出错」然后自己恢复，这种偶发 bug 极难复现。
  `recv` 里过滤掉带标记的控制包，一次解决。
  ③ **串行探 4 个 STUN 服务器要 40 秒。** 「随处可测」如果测一次要等半分钟，这能力
  等于没有。改成同一 socket 并发发、按 txid 收（不同服务器回包靠 txid 区分，不会串），
  体检从 **39.8 秒降到 3.07 秒**。

  **诚实边界**：只做 UDP 打洞 + TCP 同步打开的原理（未接进主链路）；生日攻击与端口
  预测只给了算法和预测函数，没有做高密度扫描（那会被对端防火墙当扫描）；WebRTC
  （STUN + TURN + 信令，1400 行 Rust）没做；接收侧 TLS 没做。**中继兜底**由 relay 那条线
  负责，这层只管打洞——打不通时如实说打不通，由上层决定降级。

- **隧道编排 · 先能用，再变快（2026-11-01）**：打洞是一个**动作**，不是一条**通路**。
  `nat.punch` 失败 = 会话废了、上层只能重试或放弃；而真实网络里打不通是常态
  （本机 APDF，双对称组合按机理成功率就低）。**一个只在好网络里能用的功能等于没有**，
  所以上面再叠一层：`tun.*`。

  设计取自两个开源项目，各要一半：

  | 来源 | 要的思想 | 落到哪 |
  |---|---|---|
  | [Warpgate](https://www.warpgate.io/)（Python，8 插件级联） | 级联 + 剪枝：只跑这对 NAT 真有可能成的策略；**打洞时刻由会话 id 的 hash 推出**，两端各算一次即对齐，信令只花一轮 | `cascade()` / `punch_at()` |
  | RavenFabric 的 DCUtR（libp2p 那套） | **永远不要等最优路径**：先连中继（立刻可用），后台探直连，通了平滑迁移，旧中继留作兜底 | `Tunnel` 状态机 |

  **IPv6 排在阶梯第 0 步，而且它不是「另一条打洞路线」——它让整套打洞变得不必要。**
  IPv6 没有 NAT，每台机器的地址就是它在全球的唯一入口：映射行为、过滤行为、端口预测、
  生日攻击、STUN 映射发现，这一整套存在的唯一前提是「NAT 后面没有稳定入口」，而这个
  前提在双 v6 下直接消失。所以正确顺序是「先问有没有 v6，有就别折腾 v4」；反过来做
  （先跑 40 秒 STUN 探测，再发现根本用不上）是纯浪费。
  ⚠️ 无 NAT ≠ 无墙：主机防火墙默认拦入站，必要时仍要开 pinhole；隐私地址（RFC 4941）
  会按小时轮换，不宜做长期候选。

    归调用方。格式归本层，通道归上层——这样脏数据在进入打洞阶段前就被校验掉，
    而不是拿脏地址去发几十万个包。
  - **打洞时刻依赖两端时钟大致同步**（默认都开 NTP，误差几百毫秒内），所以抖动窗口

- **对等中继 + 地址动态 · 「另类的固态」（2026-11-01）**：隧道层要的中继，和
  `wsrelay.py` 当时能做的那件事**不是一回事**——前者是「两台机器各自接进来，中继转发
  彼此的字节」，谁都不指定目标；后者是「WS → 某个 host:port」的**出口代理**，客户端
  说要连谁，服务端替它连。语义不同，所以不是加个参数，是加一条独立路径。

  | 新增 | 解决什么 |
  |---|---|
  | `wsrelay.py` 的 `/pair` | 房间配对，两端到齐即双向透传；一端走另一端必收 close（否则它在傻等，上层看到「连着」实际对端早没了） |
  | `wsrelay.py` 的 `/addr` | 设备指纹 → 当前地址的地址簿。**整份覆盖**而非增量合并：增量会让已消失的地址永远留着，对端去连空气 |
  | `wsrelay.py` 的 `/probe` | **从墙外回连我自己**。这是唯一可信的入站判据 |
  | `fleet/relay_pair.py` | 把 `/pair` 包成隧道认的形状；`send` 返回字节数，断了返 0 不抛 |
  | `fleet/rendezvous.py` | 动态检测 / 动态自检 / 自动切换 |

  **为什么入站自检必须放到墙外。** 本机往自己的公网地址发包走的是 hairpin NAT，
  很多家用路由器根本不支持。于是「本机自连成功」不能证明外网能连进来，
  「本机自连失败」也不能证明外网连不进来——**两个方向都是假信号**。
  只有站在墙外的机器来试才算数，中继正好在墙外。

  **「另类的固态」是什么意思**（主人原话）：会变的地址只要加一个动态就行。
  做完之后对外呈现的是一个**逻辑上固定、物理上可换**的入口——
  上层永远只认 `self_id`（设备指纹，跨重启跨网络不变），
  地址是它的属性，随便漂；漂了自动检测 → 自动上报 → 自动自检 → 自动切换。
  像 SSD 的磨损均衡：写的是同一个逻辑块，落在哪颗颗粒上用户看不见也不需要知道。

  所以 **IPv6 临时地址（RFC 4941）不再是缺点**。上一版我把它降权、当成「不适合做
  长期候选」，那是把「需要刷新」错判成「不能用」——而刷新恰恰是这一层的工作。
  现在它照收，只打 `temporary` 标记，稳定地址排前面。

  **IPv6 也从一个布尔值改成四档**（`tun.ipv6`）：`no-address`（一个都没有）/
  `local-only`（只有 fe80 或 ULA，路由器没下发前缀）/ `egress-fail`（有全球地址但
  出不去，缺默认路由）/ `ready`（出得去——但**出得去不等于进得来**，入站是另一道墙）。
  原先只有「有 / 没有」两档，会把后面三种全归成「没有 IPv6」，等于劝人放弃一条本来
  能走的路。本机实测：`ready`，出网 127ms，防火墙三档全开（v6 入站默认全拦）。

  `rdv.self / publish / verify / resolve / events / forget` 六条能力（+6 条）。
  门禁 **T57** 全离线（中继在本进程里起、两端走回环），钉配对 / 鉴权 / 超时 /
  整份覆盖 / 墙外自检 / 动态切换六件事。self_id 用 Windows `MachineGuid` 派生，
  跨重启跨网络不变——拿主机名当身份是错的，主机名恰恰是最常被改的东西。

  **诚实边界**：`/pair` 的 token 是 HMAC 共享密钥，挡得住随机扫描，
  **挡不住已经拿到 secret 的人**。中继不做自动重连——断了就是断了，
  自动重连会让「对端已经没在等」的房间被反复占用，并掩盖真实的断线原因。

  都是**手动**能力：地址变了得有人去 publish，能不能进来得有人去 verify。这一段补的

  而真正的原因根本不在对端。

  一轮的次序本身就是设计：先检测 → 变了才上报（没变就不动，省中继往返）→
  上报成功后再从墙外自检 → 两者共同定状态。反过来（先自检）会出现「地址簿里还没有
  这个地址就让人去连」，那不是网络问题，是自己制造的假阴性。失败按 1×2×4… 退避，
  封顶 5 分钟——别把一个临时故障打成长期骚扰。

  门禁 **T58** 里最要紧的一条：**测不了 ≠ 进不来**。本机实测踩到了——候选地址
  `port=0` 时中继回 `WinError 10049`（地址无效），旧逻辑把它当成「不可达」，于是
  一个「还没开监听口」的状态被判定成 `blind`，会让人去改一通根本没问题的防火墙。
  现在 `/probe` 对 `port<=0` 明确回 `invalid`，自检层标 `confident=false`，状态落
  `unverified`：「还没法测」就是「还没法测」。

  另外 `rdv.auto.status` **没配置时也能查**：上一版把配置检查塞进 `probe()`，结果
  没配置 ⇒ 设备不可用 ⇒ 连状态都看不到，恰恰在最需要看「缺什么」的时候看不到。
  诊断性能力必须永远可查。

  **地址簿现在落盘了**（`SKYNET_ADDR_STORE`，默认工作目录 `addrbook.json`）：原子写
  （tmp + replace）、写盘节流 2 秒、坏 JSON 只降级不阻断中继启动、只读磁盘则
  `persist=false` 如实标出「其实只在内存」。PaaS 会随时重启，纯内存等于每次从零开始。

  自动起来：`FLEET_RDV_AUTO=1` + `FLEET_WSRELAY` / `FLEET_WSRELAY_SECRET`，服务
  `start()` 时自动拉起（失败不影响主服务）。**不默认偷偷起**：没配置时它只会每轮报
  同一个错，那不是自动化，是噪音（+4 条：`rdv.auto.start/stop/status/events`）。


- **伪装登录两层：邮箱供料 + 有头注册（2026-11-02 凌晨）**：主人说的「注册谷歌邮箱 → 用谷歌账号正常登录」本质是**关联**不是攻破，所以这一段不造攻击能力，只造**通行能力**。两层分开落，谁挂了都不牵连对方——这就是可续。

  **第一层 `email.*`（+4 条）**：借免费临时邮箱当供料口，零成本不实名（付费 = 状态不可续）。三源实测全活：guerrillamail（主力，`sid_token` + `seq` 分页）／mail.tm（**必须带 `Accept: application/json`**，少这个头就报错）／maildrop（GraphQL：`altinbox` 建、`inbox(mailbox)` 读）。`email.wait_code` 把「轮询收信 + 正则提码」合成一步，直接喂注册流程。

  **第二层 `register.*`（+10 条）**：`open / close / list / goto / inspect / fill / submit / click / await_pass / save_session`。

  核心一句：**不自建浏览器，只接管浏览器**。Playwright 自己 `launch()` 时会塞 `--remote-debugging-pipe --no-startup-window`，窗口是假的、指纹是自动化的，Cloudflare 一眼看穿（HF 那次 headless 死在这一步）；改成「自己起一个完整 chromium，再 `connect_over_cdp` 接管」，浏览器就是浏览器，墙自己放行。

  **人机分工写成能力切分，不是写成流程**：`fill` / `submit` / `click` / `await_pass` 是四个独立动词。机器走完前三个，卡在图形验证码就「停在那里等人」，人点完第四个接着跑——**断点天然存在**，不用另造状态机。8 步里机器 7 步，真人只点那 1 下。

  **进程模型是刻意的**：Playwright 的 sync API 绑线程绑事件循环，而天网设备会被控制面任意线程调，在 asyncio 线程里 launch 直接炸。所以启停留在本进程（纯 subprocess），页面动作全部子进程隔离（`browser_reg.run_verb`）——单步超时、崩了不牵连 host。

  实测撞出四个 bug，全是「看代码看不出来、跑一次就现形」那类：
  ① **启动器误判**——Windows 下 `chrome.exe` 是启动器，fork 出真进程后自己以 code 0 退，旧逻辑把 code 0 当失败；
  ② **错误页被判成「没墙」**——`ERR_CONNECTION_CLOSED` 页既没墙也没内容，只看 `blocked` 会得出「过了」的假结论，现在 `error` 单列且**立刻返回**，不让人干等 180 秒超时；
  ③ **「页面过薄 = 挑战壳」是错的判据**——example.com 只有 1989 字节，被判成墙。墙只由**标题 + 挑战专用 DOM** 决定，过薄另立 `loading` 态；
  ④ **关不掉**——杀的 pid 是启动器，真进程还占着端口。改成「簿记 pid + `netstat` 反查 pid」两个都杀。

  **通道优先级（2026-11-02 03:37 更新，主人装了扩展之后）**：① WorkBuddy Chrome 扩展（真 Chrome、真指纹、还能接管已登录标签页走 OAuth 关联）＞ ② WorkBuddy 内置浏览器 ＞ ③ 本模块自建 chromium。前两条只在 WorkBuddy 会话内可用（MCP），天网是独立进程调不到，所以第三条必须留着，定位 = 兜底 + 无人值守。

## 作业层 + 产物中心（长任务的地基）

同步调用（`call`）适合「点一下、读一屏」，撑不住手机算力的真实形态——SDXL 实测 **179s/步**、视频生成、4B 长文都是分钟级。所以补了两层：

**作业层（`fleet/jobs.py`）** —— 把「提交」与「执行」拆开：

| 能力 | 说明 |
|---|---|
| `job.submit` | 提交长任务，进盘账本（`~/.fleet/jobs.json`） |
| `job.list` / `job.get` | 按状态筛、查状态历史（每次尝试都有记录） |
| `job.cancel` | 排队中/运行中都能取消；终态作业**如实说不必取消** |

三条硬语义：**① 租约**——节点领走后必须在 180s 内续租或回报，过期即判掉线；**② 掉线迁移**——过期未超次数就退回队列、清空节点，换台机器接着跑；**③ 永久失败不重试**——能力不认识/参数不可能对这类错误一次判死，不浪费别的节点再跑一遍。

REPL：`job submit image.gen {"prompt":"一只蓝鲸"} node=phone1` / `job list failed` / `job show <id>` / `job cancel <id>` / `job reap` / `job pump <节点>`。

**产物中心（`fleet/artifacts.py`）** —— 把文件变成有身份的东西：

- 内容寻址：`art-` + sha256 前 16 位，**同内容不重复存盘**，跨机器只认 id 不认路径；
- 元数据：kind / size / 来源节点 / 关联作业 / TTL；
- `artifact.put`（路径或 base64）/ `artifact.get`（回 base64）/ `artifact.list` / `gc`；
- 取不到时**分清「没这条」和「索引在但文件丢了」**，不冒充成功。

这层解开三个断链：换机引用不到、重复传输、记忆/技能无法指向一个产物。

**对外可见性**（自动，无需改三份清单）：两项都进了注册表与能力说明书，因此终端补全、MCP 工具表、「她」能看见的东西同时生效——只读项（`job.list`/`job.get`/`artifact.get`/`artifact.list`）默认导出给外部 AI 客户端，副作用项（`job.submit`/`job.cancel`/`artifact.put`）只在 `--unsafe` 下导出，且过注册表闸门（无 gate 一律 fail-closed）。

门禁：`evals/test_jobs_artifacts.py`（38 项，含状态机、去重、GC、注册表真表、MCP 导出）。

## 四原则（设计铁律）

1. **锚定最底层 OS 平台层**：只对接 Android / Windows / Linux / Apple 四大平台原生能力，绝不对接厂商 App / 云。米家 leaf（灯/插座/传感器）是 MCU+RTOS 非安卓，经你自控的 Linux/Android 网关桥接；Apple 标「半可达」（仅屏共/快捷指令）。
2. **单一自包含工具箱 + 反向推送**：不要求每台设备各自去公网下载 agent；由手机/家服持一份自包含工具箱（二进制+依赖+配置+幂等安装脚本），接触即推。
3. **病毒式执行模型（同源 RMM/MDM/远控）**：一次进入 → 提权到最高 → 无弹窗 → 常驻后台 → 可远程 → 叠能力。区分合法/恶意只凭三点：归属（是否有权管理）、同意（本人或授权人许可）、范围（只部署在有权限设备、不向他人扩散、不窃他人数据）。
4. **无条件最高权限 + 常驻 + 零运行时分支**：agent 内部不设「能不能推 / 是不是家」之类 if——拿到 admin 即提满、常驻、静默、可远程；**边界靠两道外部闸**（非运行时逻辑，故无 bug）：①管理员启动闸（OS 强制，无 admin 提不上去）②环境复位闸（重装/合规清理自清）。

> **L1 落点**：Windows = SYSTEM 服务 / 计划任务；Linux = systemd root；Android = 已 root 应用 UID。跨重启常驻；重装系统即清——**这是特性不是缺陷**（不被「删不掉」反噬）。L2 内核驱动（抗本机管理员卸）与 L3 固件级均**不做**。

## 终端：一个入口，一套命令

设备层的所有能力只有一个入口。加一个能力只改注册表一处，命令补全、MCP 工具表、
模型能看见的说明同时出现。（全屏那套与命令行本来就是同一套命令，2026-11-07 删除，
不再养两个面。）

```bash
# 命令行：双击 fleet-cli.bat，或
python -m fleet.shell

# 不进交互，只跑一条
python -m fleet.shell -c "caps phone"
```

`fleet-cli.bat` 自己找解释器（本机 portable → `py -3` → `python`），且每个候选都要
**真跑通一次**才要——Windows 商店那个存根会假装自己是 python（静默 exit=49），
不实测就会被它骗到。要用别的解释器：先 `set FLEET_PY=你的python.exe` 再打开。

**打包**：push 到 `main` 或打 `v*` tag 时，GitHub Actions 用 PyInstaller 构建
`fleet-gui.exe`（图形版，见 `PACKAGING.md`）。

### 网络层显影面（`net.status` / `net.route`）

网络层能力（`net.*` / `proxy.*` / `tun.*` / `nat.*` / `rdv.*`）以前散在 6 个模块，只能翻源码才知道状态。
现在收成两条**只读**能力，面板和模型都够得着，且只有一处来源、三处显影（不重算）：

- `net.status`：一屏看全——出向三路死活（自有内核 / 系统代理 / 直连）、代理内核装没装起来、
  分流规则集、P2P 会话、会合循环。
- `net.route host=xxx`：给一个域名，说清它**会**走哪条通道、凭什么这么判。

`tui` 顶部多了一个「网络」标签页（`ctrl+n`），只读 `net.status`；`fleet/gui/server.py` 对应
`GET /api/net?probe=1`。两者都**默认不出网**——只读、不探测就不声明通道通，缺数据如实报 `None`，不编。

## 真机部署（Windows）

```bash
# 1) 一台当 Commander（建议走 Tailscale 虚网，不在公网裸奔）
python commander.py --password 你的密码 --host 0.0.0.0 --port 9000

# 2) 另一台装常驻节点（管理员跑一次即永久常驻、无弹窗）
python install_windows.py --install --name PC-B --host <CommanderIP> --port 9000 --password 你的密码

# 2b) 或：扫码入网（推荐，不必在新机器上敲密码）
#     在 Commander 控制台签发 -> 把输出的 fleet:// 文本渲成二维码 -> 目标机扫/粘贴
enroll PC-B                    # 得到 fleet://enroll?p=...（10 分钟、一次性、绑 PC-B）
python install_windows.py --enroll "fleet://enroll?p=..." --dry-run   # 先在目标机验签看参数
python install_windows.py --enroll "fleet://enroll?p=..."             # 兑换并装（管理员）

# 3) 控制台
nodes                      # 看在线节点 + 能力
exec PC-B ipconfig         # 单点执行
broadcast echo 统一指令    # 一条意图扇出所有节点
ctx_put her key 值         # 写共享上下文（跨设备记忆）
compute 帮我写段代码        # 路由到算力节点跑重活（她三段式 ③）
computemap a;b;c          # 批量分发多算力节点聚合
computepool               # 看算力池
ui Her-Phone com.xx.app   # 让节点按规则库当前版本跳广告（--vision 走视觉兜底）
rules / rules_put <文件>  # 规则库：看版本 / 发布会自动带版本下发
rules_rollback 1          # 回滚（生成新版本，历史保留）
policy / policy_eval '{...}'  # 看生效策略 / dry-run 一个事件
arbiter                  # 多控制面仲裁：谁是领袖 / 本机是领袖还是待机
her / her_say 你在干嘛     # 看她的状态 / 让她现在说一句（走频控刹车）
her_memory                # 列出她能回忆的往事（隔日 12h–72h，可人工核对是否真的记得）
her_followups / done <topic>    # 看 24h 没闭环的账 / 告诉系统这事做完了（清账）
journal [n]                     # 回看对话流水（她起话题的依据都在这）
intent 巡检                # 统一意图编排：一句话 -> 多步带依赖 -> 失败逆序回滚
cap / token ...           # 她能力授权 / 配对设备令牌

# 4) 算力接真模型（任一节点设了即可，改环境变量即切换，代码零改动）
set FLEET_LLM_CMD=ollama run qwen3:4b
set FLEET_LLM_URL=http://127.0.0.1:8080
```

> 真部署须收紧 exec 白名单并走 Tailscale；当前白名单仅含演示命令。
>
> 排查通信问题：`FLEET_DEBUG=1` 打开后，收发帧、超时、连接 fd、以及周期线程栈都会打出来——
> 同类「帧已写出但对面没收到」的问题不必再猜。

## 安全与伦理边界

- **只管自己的设备**：部署在你拥有或被明确授权管理的机器上；不向无权/陌生机器推送，不窃取他人数据。
- **不碰恶意线**：不做 UAC 静默绕过（属提权漏洞利用）、不用 BYOVD（借漏洞签名驱动）、不写固件级持久化。
- **可清除**：L1 常驻重装即清；卸载须经密码闸门（`install_windows.py --uninstall --password ...`）。
- **合规兜底**：临时/公共节点（如网吧）采用无状态执行端 + 身份随身（记忆留手机侧），下机即清、不落凭据，与场所合规清理互补。
