# 人格载体的四层阶梯——本仓站在哪一层（2026-10-21）

> 主人在讨论角色卡生态时给了一张四层表：
>
> | 层级 | 代表项目 | 核心思路 |
> |---|---|---|
> | Prompt 注入 | SillyTavern 角色卡 | 人格写进 system prompt，零成本切换 |
> | LoRA 适配器 | Macaron V1 / MinT | 冻住基座，挂 LoRA 专家，MoL 路由 |
> | 插件化框架 | DeepSeek Harness | 一切皆插件，人格/工具/UI 全部可插拔 |
> | 技能自进化 | SkillOpt / SkillEvolver | 技能文本自我优化，不改模型权重 |
>
> 本文做两件事：①把本仓在四层里的确切位置标出来 ②把「角色卡只是第一层」这件事
> 落到本仓的架构判断上（哪些已经做了、哪些是下一站）。
>
> 结论全部基于本仓代码实跑（`persona_card.py` / `fleet/skills.py` / `fleet/mcp/` / `fleet/catalog.py`），
> 数字是实跑出来的，不是估的。

## 0. 结论先行（7 条）

1. 🔴 **本仓同时站在第 1 层和第 3 层上，而且第 3 层才是主线。**
   第 1 层（角色卡 = prompt 注入）：`persona_card.py` 849 行、6 张卡、21 个函数，**已完整实现**。
   第 3 层（插件化框架）：`fleet/` 包 + `fleet/mcp/` + `fleet/catalog.py` 74 项能力 + `fleet/skills.py`，**已落地**。
   ⇒ 主人那张表的四层不是「选一层」，本仓是**第 1 层的人格 + 第 3 层的框架**。
2. 🔴 **第 2 层（LoRA 适配器）本仓明确不做，而且理由是结构性的。**
   依据是**北极星项目的宪法 §4 E-7**（`D:/work/_local_ai/train_15b/CONSTITUTION.md`，
   跨项目铁律，本仓的「她的人格」也受它约束）：
   **个人数据只进「可寻址可删的记忆层」，不进被训练参数。**
   LoRA 适配器 = 训练产物 = 进了参数 = 走在这条线外面。
   ⚠️ **诚实边界**：E-7 有一条已登记的例外（2026-10-18 用户裁定）——
   「自有对话进入预训练权重属既定计划，不计为 E-7 违反」。
   **那条例外给的是「语料」不是「人格适配器」**：
   训 LoRA 的人格 = 把「她是谁」固化进参数，**恰恰是 E-7 最想防的事**。
   ⇒ 第 2 层不是「暂时没做」，是**架构上排除**。这条要写死，别以后被「LoRA 效果更好」带跑。
3. 🔴 **第 4 层（技能自进化）是本仓的真下一站，而且地基已经有了。**
   本仓 `fleet/skills.py` 已经做到：扫两个目录（本仓 `skills/` + 用户 `~/.workbuddy/skills/`）、
   认 `SKILL.md` + frontmatter、报明确错误不瞎猜。
   **实跑：扫到 37 个真实技能**（用户级 37 个技能目录，全部可读）。
   ⇒ 第 4 层要的不是「引入新框架」，是**给已有的技能装载器加「评估 + 迭代」**。
4. 🔴 **ClawHub 是第 4 层现成的上游，本仓 `skills.py` 的字段几乎一一对得上。**
   实测 `GET https://clawhub.ai/api/v1/skills?limit=3` 返回：
   `{ownerHandle, slug, displayName, summary, tags:{latest}, stats:{downloads,installs,stars,versions}, createdAt, updatedAt, latestVersion:{version, createdAt, changelog}}`。
   对照本仓 `skills.py` 认的 frontmatter 键：`name` / `description` / `version` / `license` / `agent_created`。
   ⇒ **「从技能市场装技能」是个几十行的活**，且这比「装角色卡」值钱得多（技能是方法论，卡只是数据）。
5. 🔴 **主人那句「角色卡本质上是结构化的提示词注入……运行时动态加载的人格插件，跟人格独立化方向完全一致」——
   本仓已经是这么做的，而且这是本仓的宪法要求，不是巧合。**
   卡不进模型权重，只进 system prompt；换人格 = 换卡，不重训。
   ⇒ 这句话可以直接作为本仓路线对外的正式表述。
6. 🔴 **「一切皆 MCP」是第 3 层在本仓的具体实现形态。**
   设备 = 内建 MCP server，外部第三方 = 外接 server，
   「连接器」Tab 是一张表用 `source` 字段区分 builtin/external。
   本仓对 DeepSeek Harness 的定位是「**要机制不要产品**」
   （见 `docs/无限智能体_DeepSeekHarness学习与落地_2026-10-21.md`），
   借的是它的编排纪律，不搬它的 Node 栈。
7. **本仓在四层阶梯上的位置，一句话：**
   > **用第 1 层（角色卡）承载「她是谁」，用第 3 层（MCP + 技能 + 能力注册表）承载「她能做什么、能怎么学」，
   > 永远不碰第 2 层（不让人格进参数），并在第 4 层上做「技能自进化」而不是「模型自进化」。**

## 1. 四层逐层对照本仓现状

| 本仓资产 | 实测状态 |

| 私有 schema 适配 | ✅ `aicc_card` 适配器（实测真卡：修复前 47 字空壳 → 修复后 522 字完整人设，**丢失 0 段**） |
| 现有卡 | 6 张：`大肥鱼`（人格本体）+ 5 张执行角色卡（研究员/程序员/编辑/批评者/验收者） |

**这一层本仓已经做完了，甚至比社区编辑器更严谨**（社区根本没做卡级注入防护）。
🔴 **所以第 1 层没有下一步了**——不该在这里继续加功能。

### 第 2 层：LoRA 适配器 —— ❌ 架构上排除

| 为什么不做 | 依据 |
|---|---|
| **走 E-7 外面** | 北极星宪法 §4 E-7：个人数据只进「可寻址可删的记忆层」，不进被训练参数。LoRA 权重 = 训练产物 = 进了参数（E-7 的已登记例外给的是「自有对话语料」，不是「人格适配器」） |
| **不解决本仓的真问题** | 本仓的瓶颈是「设备能不能被可靠操控」「她能不能记住并可删」，不是「人设表达力不够细」 |
| **可逆性差** | 权重训完就固化；要「撤销」只能重训或换基座，**做不到「可寻址可删」** |
| 本仓已有更好的 | 「换人格 = 换卡」是 **O(1) 换文件**；LoRA 是 O(训练) 换能力 |

🔴 **写死这条**：以后谁提「上 LoRA」，回 E-7 + 可逆性差两条，不是「以后再说」。

### 第 4 层：技能自进化 —— ⏸ 地基有，下一步

**已有的地基**：
- `fleet/skills.py` 完整实现装载（扫目录、解析 frontmatter、错误带原因）
- 37 个真实技能在位
- 本仓有 `evals/` 门禁体系（**54/54 通过**）⇒ **有「评估」的手段**

**缺的**（= 第 4 层要做的事）：

2. **技能迭代闭环**：评估结果 → 改写技能文本 → 再评估。**只改文本，不动权重**（这正是第 4 层与第 2 层的分野）
3. **技能来源接入**：ClawHub 的 `/api/v1/skills`（见 §2）

## 2. ClawHub：第 4 层的现成上游（实测）

### 2.1 端点

```
GET https://clawhub.ai/api/v1/skills?limit=3      → {"items":[…]}
GET https://clawhub.ai/api/v1/promotions            → {"promotions":[…]}
GET https://clawhub.ai/api/v1/cards?limit=3         → "No matching routes found"  ← 不提供角色卡
```

### 2.2 返回结构 vs 本仓 frontmatter

| ClawHub 字段 | 本仓 `skills.py` 认的键 | 说明 |
|---|---|---|
| `displayName` | `name` | 名字（`skills.py` 实际提取的字段） |
| `summary` | `description` | 描述（**技能触发靠它**；缺失时会退回正文首个标题，但会说明） |
| `latestVersion.version` | `version` | ⚠️ **frontmatter 解析器能读，但 `load_skill()` 目前不提取它**（要接就得加字段） |
| `tags` | — | 本仓暂不认，但可扩 |
| `stats.{downloads,installs,stars}` | — | 可做「热门」排序 |
| `latestVersion.changelog` | — | 可写进技能正文做「变更记录」 |
| — | `agent_created` | 本仓自有标记，ClawHub 无 |
| — | `license` | ⚠️ ClawHub 列表里**没给**；`skills.py` 也不提取 |

**本仓 `skills.py` 目前实际提取的 frontmatter 键只有 3 个**：`name` / `description` / `agent_created`
（外加 `source` / `dir` / `file` / `heading` / `body_len` 这些运行时字段）。
⇒ **接 ClawHub 要加 `version` / `license` 两个提取字段**，这是个小改动。

⇒ **字段高度同构**，「装技能」比想象的简单。

### 2.3 但要先把三个问题答了再动手

1. **许可证**：ClawHub 列表里没给 license ⇒ **下载前必须能看到 license**，否则违反本仓「许可人工过」纪律。
2. **技能是「提示词模板」还是「可执行代码」**：本仓的技能是**方法论文档**（不动手、不改外部世界），
   若 ClawHub 上有带可执行脚本的技能，**装进来就破了「能力要过闸门」的红线**。
   ⇒ 装之前必须区分「纯文档」与「带代码」。
3. **安全审查**：37 个用户级技能已经在本仓里了 ⇒ 装外部技能**必须过一遍审查**
   （社区有对照物：`archive-binary-audit` 技能就是干这个的，本仓已有）。

## 3. 本仓的架构判断（把四层表落成决策）

| 决策 | 内容 | 依据 |
|---|---|---|
| **D1** | **人格只走第 1 层**：角色卡（`persona_card.py`）+ PersonaState（`persona.py`：情绪/口癖/执念）+ 记忆层（`memory.py`：`SharedContext`），三块拼 system prompt | E-7 + 已实现；`memory.py` 有 `delete(ns, key)` 逐条删 ⇒ 「可寻址可删」是真的 |
| **D2** | **永不进第 2 层** | E-7 铁律；可逆性差；不解决本仓真问题 |
| **D3** | **能力/工具/UI 全走第 3 层**，且统一成 MCP 形态 | 「一切皆 MCP」+ 已落地 74 能力 + MCP 出口 |
| **D4** | **学习走第 4 层，但只改技能文本，不改权重** | E-7；本仓 `skills.py` + `evals/` 已是地基 |
| **D5** | **角色卡不再加功能**——它已完备；下一站是体检器（外来卡入口）+ 拉取器 | 上一轮 + 本轮实测 |
| **D6** | **本仓的差异化 = 安全性**（卡级注入防护 + 审批 diff 预览 + 门禁自证），不是功能数量 | 社区全是编辑器，红海；本仓的机会在「可信」 |

🔴 **一句话记住**：
> **本仓不是「再造一个酒馆」，是「造一个可信的、她的东西在哪都跑得起来、而且她学到的东西你能看见能撤销」的运行时。**
> 角色卡是她的「简历」，MCP 是她的「手」，技能是她的「习惯」，记忆是她的「经历」——
> **四样都不进她的权重。**
