④ 边界靠两道**外部闸**（管理员启动闸 + 环境复位闸），agent 内部零运行时分支。

**模型分工（总纲 v1 定死，不再讨论）**：0.6B 是「嘴」（永远在、<1s、断网可用、只负责像她），

   三条结论，一条比一条重要：

   ① **「工具太多」这个病，换个算力当场就没了。** 前一轮我按 52.9 秒的超时线

   ② **分域不是本地小模型的妥协，它是约束，对云端同样有效。**

      两级机制**不要因为换了算力就拆掉**——它省下的不只是时间，还有错。
   ③ **一级制在云端仍然值得留**（配 `AT_DECIDE_FULL=1`）：它少一次往返，
      适合工具面还会变、分域规则没跟上的过渡期。

   **落地**（`fleet/compute.py` + GUI 四个端点 + 桌面上一页「算力」）：
   - 注册表：10 个内置端点（免 key 2 / 付费 6 / 本地 2）+ 任意自定义。

     `ok`（真算过）/ `shallow`（通了但拿不到 usage，或没回出那个数）/ `fail`。
   - 路由 `route(purpose)`：决策/对话/看图/语音各选一个。档位
     **本机有 key > 免 key > 本机无 key > 远端付费**，探测结果只在同档内加减分。
   - 决策链路 `decide()` 现在认算力配置（`_decider_target`）：显式 url →

   | 关窗即退出 | `app.py` 只有 `webview.start()`，无 closing 钩子 | 想常驻就只能一直占着屏幕 |
   | 无托盘/自启 | 全仓 `grep pystray` 零结果、`winreg` 零结果 | 每天先找一下再双击 |
   | 窄窗口是「禁止」 | `WIN_MIN=(1080,680)`，而 CSS 唯一断点是 900 | 那条断点**从上线起从没生效过**；实测 456px 时「专家技能·连接器」一个字一行 |

   **落地四件 + 两个协同点：**

   - `fleet/gui/single.py`：命名互斥体回答「我是不是唯一那个」（进程死了系统自动
     释放，不留僵尸锁）；UDP 回环暗号回答「把在跑的那个叫出来」（回 ACK 才算成功）。
     **为什么不走 HTTP 唤起**：本地令牌是故意不落盘的一次性令牌，为了唤起窗口
     把凭据写上盘，是拿安全换方便。
   - `fleet/gui/tray.py`：托盘四项（显示窗口 / 开机自启 / 打开数据目录 / 退出）。
     关窗 = `hide()`，退出走同一个闸。图标现画，不依赖外部 ico（少一个打包失败点）。
   - `fleet/gui/autostart.py`：只写 `HKCU\...\Run`（不要管理员、只对当前用户）。
     状态三态 **off / on / stale** —— 残留指向旧副本时必须显示成 stale，
     否则界面上写着"已开启"、开机什么也没发生。
   - 窄窗口：`WIN_MIN` 1080 → 860，CSS 三级让位（900 收窄三栏 / 780 设备栏让位 /
     620 导航单行裁切）。

   **两条降级都写死了，因为静默降级比没有更坏：**
   ① 没装 pystray → 明确打出来 + 退化成"关窗即退出"；
   ② `--autostart` 想静默启动但**托盘起不来时不许隐藏窗口** —— 否则那是一个
      看不见也点不到、只能去任务管理器杀的进程。

   **真跑证据（不是"应该能行"）：**
   - 关窗：给窗口发 `WM_CLOSE` → `IsWindowVisible=False`、PID 仍活；再双击 → 窗口
     重新可见（`single.poke` 回 ACK）。
   - 自启：`--autostart` 起后窗口不可见、进程活；`poke` → True → 窗口变可见。
   - 注册表：`enable → state=on → disable → state=off`，幂等，收尾无残留。
   - 视觉：1440×900 与 860×600 两次真截图，侧边栏横排、设备栏在位、无塌。

   **门禁 `eval_t49`（29 条）一上线就抓到一个真问题**：`pystray` 没写进
   `requirements.txt` —— 后果是冻扁包里 import 失败、托盘静默降级，代码全对、
   能力没了、不报错。**和 10-22 的 `edge_tts` 完全同形。**
   ⇒ 依赖清单和生产代码里的 import 必须互相盯着，这是第二类「注释不是防线」。

   **真打出 exe 之后，又抓到第三个只有冻结形态才复现的 bug：**
   `dist/fleet-gui.exe` 连开两次 → **3 个进程、2 个窗口、两套服务各管一半编队**。
   根因：PyInstaller onefile **每次启动都解压到不同的 `_MEIxxxx` 临时目录**，
   而 `_default_key()` 拿的是代码目录 ⇒ 每次启动都是新 key ⇒ 互斥体名字跟着变
   ⇒ 单实例彻底失效。**源码形态跑一万次也复现不了。**
   修：冻结时 key 用 `sys.executable`（exe 自己的路径），源码形态仍用仓库目录。
   `t49` 补 [F] 段守着，并做了变异自证（去掉 frozen 分支 → 门禁立刻红）。
   ⇒ **新铁律：凡是"同一台机器上只许有一个"的东西，key 必须来自"安装位置"，
   不能来自"运行时才有的东西"（临时目录、进程号、时间）。**

   **还没做**：安装包（Inno Setup / MSIX）、首次运行引导、卸载时清 `Run` 项。
   这三件都建立在"exe 能打出来且能跑"之上，先打包再说。

### 跨机接入六判据（2026-10-25 实战：接入绕三个弯 + 接通后又两个坑）

工具：`tools/netdiag.py <host:port>...`（默认带本机网卡分类）。前四条必须按序用，跳步必错：

1. **TIMEOUT ≠ 被防火墙拦。** Windows 对「没有监听」的端口也常静默丢包，两种原因在外部
   完全同形。**超时只能读成「这条路上没有能接的东西」**，要分叉必须去端上看监听表
   （`Get-NetTCPConnection -LocalPort N -State Listen`）。
2. **REFUSED(RST) 才是好消息。** 回了 RST 说明包已到对方 TCP 栈：路通、防火墙放行，
   只是没人接。此时该查「程序跑没跑 / 绑没绑 `0.0.0.0`」——绑 `127.0.0.1` 时外部一律 RST。
3. **本机测本机不算数。** Windows 连本机非回环 IP 走本地环回，WFP 对 loopback 有例外
   ⇒ `Test-NetConnection <自己的IP> -Port N` 在任何防火墙配置下都是 True。
   **证明「对外开放」只能从另一台机器探。**
4. **报 IP 给对端前先看网卡类型。** RNDIS（USB 共享）/ vEthernet / VMware 全是虚拟网段，
   对端没有到这些网段的路由 —— 把这种地址报成「局域网地址」，对方永远连不上，
   而两边日志都看不出问题。**2026-10-25 真事故：把 RNDIS 的 `192.168.231.90` 当成
   局域网地址发给对端，对端根本够不到，白排查一轮。**

> 推论：**受控端主动外连，受控端一个入站端口都不用开**；方向选错时，所有防火墙努力都是白费。
> 只有当两边都在 NAT 后面、谁都不出得去时，才轮到 relay / 隧道。

接通之后还有两个「通了却以为没通」的坑，都是**把旧状态当现状**：

5. **磁盘上的代码 ≠ 正在跑的代码。** 对端 `git pull` 到最新 ≠ 新代码生效 ——
   进程不热加载，`commander` / `node_agent` 都得重启。判断方法不是猜：
   先看**磁盘**有没有新文件（`type docs\_stats.json` 看 gates 数、
   `dir /b fleet\kinds` 看新模块在不在），再看**接口**有没有新字段。
   本次实测：磁盘已是 `gates 98` + `mqtt_bus.py` 在，但 `nodes` 回的 `detail` 是空的
   ⇒ 唯一解释是那台 `commander` 还是改代码之前起的进程（PID 没变）。
   **反过来的误判更贵：以为同步失败又去改代码，实际只要重启一次。**
6. **回执里给的路径，自己必须存在。** `push` 会把传入路径**沙箱化**
   （只取 basename，落到节点沙箱目录）—— 这本身是对的，错的是**改了不告知**：
   传 `D:\...\tmp\a.txt`，回 `ok=True`，去 tmp 看是空的，文件在 `sandbox_node\a.txt`。
   **「成功了但找不到」比失败更难查**，所以凡是回执里带路径，判据只有一条：
   拿那个路径立刻去读，读不到就是假绿。已在 `t34` 钉死 12 条断言。
