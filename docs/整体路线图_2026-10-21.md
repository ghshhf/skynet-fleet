### 1.2 GUI 死链的**真实规模**（本轮重新实测，纠正上一版的说法）

上一版计划书写的是「6 个 `.sb-item` 死链」+「门禁扫 `id`」。本轮细查后**要纠正两点**：

| # | 上一版的说法 | 实测真相 | 影响 |
|---|---|---|---|
| ① | 门禁扫 `ui/index.html` 里每个带 `id` 的可点元素 | **6 个 `.sb-item` 根本没有 `id`**（纯 class），扫 `id` **抓不到它们** | 门禁必须扫 **class + 可点语义**，否则门禁绿着、界面照样死 |
| ② | 13 个 id「未绑定」= 死链 | 其中 12 个（`barCpu`/`valMem`/`dpBars`…）是**通过 `setBar("barCpu",…)` 字符串传入**的，**不是死链** | 差集法会**误报**，门禁红一片假的 |
| ③ | 死链就是 6 个 | 实测**还有 4 个**：`#apprRefresh`（审批刷新按钮，有 id 真没绑）、`.hbtn`×2（搜索 / 分享，**无 id**）、`.cbtn`×2（添加附件 / 浏览权限，**无 id**） | 死链真实清单是 **11 个**，不是 6 个 |

⇒ **教训（已写进本计划书）**：门禁不能只做「id 差集」。
真实做法必须是 **AST/HTML 解析出所有可点元素（`id` / `class` / `onclick` / `<button>`），
再看 `app.js` 里有没有对应的绑定**——两边口径必须一致。

**死链真实清单（11 个，本轮实测）**：

| 侧栏 6 项 | `.sb-item`（无 id） | 6 个真视图：新建任务 / 助理 / 专家·技能·连接器 / 定时任务 / 资料库 / 更多 |

**🔴 门禁的正确做法**（本轮纠正上一版）：
不是「扫 id 差集」，而是——
1. 解析 `ui/index.html`，**枚举所有可点元素**：`id` 属性 / `class` 命中可点样式 / `onclick` / `<button>`；
2. 对每个元素算一个**稳定标识**（有 id 用 id，无 id 用 `class + 序号 + 文本`）；
3. 断言这个标识在 `ui/app.js` 里**确实被绑定**（不是「出现过」而是「有 handler」）；
4. 豁免名单**只允许装饰性元素**（无 id 的纯图标 span、缩进用的空 div），且**写进代码注释**。

**验收**：
- 门禁 `evals/x0_nav_not_dead.py` 绿；
- 真机点一遍 11 个元素，每个**真换视图**（渲染图对比，不是看 console）；
- **红灯 6**（界面不许摆死链）常态化。

### 第 2 段 · X1 三 Tab（专家·技能·连接器）

产出：技能 Tab（按族分卡）/ 连接器 Tab（MCP server 清单）/ 专家 Tab（能力组合包）。
**硬约束**：能力名与数量全部来自 `/api/caps`，前端零硬编码（见 §三·重复 2）。
**语义红线**：WorkBuddy 的 `+` = 「接入外部服务」；本仓的 `+` = 「把设备纳入编队」。**只抄图标不抄语义 = 禁止。**

🔴 **连接器的语义（2026-10-21 晚更新，取代旧计划书里「连接器 = 设备」的写法）**：

> **连接器 = MCP server 清单。设备是内建的 MCP server。**

所以「连接器」Tab **不是「设备页的另一个马甲」**，而是「我能通过 MCP 用到的所有 server」，
内建设备与外接第三方 MCP server 是**同一张表**，用 `source` 字段区分：

| source | 是什么 | 怎么来的 |
|---|---|---|
| `builtin` | 本仓内建的设备（每台设备 = 一个内建 MCP server） | 注册表 `availability()` |
| `external` | 用户挂的第三方 MCP server | 真起进程 `tools/list` 探活 |

实现见 `fleet/gui/server.py::_connectors()` 与 `fleet/mcp/client.py`。
**外接行必须真探**——不探就不知道它死没死，而「摆着但不响应」是本仓明确禁止的界面骗人形态。

| 1 | 界面不许卡 | 长任务后台跑，界面还能打字/切页（撞法同 T2） |
| 2 | 能力只有一个真相 | GUI 调的每项能力都进同一张 `Registry`；全仓 grep 不许出现第二套 |
| 3 | 动手必须过闸门 | GUI / CLI / **MCP** 三条路径调同一个 `approval=ask` 能力，都必须被拦 |
| 4 | 端口不裸奔 | 只绑 `127.0.0.1` + 随机端口；一次性 token；无 token → 401；token 不落盘 |
| 5 | 界面不许骗人 | 每个状态字段来自 `reg.availability()` / `DeviceResult` |
| 6 | **界面不许摆死链** | 每个**可点元素**（不管有没有 id）都必须绑上事件，豁免写进注释 |
| 7 | 空状态不许装作有 | 拿不到值写明原因，不许给假的 0 / 空表格 / 假「可用」 |
| 8 | 数字不许写死 | 能力数/设备数/在线数一律来自接口 |
| 9 | 门禁红必须意味着代码坏了 | 离线 eval 一律把网络 I/O 假掉 |
| 10 | **不许有假的「未开放」按钮** | 输入框旁的「添加附件」「浏览权限」这类**直接删掉**，不许摆着占位 |
| 11 | **删除必须真删** | 删一条记忆刷新后不回来（E-7） |
| 12 | **失败必须带原因** | 空回 / 超时 / 被拒，都要说清为什么，不许静默 |
