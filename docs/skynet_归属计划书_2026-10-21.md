## 一、事实核查（均已当场核实，非推测）

| 项 | 事实 | 证据 |
|---|---|---|
| 归属 | `netforce/skynet/` 是主人自写 | `D:/code/netforce/LICENSE`：`Netforce Non-Commercial License 1.0 · Copyright (c) 2026 ghshhf` |
| 许可 | 可改、可传、**禁商用** | LICENSE 第 5 行「禁止任何商业用途」；分发须保留全文+版权+注明改动 |
| 内部依赖 | `skynet/` 纯标准库，内部仅相对 import | `skynet/__init__.py:18`：`from . import net, probe, search, store, discover, dns` |
| 外部消费者 1 | netforce 根 `skynet.py` CLI import 它 | `netforce/skynet.py:22`：`from skynet import net, probe as pmod, search as smod, store` |
| 外部消费者 2 | 本仓 `fleet/netforce_skynet.py` 适配层 import 它 | 走 `NETFORCE_HOME` 指路 + `_ensure_path()` 注入 sys.path |
| 非依赖方 | `resource_finder.py` **不** import skynet | grep 无 `import skynet / from skynet` |
| 唯一硬编码路径 | `store.py:19`：`DB_PATH = Path(__file__).resolve().parent.parent / "_skynet.db"` | 假设 skynet 在 netforce 仓库根下（parent.parent = netforce 根） |
| 本仓现状 | 5 个 web.* 能力已登记 | `catalog.py`：web.search / web.fetch / web.probe / web.structure / web.download；全仓 87 能力 |

**关键判断**：skynet 当前有**两个消费者**——netforce 自身 CLI + 本仓适配层。
「搬」的本质风险不是许可（许可自由），而是**复制后演进成两份天网、彼此分叉**。

## 二、三方案对比

### A. 维持现状（本仓 import，NETFORCE_HOME 指路）★ 推荐

- **做法**：不动。本仓只 `import skynet` 经 `NETFORCE_HOME` 指路，内核代码不进本仓。
- **单一真相源**：✅ skynet 只有一份，在 netforce 仓。两消费者共用。
- **许可合规**：✅ 不改分发形态，无新增义务。
- **改动面**：0。已落地，门禁 t16 钉死「只 import 不 vendoring」。
- **代价**：
  - 本仓**不可独立部署**——换机/CI 必须 `D:/code/netforce` 在或设 `NETFORCE_HOME`。
  - 离线门禁靠**假 skynet 包**（t16 注入 sys.path 一个 stub）绕过网络，不是真内核。
  - 路径假设 `store.py:19` 的 `DB_PATH` 依赖「skynet 在 netforce 根下」成立。

### B. 把 skynet 搬进 device-fleet（netforce 反向依赖）✗ 不推荐

- **做法**：`skynet/` 复制到 `device-fleet/fleet/skynet/`，本仓直接 import；
  netforce 反过来从 device-fleet import。
- **单一真相源**：❌ 搬的那一刻就复制成两份，之后两边各自演进必分叉。
- **架构**：倒挂。netforce 是采集器，device-fleet 是设备编队，**采集内核反向依赖编队层**语义错乱。
- **许可**：⚠️ 仍合规（非商用），但 device-fleet 当前许可若不同（需确认），搬运要带 LICENSE 全文。
- **DB_PATH 炸雷**：`store.py:19` 的 `parent.parent` 会变成 `device-fleet` 根，DB 落错地方；netforce CLI 反依赖后路径更乱。
- **改动面**：大。动两个仓 + 改 import + 修 DB_PATH。

### C. 抽独立仓 `ghshhf/skynet`，两边 pip 安装 ★ 唯一「真搬且不分叉」

- **做法**：把 `netforce/skynet/` 抽成独立 repo `ghshhf/skynet`，发布为可 `pip install` 包；
  netforce 与本仓都 `from skynet import ...` 经包安装，**不再本地路径 import**。
- **单一真相源**：✅ 唯一真能产生「搬」效果且**不分叉**的方案——两份都装同一个包。
- **许可**：✅ LICENSE 跟随独立仓，分发义务清晰。
- **DB_PATH 需改**：抽仓后 `parent.parent` 不再是 netforce 工作目录 ⇒ 必须改 `store.py:19`
  为**可配置**（环境变量 `SKYNET_DB` 或函数参数），否则 DB 落点错。这是本方案唯一硬改动。
- **代价**：
  - 多仓手术：建仓 + 迁移历史 + 改 netforce import + 改本仓适配层（去掉 `_ensure_path` 改 `import skynet` 裸 import）+ 两边装包。
  - 引入**构建/发布负担**（要打 wheel / 或 git submodule / 或 `pip install -e`）。
  - CI 与换机仍需能装这个包（内网/私有 PyPI 或 git+https）。
