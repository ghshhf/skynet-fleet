# 记忆：开源全景调研与融合设计

> 日期：2026-10-22
> 口径：星数为 **GitHub API 当日实测**；性能数字一律标「项目自报」，因为各家用的是不同 benchmark 的不同指标，横向比毫无意义（MemPalace 自己就在 README 里写明拒绝并排比较：检索召回 ≠ 端到端问答准确率）。
> 立场：借天下一切成就己身。学习机制，不锚定单一实现。

## 〇、结论前置

翻了 30 个项目、精读 18 个的架构与机制之后，**没有一家是"另一种记忆"，它们都是同一副骨架的不同切面**。三条收敛，每条都有多家独立证据：

### 收敛一：所有记忆系统都长成同一个四层

| 层 | 装什么 | 谁这么叫 |
|---|---|---|
| **L0 原文** | 逐字流水、对话、工具轨迹 | MemPalace `drawer`｜OpenViking `L2`｜腾讯 `L0 Conversation`｜MemOS `L1 trace`｜ReMe `daily notes`｜我们的 `journal` |
| **L1 原子** | 抽出的事实/偏好/过程/关系/事件 | mem0 `memory`｜Hindsight `world facts`+`experiences`｜腾讯 `L1 Atom`｜MemOS `L2 policy`｜Memori 8 类 augmentation |
| **L2 信念** | 多条原子合并成的、带证据的判断 | Hindsight `observations`｜腾讯 `L2 Scenario`｜MemOS `L3 world model`｜m_flow 证据路径 |
| **L3 常驻** | 稳定的长期理解，启动即可用 | Hindsight `mental models`｜腾讯 `L3 Persona`｜MemOS `结晶 Skills`｜OpenViking `L1 overview` |

我们现有 `memory.py`(KV) + `journal.py`(流水) + `recall.py`(往事) + `followups.py`(未闭环)，**占的是 L0 + 半个 L1**，L2 和 L3 是空的。这是最大的缺口，比"接哪个库"重要得多。

### 收敛二：检索全是"多路并行 → 融合 → 重排 → 预算裁剪"

没有一家靠单一向量检索赢。四路是标准配置：**语义 / 关键词 / 图 / 时间**。

- Hindsight：4 路 + RRF + cross-encoder 重排 + token 上限裁剪
- mem0（2026-04 新算法）：语义 + BM25 + 实体，并行打分融合
- 腾讯：BM25 + 向量 + RRF，L2/L3 做快速引导，要具体事实再回落 L1/L0，最后过**条数/字符/超时三重预算**
- OpenViking / MemPalace：**先用结构把范围收窄**（目录树 / wing-room），再在子树里做向量检索
- ReMe：BM25 + 可选 embedding + **wikilink 扩展**，返回行级片段
- HippoRAG：Personalized PageRank 多跳，模拟海马体联想
- m_flow：不给节点打分，**给证据路径打分**

### 收敛三：写入策略正在集体转向"只加不改"

这条最反直觉，也最重要：

| 项目 | 2025 的做法 | 现在的做法 |
|---|---|---|
| mem0 | LLM 决策 ADD/UPDATE/DELETE/NOOP | **2026-04 改成单次 ADD-only，不 UPDATE 不 DELETE**，LoCoMo 71.4 → 92.5 |
| Hindsight | — | observations **refine 而非覆盖**：新证据 strengthen / weaken / extend 已有信念，带证明计数 |
| MemPalace | — | **逐字存储，不摘要不抽取不转述**，R@5 96.6% 零 LLM |
| 腾讯 | — | L0 原文永存，逐层蒸馏但**保留来源** |

三个独立团队、三条不同技术路线，最后都放弃了"让模型决定删改"。

**对我们的直接意义**：上一轮我做的证据闸 + 不自动删除 + 待核永不自动转正，方向是对的，而且现在有第三方实证。但还差一块——**证明计数与矛盾降级**（weaken）。现在是"有证据/没证据"二值，应该是"几条证据支撑、有没有被反证"。

## 二、逐项目：真正的原创贡献（去掉宣传词）

只写"它做了什么别人没做的"，不写"它很好用"。

### mem0（67.6k）—— 只加不改的实证
2026-04 把算法从「LLM 决策 ADD/UPDATE/DELETE」换成「**单次 ADD-only**，记忆只累积不覆盖」，自报 LoCoMo 71.4→92.5、LongMemEval 67.8→94.4。同时加了三样：实体链接（跨记忆 boost）、多信号检索、时序推理（区分"现在是什么""过去发生过""将要做什么"）。
**要抄**：ADD-only 的方向；agent 确认过的动作与用户说的话**同等权重**存（它有明确一条 "agent-generated facts are first-class"）。
**要注意**：它自己的 README 承认高分来自托管平台的专有优化，开源自托管"方向类似但数字不同"。别拿 92.5 当开源基线。

### MemPalace（59.7k）—— 不抽取反而最强召回
逐字存原文，**不摘要、不抽取、不转述**。索引靠结构：人/项目 = wing，topic = room，原文 = drawer，所以检索**可以先限定范围**。LongMemEval R@5 自报 96.6%（raw，零 LLM 零 API），hybrid 版本 held-out 98.4%。另有 compress 前自动保存 hook、`sweep` 逐条落盘（幂等可续）、`audit` 给组织质量打分、时序知识图（边带有效期，可 invalidate）。
**要抄**：① verbatim 是可靠召回的地基，不该急着摘要；② `audit`——给"记忆库健康度"打分这个动作我们完全没有；③ 可插拔后端契约（chroma/sqlite/qdrant/pgvector）——不锁定存储。
**它自己承认的边界**：明确拒绝与其他项目并排比分数，因为指标口径不同。这种克制值得学。

### Hindsight（52.5k）—— 证据计数与常驻页
四类记忆（world facts / experiences / **observations** / **mental models**）。observations 是"多条记忆合并出的、带证据的信念"，**每条保留支撑证据的精确引用与证明计数，新证据来时 refine 而不是 overwrite**——新信息会 strengthen / weaken / extend 已有信念。mental models 是"一个问题定义一次 → 后台持续重写答案 → 读取是纯数据库读，无检索无 LLM 调用"。
**要抄**：① 证明计数 + weaken（我们现在只有二值）；② **常驻答案页**——这才是"启动即带着一页已定论的知识"的正确实现，比每次现算 digest 强得多；③ 四路召回 + RRF + cross-encoder 的完整链路；④ 多语言「保留原写法」（张伟不转 Zhang Wei），我们全中文，天然需要。

### OpenViking（40.5k，AGPLv3）—— 目录即上下文
一切是 `viking://` 虚拟文件系统，agent 用 `ls/tree/read/grep` 导航。每个目录带生成摘要：**L0 abstract（一句话判相关性）/ L1 overview（结构与要点，用于规划）/ L2 details（原文，按需）**。检索先由目录树解析范围（论文 TrieHI，ICDE），再做向量排序。session commit 后抽记忆成**可读可编辑的 Markdown**。
实测自报：LoCoMo 上 OpenClaw 24.20%→82.08%、Hermes 33.38%→82.86%、Claude Code 57.21%→80.32%；**input token 降 34.3–91.0%，延迟降 58.45–66.10%**；tau2-bench 任务成功率 +6.87pp（零售）/+11.87pp（航空）。
**要抄**：L0/L1/L2 三级加载；「先看摘要再决定读不读正文」。
**不能抄**：AGPLv3 + 明确禁止整体改写后重新开源。机制可以学，代码别搬。

### 腾讯 TencentDB-Agent-Memory（29.8k）—— 三重预算与先收权限
L0 Conversation → L1 Atom → L2 Scenario → L3 Persona 逐层蒸馏。检索分层：L2/L3 做快速上下文引导，要具体事实时 **BM25 + 向量 + RRF 回落 L1/L0**，结果再受**条数上限 / 字符预算 / 超时**三重裁剪。资产统一注册（Chat Memory / Skills / Wiki / CodeGraph），**Fixed Binding + ACL：先按团队/用户/agent/可见性收窄范围，再检索**。Wiki 受 Karpathy「LLM Wiki」启发，CodeGraph 索引符号与影响路径。
**要抄**：三重预算（我们的 digest 只有行数和字节，没有超时）；先收范围再检索；经验蒸馏成 Skills 这个终局。

### cognee（32.6k）—— improve 是独立阶段
五个操作 remember / recall / **improve** / forget / …。**improve = 用反馈增强记忆、把会话里被采纳的结论桥接进永久图谱**。无 LLM 也能跑（本地 GLiNER 抽取 + 本地 embedding）。整层可跑在单个 Postgres（图 + 向量 + 会话 + 元数据）。自报 BEAM 100K 0.79 / 10M 0.67。还有 **COGX 交换格式**，能从 Mem0/Letta/Zep/Graphiti 导入记忆。
**要抄**：**把"融合"当成一个显式阶段，而不是写入时的副作用**。这一点直接对应主人说的第二能力。

### MemOS（12.0k）—— 分层最干净
**L1 trace → L2 policy → L3 world model → 结晶 Skills**。MemCube：多个知识库作为可组合立方体，隔离 + 受控共享 + 动态组合。MemScheduler 异步摄取。**Memory Feedback & Correction：用自然语言反馈修正/补充/替换记忆**。检索是 **FTS5 + 向量**混合——和我们 memory.py 的技术选型完全一致。自报 OpenClaw 任务完成率 36.63%→50.87%、LoCoMo 88.83、LongMemEval 89.20。

### Memori（17.1k）—— 成本的硬指标
entity / process / session 三级，每级上做 8 类增强（attributes / events / facts / people / preferences / relationships / rules / skills），后台增强零延迟。自报 LoCoMo 87%，**每查询平均 721 tokens = 全上下文脚印的 2.8%**，比 Zep 少 67% prompt，比全量上下文省 36 倍。
**要抄**：**用 token/查询当一等指标**。我们现在的 digest 只报"字节数"，报不出"我这轮记忆花了多少上下文"。

### beads（28.1k）—— 记忆也可以是"还欠什么"
它压根不记对话。**记忆 = 带依赖图的任务图**，`bd ready` 回答"现在能开工什么"，Dolt 提供单元格级合并、分支、同步。替代"混乱的 markdown 计划"。
**要抄**：这直接是我们 `followups.py` 的升级方向——未闭环不该是平铺列表，该有**依赖与可开工判定**。

### basic-memory（4.3k）—— 工具行为标签
Markdown 双向写、observations + wikilinks 复合成图、可选 cross-encoder 重排。真正独特的是**渐进式工具发现**：每个工具打行为标签（read-only / destructive / idempotent），agent 按需选，不浪费上下文去试。
**要抄**：**我们那 87 项能力没有行为标签**。手机端"控电脑"现在只有名字+标题，人/模型都不知道哪项会改磁盘、哪项可重复执行。这是立刻能补的。

### ReMe（3.7k，阿里）—— 索引可重建
Markdown + frontmatter + wikilink 是唯一真相，**索引与生成元数据可重建**。对话与资源逐步变成每日笔记 + 长期知识，**保留来源**，随时间精炼 facts / preferences / procedures / relationships 四类。检索是 BM25 + 可选 embedding + **wikilink 展开**，返回行级片段。有 `auto_memory / auto_resource / auto_dream / proactive refresh`。无 LLM 时文件操作、BM25、wikilink 遍历都能用。
**要抄**：① 「索引可重建、正文明文」这条契约——我们的 SQLite 是黑盒，换个 embedding 就废了；② 行级（而非块级）返回；③ 四类实体划分（比我们现在的 ns 划分更贴语义）。

### 其他值得记住的一句
- **HippoRAG**：图谱检索用 Personalized PageRank 做多跳联想，而不是单跳相似度。
- **m_flow**："RAG 匹配块，GraphRAG 组织上下文，我们给**证据路径**打分"——多证据联合支撑比单条相似度更接近"想起来"。
- **SimpleMem**：语义无损压缩，长记忆不该膨胀。
- **MemoryOS**（EMNLP'25 Oral）：STM/MTM/LPM 三层 + 热度淘汰——唯一认真做了**遗忘**的学术工作。
- **ai-memory**：跨工具 handoff，**失败过的方案和未解决的问题**要传承，不只是结论。
- **agentmemory / ai-memory / memU**：都在解决同一件事——换工具、换机器、换 agent 后不该重新解释一遍。
- **LongMemory**：把"治理"（governed）写进定位，说明企业侧真在乎权限与审计。

## 四、五条跨项目定律（附证据）

**定律 1：摘要不是召回的前提，结构才是。**
MemPalace 不摘要拿 96.6% R@5；OpenViking 靠目录范围 + 三层加载把 token 砍掉 34–91%。两家都在证明：**先缩小到对的抽屉，再读**，比"把一切压成短句再相似度匹配"更有效。
⇒ 我们不该急着把 journal 摘要成一句话，该先把 journal 分成可寻址的抽屉（人/项目/设备/topic）。

**定律 2：让模型决定删改，是给自己挖坑。**
mem0 自己从 UPDATE/DELETE 退回 ADD-only 且指标大涨；Hindsight refine 不覆盖；MemPalace 干脆不抽取。
⇒ 保留我们的"不自动删除"，并升级成"累积 + 精炼 + 计数"。

**定律 3：单路检索一定输。**
四路（语义/关键词/图/时间）+ RRF 是标准配置，无一例外。连 MemOS 都是 FTS5 + 向量。
⇒ 我们只有 FTS5 + 时间窗，缺语义和图。补齐的顺序应该是 **图（实体/时间链接）→ 语义**，因为图在本地可确定性构建、无需 embedding 服务。

**定律 4：记忆的价值要用"省了多少上下文"来量。**
Memori 报 721 tok/查询 = 2.8% 脚印；OpenViking 报 token 降 34–91%。没有一家只报准确率。
⇒ 我们的门禁要加一条：**给定同一问题，带记忆与不带记忆的 prompt token 差**，以及**答案是否可溯源到具体 journal id**。

**定律 5：可读可改可重建，是长期可用性的分水岭。**
Markdown 派（ReMe/basic-memory/EverOS/agent-memory）异口同声：索引是派生物，正文明文才是真相。OpenViking 直接批评"大多数 agent memory 是黑盒"。
⇒ 我们 SQLite 里的记忆必须能**投影成 Markdown 给人看、给人改**，且改完能重建索引。否则半年后没人敢碰。

## 五、融合设计：提取 → 融合 → 创意

主人给的这三段，正好对应四层骨架的两条流水线。下面全部映射到我们已有的文件，不新建存储。

```
journal(L0 原文, 已存在)
    │  ① 提取 extract
    ▼
atom(L1 原子)  ── 类型: fact / pref / procedure / relation / event
    │             每条必带 journal id 证据 + topic + 时间
    │  ② 融合 consolidate
    ▼
belief(L2 信念) ── 同 (主体,属性) 聚合; 新证据 strengthen / weaken / extend
    │             带 proof_count 与矛盾标记, 永不覆盖
    │  ③ 结晶 crystallize
    ▼
sheet(L3 常驻页) ── 「一个问题的答案」持久化, 后台重写, 读取零 LLM
    │
    └─► 启动注入 / 按需取页 → ③ 创意（模型拿省下的上下文去思考，而不是去爬原文）
```

### 5.1 ① 提取（extract）—— 已有雏形，要补类型与行级

现状：`memguard.extract()` 按 topic 聚合流水，确定性、无 LLM、每条带证据。可用但太粗：只按 topic 分，不区分"这是个事实"还是"这是个待办"。

补：
- **类型判定（确定性规则优先，LLM 可选）**：
  - `fact`：主语 + 状态动词（"X 是 Y""X 有 Y"）
  - `pref`：出现"我要/别/以后都/不要"等偏好标记
  - `procedure`：出现命令序列、步骤编号、`->`
  - `relation`：出现设备↔人、项目↔设备等实体对
  - `event`：带时间戳且已发生（status=done）
- **行级证据**：现在证据是 journal id 整条，改成 `id + 行号区间`（ReMe 做法）。理由：一条流水里可能只有一行是真结论。
- **不抽取的两类，明确不抽**：寒暄、重复确认。理由：MemPalace 逐字存，我们也不必把"嗯""好"变成记忆。

### 5.2 ② 融合（consolidate）—— 本次要新建的核心

这是 cognee 的 `improve`、Hindsight 的 observation refine、腾讯的 L1→L2 蒸馏，三者合起来。

**输入**：L1 原子（只取 `status=open` 与带证据的）
**输出**：L2 信念，键为 `(subject, attribute)`

规则（全部确定性，可复算）：
1. **分组**：按 `(subject, attribute)` 聚。subject 取实体（设备名/项目名/人名），attribute 取属性名（电量/亮度/偏好/端口/进度）。
2. **同向累积**：新原子与已有信念同向 → `proof_count += 1`，`last_seen = now`，`evidence += 新 id`。
3. **反向降级**：新原子与已有信念相反 → **不覆盖**，标 `contested`，两者都留，各带证据，`contested_at = now`。**这是"真实"的关键**：记忆库必须能同时装下"A 说 X"和"B 说非 X"，并让人看见冲突。
4. **时效**：同键不同时间窗 → 时间近的 `proof_count` 加权，但旧的**不删**，标 `superseded`（被取代 ≠ 不存在）。这条抄 Hindsight（区分"现在是什么/过去发生过"）。
5. **永不出正文**：`contested` 和 `superseded` 的信念可以被召回，但**必须带标记**，不许当成事实平铺进 prompt。

**为什么不用 LLM 做这一步**：LLM 做合并会编造中间结论，而且无法复算。腾讯、ReMe 的蒸馏也都能在无 LLM 时降级运行。我们的原则：**融合规则确定性，LLM 只在歧义时被邀请，且其产出进 `pending` 待核**。

### 5.3 ③ 结晶（crystallize）—— 常驻页，取代"每次现算 digest"

现状：`memguard.digest()` 每次现算，40 行/6000 字节。这没错，但**每次都要算**，且不沉淀。

改成 Hindsight 的 mental model：
- 一张表 `sheet(name, question, body, updated_at, source_beliefs)`
- `question` 形如"这个用户的工作习惯是什么""这台设备的已知毛病有哪些""当前主干项目的下一步是什么"
- `body` 由 L2 信念渲染，**后台重写**（不是每次请求现算），读取是纯 DB 读
- **读取零 LLM**：启动时拼进 system prompt 的就是这张页，省掉 rediscovery
- 页面有版本：`sheet_rev`，改了什么、依据哪几条信念变了，留痕

这一步直接兑现"创意"：**模型启动就带着一页已定论的知识，上下文拿来想新问题，而不是重新认识主人。**

### 5.4 检索：从"FTS5 + 时间窗"升级到四路

按成本排序落地（本地可跑、无需外部服务优先）：

| 路 | 实现 | 依赖 |
|---|---|---|
| 关键词 | FTS5（已有） | 无 |
| 时间 | 时间窗 + 时效加权（已有雏形） | 无 |
| 结构 | 按 subject/项目/设备先收窄目录再检索（OpenViking/MemPalace） | 无 |
| 图 | 实体共现 + wikilink 式链接（ReMe），进阶再做 PPR（HippoRAG） | 无 |
| 语义 | embedding（可选，能没有） | 需模型 |

融合排序：**RRF**（倒数排名融合，无需调参）+ 可选 cross-encoder 重排（没模型就跳过）。
预算裁剪：**条数 + 字符 + 超时**三重（抄腾讯），超时就返回已得的，不阻塞。

### 5.5 治理（贯穿）

- 证据闸（已有）：无证据 → `pending`，永不自动转正
- 冲突可见（新）：`contested` 必须展示，不许模型自己挑一边
- 删除权（已有）：只报告不自动删
- **可读投影（新）**：`memguard --project` 把 L1/L2/L3 导出成 Markdown（人可读可改），改完 `--reindex` 重建
- **健康度评分（新，抄 MemPalace audit）**：无人复核的 pending 比例、contested 比例、证据已丢比例、平均 proof_count → 一个 0–100 的分，低分提示"该整理了"

## 六、明确不做（防范围膨胀）

1. **不引入向量数据库**。SQLite FTS5 + 结构化范围已经能覆盖我们 90% 的查询；embedding 作为可选插件留着，不做主路径。
2. **不上图数据库**。实体共现在 SQLite 里用一张边表就够；Neo4j 是给千万级实体准备的。
3. **不让 LLM 写"结论"进正文**。它能产出候选，进 `pending`，要证据才转正。
4. **不做自动删除/自动合并**。dupes 只报告。有人的原话删了拿不回来。
5. **不搬 AGPLv3 代码**（OpenViking）。机制学，代码不搬。
6. **不接任何一个项目的运行时**。它们要么绑 Node 宿主、要么要 Docker + PG + Neo4j。我们是单机 Windows + 一部手机，装不动。

## 七、门禁清单（`tools/mem_gate.py` 从 11 项扩到 18 项）

现有 11 项保留，新增 7 项，全部可确定性复现：

| # | 做什么 | 通过标准 |
|---|---|---|
| 12 | 同向新证据 | `proof_count` +1，`evidence` 增一条，正文不变 |
| 13 | 反向新证据 | 标 `contested`，**两条都留**，`evidence` 各自独立 |
| 14 | 冲突信念被召回 | 返回里**必须带 contested 标记**，不许当事实平铺 |
| 15 | 时间推进 | 旧信念标 `superseded` 但**仍在库里**（不可被删） |
| 16 | 结晶页读取 | 读一次 sheet **零 LLM 调用**（用计数器断言） |
| 17 | 预算裁剪 | 超条数/超字符/超时三种情况都返回**部分结果**而非报错 |
| 18 | 可读投影 | `--project` 产出 Markdown，改一行后 `--reindex` 能读回改动 |

指标（沿用定律 4）：
- **token 脚印**：同一问题"带记忆 / 不带记忆"的 prompt token 差，必须可打印
- **可溯源率**：返回的信念里带有效 journal id 的比例，目标 100%
- **健康度**：pending / contested / 证据已丢 三个比例 + 一个综合分

## 九、这一轮的判断

开源这三年把记忆做了三件事：
1. **把"存什么"想清楚了**——原文、原子、信念、常驻页，四层。
2. **把"怎么找"想清楚了**——多路并行 + 融合 + 预算。
3. **正在把"怎么改"想清楚**——从覆盖式更新退到只加不改。

我们不需要它们任何一套代码：只需要这四层、这四路、这条"只加不改"。我们的 `journal` 已经是很好的 L0（append-only + 自增 id + 可 purge），证据闸已经是对的治理地基。缺的是中间两层和检索的两路。

**真正的风险不在技术，在自制**：一旦允许 LLM 自由合并，记忆库会在三个月内变成一本自洽但不可信的小说。所以融合阶段必须是确定性规则，"创意"留给模型在读取时发挥。
