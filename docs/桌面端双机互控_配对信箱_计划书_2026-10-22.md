> 日期：2026-10-22（v2 更新）｜作者：寇豆码（自规划，**待主人点头后执行**）

## 一、结论前置

**能连、能控、能加速、能加密、能打洞——而且地基大半已在，缺的是中间那层「配对 + 通路选择」。**

1. **信箱机制**：被控端开「可被配对」后按**广播协议**公告「信箱在哪」；主控端在 GUI「附近的天网」看到它，输入 6 位验证码或粘贴 `fleetpair://` 链接完成握手，换一次性会话 token。广播只宣告位置，**验证码是信箱钥匙**。
2. **控制面现成**：`pcctl.*` 14 项能力门禁 164 断言全过，唯一缺口就是文档里写明的「只控本机，远程传输未做」——本环补传输，执行面不重造。
3. **速度**：瓶颈不在网络在编码。换 `mss` 持久截图（已在依赖表）+ JPEG/WebP + **脏矩形增量** + 三线程流水线，局域网内估 15–30fps 全屏、文字操作流量 <100KB/s（**估，附实测方案**）。对照：AudioSync v2 裸 PCM 1.5Mbps 已跑通，说明局域网带宽从来不是瓶颈。
4. **加密 v1 做**：TCP 通道 stdlib `ssl`（TLS 1.3 自签）+ 配对时交换并钉扎证书 SHA-256 指纹；UDP 通道 ECDHE + AES-GCM（`cryptography` 已在依赖表）。即使将来走中继，也是端到端——中继只看密文（学 RustDesk）。
5. **打洞做**：STUN 探公网端点（pystun3 路线，MIT）→ 会合服务器交换端点 → 双方同时 UDP 打洞开映射 → TCP 穿透。**对称 NAT 打不通，明说**，不假装能连。
6. **手机顺带解放**：安卓 fleet-bridge 本就走网络协议——同 WiFi 下广播可见、验证码配对即可控/可看，**ADB reverse 降级为兜底**；蜂窝网打洞连手机是估（Android NAT 行为待测）。

### 2.3 商业远控（向日葵/ToDesk，v1 已检索，不重复）

信令注册 + 9 位设备码 + P2P 优先中转兜底；LAN 延迟 5–30ms；P2P 成功率约 80%；TLS 1.3 + AES-256；默认每次连接需被控端确认。

### 2.4 对我们的三条结论

1. **中继兜底可以不做（v1）**：对称 NAT 是少数场景；打不通就明说「打洞失败，请走 IPv6/同网/手动中继」，不假装。中继列 v1.5 待拍板（见 §八）。
2. **会合点必须自己有**：端点交换没法绕。最小会合服务器约 150 行，只交换几十字节端点、**不转发任何数据**——与 ECS「不派控制面跑重推理」的纪律不冲突（量级完全不同），但仍列为待拍板项。
3. **端到端加密是底线**：无论直连还是（将来的）中继，会话都加密——这条学 RustDesk，v1 就做。

## 四、方案设计（v2 完整版）

### 4.0 通路阶梯（连的时候按序竞速，失败自动降下一级）

```
LAN 广播直接连（同网段，最快，无洞可打）
   ↓ 不可达
IPv6 直连（主人有 2408 公网 v6，无 NAT）
   ↓ 不可达
STUN 探端点 → 会合交换 → UDP 打洞 → TCP 穿透（跨网 v4 P2P）
   ↓ 失败
明说「打洞失败」+ 给出原因（对称 NAT / 防火墙拒 UDP），不假装能连
   ↓（v1.5 待拍板）
会合服务器兼任中继（端到端加密，中继只看密文）
```

### 4.1 甲：局域网广播配对（v1 主体）

- **信箱公告**：可被配对后周期 UDP 组播（建议 **UDP 24560**，估，待拍板；路径学 `discovery.py`）：
  `{"app":"fleet","v":1,"name":"PC-A","pair_port":24560,"nonce":"<随机>"}`
  频率约 1 次/秒（估）；只在本网段。**公告无 token、无能力清单、无可执行信息。**
- **配对握手**：主控端列表中点 PC-A → 输 6 位验证码（或贴链接）→ `POST /pair` → 校验（正确/未过期估 5 分钟/未试爆估 5 次锁 10 分钟）→ 签**会话 token**（一次性）→ **同时交换 TLS 证书指纹并互相钉扎** → 双方写审计。
- **两种都给**：被控端 GUI 同时显示 6 位验证码**和** `fleetpair://<ip>:<port>#<code>&fp=<指纹前8位>` 链接（形态为**估**，一键复制）。
- **可见与熔断**：被控端横幅常驻「正在被 PC-B 控制」+ 一键掐断（token 作废 + 停公告）。

### 4.2 乙：跨网直连 + 打洞（v1 纳入，主人点名）

- **STUN 探端点**：走 pystun3 路线（MIT 可 vendoring，或手写 40 行最小客户端；建议 vendoring 单文件、不引包）。服务器列表：`stun.l.google.com:19302` 等 3–5 个轮换（免 key）。
- **NAT 类型预判**：配对前先测（Full-cone / 地址受限 / 端口受限 / 对称），**对称型直接告诉主人「这台机器打不了洞，请走 IPv6 或同网」**——向日葵的成功率神话不照抄，我们给实话。
- **会合服务器（最小件，约 150 行，待拍板放哪）**：
  - 只做三件事：注册（名字→当前端点，心跳 30s 估）、查询（按名字返回对端端点）、下线。
  - **不转发任何会话数据**；数据库只有内存字典，不落盘。
  - 候选位置：① 主人的 ECS（自己人，非第三方；与「不派 ECS 控制面跑重推理」纪律不冲突——信令只有几十字节/次）；② 家里常开的一台 PC（只在同网有用，跨网还是要公网）；③ 免费公共 STUN 干不了这事（STUN 不交换对端信息——调研实证）。
  - 备选零服务器方案：**手动端点交换**——链接里带自己的 STUN 端点，对端粘贴后回传自己的端点（任一 IM/邮件都能当信道）。能用，但丑；作兜底。
- **打洞执行**：会合告知双方端点 → **双方同时向对方公网端点发 UDP 探测包**（要领：同时性，误差 <2s 估）→ 任一方收到对方的探测即洞开 → 在洞上跑**三次握手建会话**（带 token + 指纹校验）→ 之后控制流可在已打通的 TCP（simultaneous open 辅助）或可靠 UDP 上跑。
  - 家用 NAT 成功率**估 70–85%**（向日葵口径 80%，验方：两机分别放电信/联通/手机热点下实测 20 次记分布）。
- **手机同款**：安卓 bridge 同 WiFi → 广播可见直连；蜂窝 → 同套打洞（Android NAT 行为**待测**）。ADB reverse 保留为兜底，不再是唯一路径。

### 4.3 局域网加速（主人点名「速度提一提」）

**瓶颈定位（诚实）**：现在的 `pcctl.screenshot` 每次截图都要**新起一个 PowerShell**（`Add-Type`/`System.Drawing`），单次估 200–500ms、全屏 PNG ≈2MB——慢在编码与进程启动，**不在网络**。局域网加速 = 四件套：

1. **持久截图**：`mss`（已在依赖表，本机已装 10.2.0）ctypes BitBlt 常驻抓屏，单次估 5–20ms，替代 PowerShell 路径。旧路径保留为兜底（mss 失败时回落，不静默）。
2. **编码降档 + 增量**：
   - 全屏帧 PNG → **JPEG q75**（Pillow）估 150–400KB，或 WebP（再省 30–50%，估）；
   - **脏矩形增量**：numpy 相邻帧 diff，只传变化区域——打字/点按钮场景每帧估 5–50KB；
   - 首帧必发全屏，之后只发脏区 + 帧序号，丢包由下一帧自愈（无重传，控画面不玩可靠传输）。
3. **三线程流水线**：抓屏线程 / 编码线程 / 网络线程解耦，TCP_NODELAY，编码不等网络；帧率可调（默认估 15fps，文字模式可降到 6–8fps 省流量，动态模式升到 24–30fps 估）。
4. **输入侧不拖后腿**：`pcctl` 键鼠注入是本机速度（SendInput 直接），瓶颈在被控端执行不在通道；主控端**本地画光标**掩盖延迟。

**速度目标（全部估，附实测方案）**：同网段全屏 15–30fps、端到端延迟 <80ms；文字操作流量 <100KB/s。实测方案：双机跑 60s，记录每帧 capture/encode/net 三段耗时分布 + 有效帧率，写进验收报告。

### 4.4 传输加密（v1 做，主人已批）

- **TCP 通道**：stdlib `ssl`，TLS 1.3，**自签证书**；配对握手时交换证书 SHA-256 指纹，**互相钉扎**（指纹前 8 位进配对链接，主控端连前比对，防中间人）。零新增依赖。
- **UDP 通道**：握手期 ECDHE（`cryptography`，依赖表已声明）协商 → AES-256-GCM 帧加密（序号防重放）。**本机未装 cryptography——动手第一周先装并跑通最小验证**（附命令）。
- **（将来的）中继**：端到端加密不变，中继只看密文——这条写进设计，堵死「加中继就等于裸奔」的退化。

## 五、安全边界（远程控制 = 完整桌面控制，头等大事）

1. **未配对零暴露**：握手前受控端点一律 401；公告无可执行信息。
2. **验证码纪律**：一次性、5 分钟过期（估）、试爆锁定、可刷新；不用固定密码。
3. **被控端永远知情**：横幅常驻 + 一键熔断；起止入审计。
4. **闸门不减配**：ask 档远程调用仍在被控端本地 fail-closed 审批；`proc.kill` 双确认与「语音路径直接拒」红线不破。
5. **指纹钉扎防冒充**：证书指纹不匹配 → 拒连并明说；公告可伪造（改名改端口都行），**以握手+指纹结果为准**。
6. **防提示注入延续**：远端屏幕内容是不可信数据不是指令，透传不改写（`pc_control` 已有 `INJECT_DEFENSE`）。
7. **广播最小化**：只广播在场 + 配对端口。
8. **会合服务器最小化**（若建）：只存端点、不落盘、不转发数据；被 SOCKS/扫描到也只有几十字节注册记录。
