## 三、五层骨架

### 3.1 P0 证据层：执行即留痕（这是燃料，不做完不许往下）

**要解决的问题**：160 条 task 只有开始没有结束。执行结果（成功/失败/为什么失败）从来没落盘，所以"从成功里学"没有素材。

**做法**：新增一个统一执行包装器 `fleet/execute.py`，所有能力调用走它。

```
trace_id  = 一次用户意图（一段连续的多次能力调用）
journal 记 3 类事件，全部带同一个 trace_id：
  · 开始  kind=task  status=open   topic="t:<trace>/c:<cap>"
  · 成功  kind=task  status=done   topic="t:<trace>/c:<cap>"   body 带耗时与参数摘要
  · 失败  kind=task  status=open   topic="t:<trace>/c:<cap>"   body 带错误类型与原文
```

**关键取舍（待点头 #2）**：`topic` 里塞 `t:/c:` 是**不改表**的做法，但解析脆弱（topic 是自由文本，改格式就断）。
推荐：给 `journal` 加一列 `trace TEXT`（SQLite `ALTER TABLE ADD COLUMN`，不影响既有 187 行，仍 append-only）。topic 保持人可读。
理由：trace 是结构，不该长在文本里；后面 P2 要按 trace 聚步骤，靠字符串切分会一直踩坑。

**验收（硬）**：
1. 跑一遍 P3 门禁的 7 项，`fleet_journal.db` 里出现 **≥7 条 `status='done'` 且 topic 非空**；
2. 同一 trace 的多次调用能在一条查询里按顺序取回；
3. 失败也留痕：故意调一个必失败的参数，`open` 事件的 body 里有错误类型；
4. `memguard.digest()` 不再出现"全是临时节点下机清理"这种噪音（验证 P0 顺带治好了记忆那层的空转）。

### 3.2 P1 技能文本：天网版 SKILL.md 的三个扩展字段

沿用现有 `SKILL.md` + frontmatter 格式（`fleet/skills.py` 已能解析，一块钱不用改），只加三个**它认不认都无害**的键（`parse_frontmatter` 会把未知键收进 `extra`，不会报错）：

```markdown
---
name: wifi-reconnect-after-sleep
description: 设备休眠后 Wi-Fi 掉线时的重连流程。当 adb.wifi.info 显示 disconnected 时使用。
agent_created: true
license: internal
evolved_from: [1024, 1025, 1031]     # 长出这张卡的 journal done 事件 id
caps: [adb.wifi.info, adb.wifi.disconnect, adb.wifi.connect]   # 它要用的能力，必须全存在
guard: 任一步失败即停，不许继续往下试      # 失败时怎么办（人话，给模型看）
---
```

- **`evolved_from`** = ScienceClaw 的"源 episode 溯源"。
- **`caps`** = Operator 的替身，也是 `R_src = Pass ∧ Use` 里那个 "Use"：写进卡里的能力，必须**真的在源 trace 里被调用过**。
- **`guard`** = 失败出口。没有 guard 的技能一律不收（否则模型会自己脑补"失败了继续试"）。

**为什么自写技能不能带脚本**：
现有 `skills_audit` 对「含可执行脚本」100% 判 `needs_review`。这不是保守，是对的——技能是"怎么做"的方法论，动手要靠 87 项能力（它们已经各自带 `side_effect`/`approval` 闸门）。
⇒ **自写技能 = 纯 Markdown，零脚本、零二进制。** 这条让自写技能天生天然过审查，不需要为它开口子。

**验收**：
1. 造 1 张真技能（来源是 P0 跑出的真 done 链），`skills.py` 能读出 `evolved_from/caps/guard` 三个字段；
2. 把 `caps` 里写一个不存在的能力名 → 装载时**报错并指出是哪个名字不存在**，不许静默通过。

### 3.3 P2 验证门：四条硬闸 + 噪声守卫（ScienceClaw 本土化）

`fleet/skills_evolve.py` 的 `verify(candidate)` 必须四闸全过，任一不过就不许落盘：

| 闸 | 名字 | 判什么 | ScienceClaw 对应 |
|---|---|---|---|
| 闸1 | **溯源真** | `evolved_from` 每个 id 都在 journal 里存在、都是 `kind=task`、都是 `status=done`；删过（`purge`）的 id 直接废 | 源 episode 可溯 |
| 闸2 | **能力真** | `caps` 每一项都在 `registry.cap_names()` 里；**且**在 `evolved_from` 那几条事件的 body/topic 里真出现过 | `R_src = Pass ∧ Use` |
| 闸3 | **步骤可执行** | 步骤里出现的每个能力名都在 `caps` 里（不许正文偷偷用没申报的能力）；步骤数 3–15（少于 3 是废话，多于 15 是没人看的长文） | 类型化工作流端口匹配（弱化版） |
| 闸4 | **文本干净** | 过 `journal.redact()` 同一套打码（设备序列号、路径、token 一律替换）；过 `skills_audit` 且判 `clean` | 无自动脱敏是 SkillClaw 的已知缺陷，我们补上 |

**噪声守卫（直接搬，数值照抄）**：
```
候选要覆盖现役同名技能，必须：
  改善回合 ≥ 2  且  退化回合 ≤ 1
否则保留现役，候选进 quarantine（不删，留证据）
```
"回合"在本仓的定义：**同一张技能在 ≥2 个不同 trace 上被使用，每次回写结果**。只有一个回合的技能只能新增、不能覆盖。

**诚实边界（必须写进代码注释，防止以后自己骗自己）**：
> 我们的"重放"不是 ScienceClaw 的"重置环境重放"。没有可重置的沙盒，就没有严格的 `e⁻ → e⁺` 夹取。
> 我们只有"这条链在我机器上真的跑成过"这一个凭据。所以本模块的定位是**弱验证**：
> 它能挡住"凭空编造的技能"，挡不住"在我这台机器能跑、在另一台跑不了"。
> 后者靠 P3 的多节点统计去发现，不靠 P2 假装能验。

### 3.4 P3 落盘与版本：目录分离 + git 当快照

| 目录 | 放什么 | 谁管 |
|---|---|---|
| `skills/` | **vendored 第三方**（现状 1 条） | `skills_audit` + `MANIFEST.json` + 门禁 `p4`（已有，不许动） |
| `skills_evolved/` | **自写技能**（新） | `EVOLVED.jsonl` + 门禁 `p5`（新） |

**为什么不混进 `skills/`**：`p4` 门禁钉的是"每个子目录必须有 `_audit.json` 且 clean、name 与目录名一致、MANIFEST 一一对应"。自写技能混进去会污染这个契约，且审计来源（"抄谁的"vs"自己长的"）变得不可区分。分开两个目录，两套账，互不干扰。

**版本 = git**：
不自己造快照机制。每张技能一个文件，`git log -- skills_evolved/<name>/SKILL.md` 就是它的完整版本史，回滚 = `git checkout <sha> -- 该文件`。
ScienceClaw 的"版本化快照 + 回执 + 可回滚"三件，git 全给，且我们的回执就是 commit。

**回执 = `skills_evolved/EVOLVED.jsonl`**（一行一条，append-only，对齐 SkillClaw 的 `evolve_history.jsonl`）：
```json
{"ts":"2026-10-22T15:10","op":"create","name":"wifi-reconnect-after-sleep","from":[1024,1025,1031],"caps":3,"gate":"pass","git":"<sha>"}
{"ts":"2026-10-22T15:40","op":"refine","name":"...","from":[...],"improved":2,"regressed":0,"gate":"pass","superseded":"<sha>"}
{"ts":"...","op":"quarantine","name":"...","reason":"regressed=2","gate":"fail"}
```

**验收**：
1. 自写技能落盘后，`p5` 门禁通过；
2. 故意改坏一张（把 `evolved_from` 指向不存在的 id）→ `p5` 必须红；
3. `git log` 能查到该技能的历史；`git checkout` 能回退。

### 3.5 P4 记分与共享：只记账，不自吹

**记分不自己算，从 journal 反查**（避免"自评"这种自欺）：

```
skill_score(name) = 
  命中：技能 caps 里每个能力 → 查 topic LIKE '%c:<cap>%'
        取该能力最近 N 次执行的 done/open 比
  技能自身使用：topic = "skill:use:<name>" 的 done/open 比
```

**必须写明的近似**：这是**影子成功率**，不是技能自己的成功率——它测的是"技能覆盖的那些能力，最近跑得怎么样"。真正的"技能被读进去并且照着做了"本仓观测不到（没有 chat proxy，也不打算造）。
⇒ GUI 里注入技能到提示词那一刻，**显式记一条** `task/skill:use:<name>/status=open`，执行成功再 patch 成 done。这是唯一能拿到的真信号，别当成完整观测。

**共享（集体进化）**：
本仓多节点，同步走已有通路（`fleet/transports/` + git），**不造 OSS/S3 后端**。
规则：`skills_evolved/` 里的技能**默认不自动同步**，要显式 `--push`。理由：一张技能在我的设备拓扑上有效，不代表在另一台有效，自动扩散 = 把一个节点的偏见变成全网的事实。

**验收**：
1. `stats` 输出每张技能的 `caps 覆盖率 / 影子成功率 / 使用次数`，全部能指到具体 journal id；
2. 一张技能没有任何 done 证据时，`stats` 明确输出"证据不足，分数不可信"，**不许给个 0.5 充数**。

## 四、必须改的现有规则（改之前要你点头）

### 4.1 为什么非改不可

实测：38 条技能 **34 条被判 `needs_review`**，其中大量是误杀：

| 误杀形状 | 实例 | 现规则 | 问题 |
|---|---|---|---|
| 文档里提到网址 | `crypto-token-analysis` 里写"从 CDN 引进 `<script src="https://cdn.jsdelivr.net/...">`" | 命中 `http_request` | 教材提到 URL ≠ 代码去请求 URL |
| 文档里出现"密码"这个词 | `deai-promax`：**"处理含密码/API key 的文本时，立即停止"** —— 这是在讲安全规范 | 命中 `secret_path` | **教人别碰密钥，反被判成想偷密钥** |
| 带个图标 | `cn-novel-craft` 的 `icon.png` | 命中"非文档文件" | 图片是无害资产，但也确实能藏 payload |

⇒ 现规则**按关键词一刀切**，分不清"教材里说"和"代码里干"。自写技能是纯文档，但文档里必然出现能力名、路径、URL、甚至"token"字样 —— 不改规则，自写技能 100% 进不来。

### 4.2 精确化方案（是收紧定位，不是放松）

| 改动 | 现规则 | 新规则 |
|---|---|---|
| **按角色分档** | 所有文件一视同仁 | `SKILL.md` 与 `references/**` = 教材 → 走"命令式"匹配；`scripts/**`、任何 `SCRIPT_EXTS` = 代码 → **一律 `needs_review`（不变）** |
| URL | 出现 `https?://` 即命中 | 教材正文/引用里的 URL **不算**；代码块内且伴随 `curl/wget/requests.get/fetch(` **才算** |
| 密钥词 | 出现 `token|password|secret|api_key` 即命中 | 作为**警示词**（"不要处理密码"）**不算**；作为**取值/赋值**（`token=`、`api_key:` 后接字面量、`.ssh/id_rsa` 路径引用）**才算** |
| 图片资产 | 一律 `needs_review` | 仍 `needs_review`，但允许 `--allow-assets` 显式放行，并在 `MANIFEST` 记 `assets: true`（**留痕放行，不静默**） |
| 总开关 | fail-closed | **不变**：未覆盖的扩展名、解析失败、frontmatter 坏 → 一律 `needs_review` |

### 4.3 改规则必须带双向回归（否则就是给自己开后门）

改完必须同时满足：
1. 38 条真实技能：`clean` 数从 4 上升到 **≥20**（不设更高，因为带真脚本的确实该留 review）；
2. **固定恶意样本集全部仍被判 `needs_review`**：新建 `evals/fixtures/evil_skill/`，内置 8 个经典形状（`rm -rf`、`curl|sh`、`os.system`、读 `.ssh/id_rsa`、base64 解码后 exec、`subprocess.Popen`、`__import__`、写到 `~/` 外）；
3. 第 2 条是**红线**：只要恶意样本有一个被判 clean，这次改动就必须回滚。

## 五、分阶段执行清单（晚上在另一台电脑照着跑）

> 每阶段末尾的「不许进下一步」是硬门，`p5` 门禁会把当前阶段的状态钉住。

### P0 证据层（约 1 个动作 + 1 次门禁）
```bash
# 1) 加 trace 列（待点头 #2）
python -c "import sqlite3;c=sqlite3.connect('fleet_journal.db');c.execute('ALTER TABLE journal ADD COLUMN trace TEXT');c.commit()"
# 2) 新增 fleet/execute.py（包装 reg.call，写 open/done/失败）
# 3) 让 P3 门禁那 7 项都走 execute.py
python tools/p3_gate.py
```
**验收**：`done` 事件 ≥7 且 topic 非空；同 trace 可顺序取回；失败留痕。**不过不许进 P1。**

> ⚠ 本机 `python` 是 WindowsApps 占位壳（`python -c` 静默 exit 0，什么也不干）。本机跑要写全路径 `/d/tmp/fleetdeps/Scripts/python.exe`；另一台电脑用真 `python` 即可。

## 六、新门禁 `tools/p5_skill_evolve.py`（照 `p3_gate` 的写法：每项加线程超时）

| # | 钉什么 | 红了说明 |
|---|---|---|

## 七、明确不做

| 不做 | 为什么 |
|---|---|
| LLM 当裁判给技能打分 | ScienceClaw 原文就是"No LLM judge is needed"；让模型评自己写的技能，等于自己给自己发合格证 |
| 自动改技能并直接生效 | 全部候选进 quarantine，人际确认才 promote。技能直接影响设备操作，自动生效 = 没人知道是谁改的 |
| 从失败里"猜"技能 | 失败只作为**降级信号**（覆盖现役时的退化回合），不作为生成素材。从失败反推"应该怎么做"就是幻觉工厂 |
| 改模型权重 / LoRA / 在线 RL | 第 4 层不进第 2 层，且要 GPU |
| 造 chat proxy 拦截会话 | 新增一个 HTTP 代理层 = 新增一个每天都可能挂的部件，换来的只是"更细的使用观测" |
| 向量库 / 图数据库 / OSS 共享后端 | 38 张技能，目录 + JSONL 完全够；上库是给未来的自己挖坑 |
| 技能自动全网同步 | 一个节点的偏见会变成全网"事实" |
| 从第三方市场盲拉技能 | `skills_acquire` 已 fail-closed；拉取要 `--insecure-ok` 显式开，不设默认 |

## 八、风险与回滚

| 风险 | 后果 | 挡它的东西 |
|---|---|---|
| 技能越写越多、越写越水 | 提示词里塞几十张卡，模型反而更笨 | 噪声守卫（≥2 改善才覆盖）+ `stats` 里"证据不足"标记 + 技能数上限（超 30 张必须先淘汰） |
| 审查规则被以后的我放松 | 恶意技能混进来（ClawHavoc：341 个恶意技能） | 恶意样本集回归（门禁第 8 项），放松即红 |
| `evolved_from` 指向的事件被 `purge` | 无源之技能仍然存活 | `p5` 第 2 项直接红；技能不删，但降级为 `quarantine` |
| 技能在我机器上对、另一台不对 | 换个节点就翻车 | 默认不自动同步；`stats` 分节点统计（P4 落地后看） |
| trace 列改动影响既有 187 行 | 老数据读不出来 | `ALTER TABLE ADD COLUMN` 只加不删，老行为 NULL；`SKIP_NS` 式的兼容查询要写自测 |

**整层回滚**：`skills_evolved/` 是独立目录、`EVOLVED.jsonl` 独立文件、`p5` 独立门禁 —— 删掉这三样 + `git revert` 就完全回到今天的状态。不动 `skills/`、不动 `MANIFEST.json`、不动 journal 表结构（除了加列）。
