# 工具面 v2：多轮、权限三档、Sky MCP 下放（2026-10-24 凌晨）

接着 `docs/手机端工具调用_调研与决策_2026-10-24.md` 与
`docs/下一轮计划_工具面扩展_2026-10-24.md`（P0 已落地）往下做。
这一轮把 P1（多轮）和 P2（权限）做完，并把 **Sky MCP 挂成手机能连的 HTTP 端点**。

结论前置：

1. **「让模型自己决定还要不要工具」这条路是死的**——真机 1.7B 跑 10 条复合句，
   **10/10 回 none**。改提示词只会更糟（写进「明说两件事就必须选另一个」后，
   none 从 9/10 升到 10/10）。多轮的缰绳必须在代码里。
2. 正解是**把后半句拆出来，走第一轮那套 7 选 1 枚举**——同一形状、同一能力，
   实测 **10/10**（该问的 4 条全对，不该问的 6 条根本不问）。
3. 权限是**两层白名单**（工具名 + 档位），执行层再查一次；审计日志落盘。
4. Sky MCP 现在有两种传输（stdio / HTTP），**同一份派发逻辑**，手机侧可达。
5. 真机端到端：问「看看通知，顺便告诉我电量」→ 第一轮 notify.read、
   第二轮 thermal.read，**两条都是真数据**，回答零编造。

## 一、P1 多轮：三种做法，两次实测

### 做法 A（废）：把工具结果回填，问模型「还需要别的吗」

```
第一轮：decide(问题) → notify_read → 结果
第二轮：decide_next(问题, 已有结果) → ???
```

探针 `tmp/probe_round2.py`（真机 1.7B，10 条：6 条单句 + 4 条复合句）：

| | 结果 |
|---|---|
| 无条件问第二轮 | 6/10，**其中 9/10 选 none** |
| 平均耗时 | 3.6s（白搭） |
| 把「明说两件事就必须选另一个」写进提示词后 | **10/10 选 none** |

诊断：小模型没有「我还缺什么」的自觉，只有「看起来够了」的默认。
这和 BFCL V4 的结论是同一件事的两面——4B 单轮 88%、多轮 22%，
崩的不是知识，是**「什么时候停」的判断**。
再强调一遍本仓的纪律：**新形状一律不交给小模型**。

### 做法 B（采纳）：拆后半句 → 走第一轮那套枚举

```
compound_intent("看看通知，顺便告诉我电量")        → True   （规则，不靠模型）
split_compound(...)                              → ("看看通知", "顺便告诉我电量")
decide("顺便告诉我电量")                          → device_status  ← 16/16 那套
```

真机复测（`tmp/probe_round2.py`）：

```
第二轮决策：10/10 = 100%
规则门（compound_intent）：10/10 判对
该问的那些（复合意图）决策准确率：4/4
平均耗时 0.5s（单句根本不问第二轮，省掉 3.6s）
```

连接词表：顺便 / 并且 / 以及 / 还有 / 然后 / 接着 / 同时 / 再者 / 另外 / 外加 /
再(帮我|看看|看下|看|读|扫|打开|查) / 一边…一边 / 既…又 / 先…再。
**连接词留在后半句里**（`顺便告诉我电量` 而不是 `告诉我电量`）——
16/16 那套决策本来就吃得住带连接词的说法，切太干净反而丢语义。

### 缰绳（四条，全在代码里）

| 缰绳 | 值 | 防的是什么 |
|---|---|---|
| 轮次硬上限 | `MAX_ROUNDS = 2` | 模型自我循环（BFCL 多轮崩） |
| 总预算 | `TOOL_BUDGET_S = 60` | 决策+执行一起拖垮对话 |
| 同工具不重复 | `tool in used → break` | 模型没听话时不要跟着傻 |
| 首轮失败即止 | `not ok → break` | 拿失败结果再赌一轮只会更糊 |

## 二、P2 权限三档：两层白名单 + 审计

```
DEFAULT_TIERS = {
    web_search / notify_read / screenshot_describe / device_status / wifi_survey → auto
    app_launch                                                                  → ask
}
```

两条硬规矩：

1. **工具名不在 DEFAULT_TIERS 里 = forbid，不看档位**。
   否则「配一个没见过的工具名并给它 auto」就成了提权后门，
   而配置来源是环境变量（`FLEET_TOOL_TIERS`），比代码更容易被动手脚。
   未知工具即便被外部 tiers 说成 auto 也不执行。
2. **权限在决策之后、执行之前再查一次**。模型输出的一切都不可信，
   决策层说用什么不代表就该让它用什么。

`load_tiers()` 读 `FLEET_TOOL_TIERS="app_launch=auto,wifi_survey=forbid"`；
非法项**打印并忽略**，不静默、不降级成 auto。

审计：每次执行（含被拒的）写 `~/.fleet/tool_audit.log`，
字段 `at / tool / arg / tier / outcome`。写失败就算了——审计不该拖垮对话。

**没做的**：短信 / 联系人 / 通讯录类能力压根没进工具表。
Operit 那类激进面不跟——隐私边界不是功能开关。
`shell.exec` 也不在首批里。

## 三、Sky MCP 下放：stdio 与 HTTP 共用一份派发

`fleet/mcp/server.py` 的 `MCPServer.handle()` 现在**直接吃数组**（批请求），
`handle_json()` 只是它的薄包装。于是两条传输共用同一份协议逻辑——
否则改了 stdio 忘改 HTTP（或反之）会在真机上表现为
「手机连上了但工具永远空」，极难定位。

端点：`POST /api/mcp`

- 挂在**两处**：GUI 主服务（127.0.0.1，令牌或设备凭据）与配对监听器
  （0.0.0.0 + TLS，手机走网络地址时用）。鉴权与主控端同一套，**没有匿名入口**。
- `/api/mcp` 必须**赶在 `_read_json()` 之前分流**：JSON-RPC 批请求是一个数组，
  而 `_read_json` 只认对象（它会先把请求体读走再回 400）。
  所以加了 `_read_json_loose()`。
- 通知（无 id）→ **204**；错误码照 JSON-RPC（-32600/32601/32602/32603）。
- **默认只导出只读能力**。`pcctl.proc.kill` 这类动手能力不导出，
  注册表层还会再 fail-closed 一次——**手机最多只能看，动不了手**。
  手机端真连上实测：tools/list 51 个工具，`pcctl_sysinfo` 能调通，
  `pcctl_proc_kill` 回 isError 且说清「没有导出」。

### 手机侧怎么连（两条路，实测）

| 路 | 通不通 | 说明 |
|---|---|---|
| `adb reverse tcp:8000 tcp:8000` + `http://127.0.0.1:8000/api/mcp` | ✅ 实测收到请求 | 推荐。手机上填 127.0.0.1，不出局域网 |
| 热点直连 `http://192.168.137.1:8000/api/mcp` | ❌ 实测 `ERR_EMPTY_RESPONSE` | 这台手机跑着 **Karing（全局规则 VPN）**，把 LAN 流量也劫走了 |

VPN 那条不是本仓的 bug，是环境事实，但必须写下来：
**下次再遇到「手机连不上电脑」，先看手机上的 VPN 是不是全局模式。**
天网 App 设置页新增了「Sky MCP 地址 + 复制」一行，不用再背这个地址。

## 四、顺手修的一个真 bug：连不上被写成「凭据失效」

天网 App 标题栏显示 `凭据失效：Failed to connect to /127.0.0.1:8000`。

- 实际原因：**电脑端服务没起 / adb 隧道断了**，跟凭据一点关系没有。
- 危害：人被指挥去重新配对，**配一百次也是同一个错**。
- 修法（`MainActivity.probeHealth`）：`ConnectException` / `SocketTimeoutException` /
  `UnknownHostException` 各说各的，只有走到最后才叫「凭据失效」。

这与本仓一贯的口径一致：
**「连不上」和「带了但不对」是两种事，处置不同，文案就必须分开。**

## 六、门禁

新增 `evals/t24_agent_tools_v2.py`，已入 `run_selftests.py`。四组 21 项：

1. **两条传输同一份派发**：同一请求 stdio 与 HTTP 响应相等；批请求顺序不变；
   纯通知 → None；jsonrpc 版本不对 → -32600。
2. **权限**：未知工具 forbid；app_launch 默认 ask；只读 auto；
   未登记工具即便被配成 auto 也禁；审计日志落盘。
3. **多轮缰绳**：复合句两轮各拿一个工具且第二轮只喂后半句；
   单句不问第二轮；首轮失败即止；同工具不重复；0 预算一轮不跑；拆句保连接词。
4. **真 HTTP 端到端**：临时起 FleetServer，不带凭据 401、initialize 走通、
   tools/list 有只读无动手、只读能调通、未导出回 isError、纯通知 204。
