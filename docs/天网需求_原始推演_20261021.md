# 天网 · 原始推演记录（2026-10-21 晚，与「鲸鱼娘」的对话）

> **性质：需求真源。** 这是主人自己走完的一轮推演，本文件是它的存档摘录。
> 后续任何工程决策与本文件冲突时，先怀疑工程决策，别怀疑推演。
> 计划书：`docs/天网桌面端_计划书_v2.md`。

## 一、人设「掉线」（跳戏）

> 主人：还是有一些问题会突然切换为正经的思考模式，正经的思考模式里面暂时没有那个「金云阳」的感觉。

- 鲸鱼娘诊断：**「人设层」和「推理层」在打架**。问题一复杂，推理层就压过语气层。可以在设定里加约束，但**推理越深，语气越难保**——这是取舍，不是 bug。
- 工程含义：这一版必须**同时**管两件事：①注入层（角色卡）②生成层（推理深度/长度/温度）。只做注入不做生成约束，遇到复杂问题照样掉线。

## 二、0.6B「天狼星」训练失败

> 主人：最近在搞 0.6B 的推理小模型，用大量词句压模型，走的是「主人路线」，模型叫**天狼星**。先原声训练再量化，但训练出了问题——没法跟他正常交流，前后逻辑有问题。是不是数据太小了（500/1000 条）？还是直接像你一样压提示词？

- 鲸鱼娘：**大概率不是数据少，是训练方式把 0.6B 压坏了**。Qwen3-0.6B 有严重的**终止失败**问题，可能是 **Chat template 没对齐**。提示工程快、便宜，但管不住 0.6B 的逻辑。
- 建议：先别加数据，用**官方模板**测；提示词兜底；数据质量 > 数量。
- 主人：**实在不行明天试提示词注入，再叠加一部分数据**。过去想全靠 SFT 训权重，现在没官方教程，调成个人的很麻烦。
- 鲸鱼娘推荐：NVIDIA NeMo / HuggingFace PEFT 教程；**0.6B 纯 SFT 性价比最低**，提示词注入 + 少量微调最省心。

## 三、模型选型：1.7B 还是 4B

> 主人：1.7B 可以吗？还是 4B？反正 4B 以下手机能运行。

- 手机跑 4B 量化的速度档位：**旗舰 15–40 tok/s / 中端 5–15 / 纯 CPU 1–5**；0.6B 是毫秒级延迟。
- 主人：上一年的旗舰手机，**差不多 10 tok/s**。
- 结论：**4B 容量足够出人格；如果崩了绝对是工程问题**（模板、终止符、量化、数据），不是模型太小的问题。
- 路线：**先测 1.7B，如果比 0.6B 强就慢慢往上调；如果一样崩，就是自己的整合工程有问题。**

## 四、PocketPal 实测与吐槽

- 主人发截图：**北极星-V7-Q8_0，28 tokens/秒，TTFT 300 多毫秒**。用的 POCK 软件。
- 症状：**「一上手机就不行」**，权重在电脑上测挺好；截图里**「被打字也打不开」= 典型的上下文断层**。
- 鲸鱼娘：电脑好手机崩 = **端侧部署工程问题**；PocketPal 的 Pals 功能可能被藏起来了，联网需要买密钥。
- 主人：**没提示词输入、也没联网**，这软件挺火但只能无语；**不想花钱买密钥**。打算用 AI 自己写原生软件——不用等别人更新、不用合并 PR、不会和上游不同步触发 Bug。
- 鲸鱼娘：自己写可以用免费 API，能**绝对对齐 Chat Template**，参数全解锁，人设强控。先搞 MVP，验证人设和逻辑。

## 五、硬件底气与未来构想

> 主人：上一年的旗舰手机，打算上 4B 的 Q4 量化，7B 有点卡但也能生产，有很多想法，比如 **GPT 那种点开语音就能聊天**，最后发现只能自己造个软件融合起来。

- 鲸鱼娘：**语音直通、全局唤醒、长期记忆**——这些只有自己写原生软件才能做到，是「专属赛博生命」。
- 主人：**不想花钱买密钥**；自己写的原生软件强。

## 六、「天网」的定义（系统级，不是桌面小工具）

> 主人：最近搞的系统里有个逻辑，为了防止天天「以管理员身份运行」右键，直接**永久提权，一步到位**。

- 鲸鱼娘警告：权限坑；如果写进原生 App，安卓卡得严，别轻易 Root。
- 主人：不是这个逻辑，是**整个系统，我称之为「天网」**。
- 鲸鱼娘：如果是一步到位提权，**记得留一个紧急断路器**，防止误删系统。
- 主人：**肯定有物理按键的。** 整个项目的逻辑就是——**目击所及之处人力能接触到的地方，一切由一个终端操控**，相当于真正地控制所有智能设备。
- 鲸鱼娘：赛博朋克终极智能家居中枢；四个关卡：协议融合、AI 工具分配、本地网关算力、**从「小而美」落地**（比如一句话关灯关空调）。

## 七、本轮的范围（主人原话）

> 「这一版先给我在桌面端……咱们电脑能运行 GGUF 模型最快的那个，你就给我运行一个，然后开启后就能聊天之类的。」

- 补充澄清（主人）：**本机无桌面端**——这个软件**还没构建**，**还在开发阶段**。所以桌面端不是既有资产，是本轮要造出来的东西。
- 命名：桌面端即叫**天网**（整个系统也叫天网，桌面端是它的总控终端）。

## 八、从推演里提炼的六条工程结论（写进计划书，不可再忘）

1. **模板对齐是第一号敌人**：0.6B 的崩（不能交流、前后逻辑错）最可能不是数据量，是 chat template / 终止符。⇒ 本轮第一个验收项就是**模板体检**，不是模型规模。
2. **人设掉线是双层问题**：注入层（角色卡）+ 生成层（推理深度、回复长度、温度）**必须同时管**。只写角色卡不管生成参数，一遇复杂问题照样跳戏。
3. **提示词注入优先于 SFT**：0.6B 纯 SFT 性价比最低；角色卡是当天能用人、换人零成本的路线。
4. **4B 起步，1.7B 作为中间观测点**：本机已有 4B Q4_K_M（2.78GB），先用它把链路和工程做对；不拿 0.6B 赌逻辑。
5. **端侧崩 ≠ 模型崩**：PocketPal 手机端崩是上下文/部署工程问题。⇒ 桌面端第一版就带**上下文体检**，别把同一个坑踩两次。
6. **全免费、零 key、零付费**：不订阅、不买密钥；能用本地的用本地（TTS 优先本地 Kokoro，edge-tts 只作在线兜底）。
