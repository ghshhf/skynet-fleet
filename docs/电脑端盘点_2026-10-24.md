# 天网（device-fleet）电脑端盘点

 counterpart of `docs/整体盘点与下一步计划_2026-10-24.md`（那边是手机+全局）。
本篇只答一件事：**电脑端有几套可运行的形态、各自做到哪、缺什么**。

## 一、电脑端有三种可运行的形态（同一套后端，三个壳）

<|constrain|> 形态 | 入口 | 面向 | 状态 |
|---|---|---|---|
| **T0 单行 REPL** | `fleet-cli.bat` → `python -m fleet.shell` | 键盘党 / 快速 probe | 可用，自动装 prompt_toolkit/rich |
| **TUI 全屏** | `fleet-tui.bat` → `fleet_tui.py`（python -m fleet.tui） | 无 GUI 也想看编队 | 可用，双栏（编队 + 会话），`--smoke` 只起界面不阻塞 |
| **GUI 图形版** | `python fleet_gui.py` / 打包 `fleet-gui.exe` | 主力用户（Windows） | 可用，pywebview 套本地 Web UI；`--no-window` 只跑服务本体（门禁/自动化用） |

三者共用 `fleet/gui/server.py`（HTTP 后端）+ `fleet/catalog.py`（109 条能力）；
GUI 比 TUI 多：审批弹窗、语音、配对 UI、控电脑面板、出图/出视频、模型下载页。

**GUI 参数**（`fleet/gui/app.py`）：`--no-window`（只服务，无窗）、`--voice`、`--smoke`、
`--port`、`--theme`、`--link`（固定端口 8000，靠 adb reverse 让手机接进来）、
`--link-port`、`--lan`（LAN 模式，**无鉴权，注释自认「留给下一版」**）。

## 二、GUI 是不是套浏览器

**是**——`pywebview`（WebView2）包本地 Web UI（`ui/` 目录，打包进 exe），
`fleet-gui.spec` 的 `hiddenimports` 明确含 `webview`，`datas` 带 `ui/` + `cards/`。
`--smoke` 路径故意**不 import webview**（`_require_webview()` 懒加载），所以无显示器也能冒烟。
没装 pywebview 时 `_require_webview()` 给明确报错，不许静默失败。

GUI 里有哪些 Tab（从 server 侧）：编队、设备、音频（`renderAudioTab`）、
连接器（`connector` Tab，mcp/`/api/mcp`）、审批中枢（W2 起）、
控电脑面板（`/api/caps` 拉全量能力 → ListView 选一项 → JSON 参数框）、
语音、模型下载、配对、设置、关于。

## 三、打包与 CI

- **`fleet-gui.spec`**：PyInstaller **onefile**，产物 `dist/fleet-gui.exe`（~59MB），
  `console=False`（无控制台）、UPX 压缩、runtime hook `tools/fleet_runtime_hook.py`；
  排除 torch/skynet/listen/speak/rules_relay（减体积）。打包脚本 `tools/build_gui.py`。
- **`fleet-tui.spec`**：没有 .spec 文件——CI 直接 `pyinstaller --onefile … fleet_tui.py`。
- **build-gui.yml**：Windows runner，Python 3.12；先 `python fleet_gui.py --smoke`（挡构建），
  再打包，再 `dist\fleet-gui.exe --smoke`（continue-on-error，onefile 冷启动解压慢）；
  上传 artifact `fleet-gui-windows`；tag `v*` 时挂 release。**paths-ignore** 安卓/文档/脚本。
- **build-tui.yml**：同结构，但触发器是 **paths 白名单**（`**.py`/requirements/.yml）；
  冒烟 `python -m fleet.tui --smoke`；产出 `fleet-tui-windows`。
- **build-android.yml**：只构建 Android，**不跑测试**。
- **结论：三条流水线全都是 build-only，没有任何一条跑 `run_selftests.py`**——
  这是电脑端和手机端共同的盲区。

## 四、版本号：电脑端**没有**统一版本号

- `fleet/__init__.py:22`：`VERSION = "0.1.0"`，**从不被任何地方读取或显示**。
- GUI/TUI/CLI 里 grep 不到版本显示；`/api/health`、`/api/fleet` 也不回版本。
- Android 端有 `tianwang_android/version.txt`（自增到 build 45），电脑端没有等价物。
- **结论：电脑端版本号目前是死代码**。每次发版只能靠 git tag / release 附件名，
  exe 自身不知道自己是哪个版本。这是个真实缺口，不是 cosmetic。

## 五、根目录 37 个老脚本：历史遗留，但仍在用

- `fleet/__init__.py` 第一段话就说清楚了：**旧脚本原地不动，fleet 只加薄适配**；
  把仓库根加进 `sys.path` 是为了 `python -m fleet` 能 import 到平铺的 `common`/`android_device`/`pc_state` 等。
- 关系是**单向依赖**：老脚本 import fleet（`commander.py:972` 用 `fleet.jobs`/`fleet.artifacts`，
  `node_agent.py:25` 用 `fleet.skynet_relay`），**fleet/ 从不 import 老脚本**（grep 证实）。
- `commander.py`（密码认证→注册→心跳看门狗→离线命令队列重放）和 `enroll.py`（PSK 账本）
  是跨机编队的**真实控制面**——`fleet/kinds/fleet_node.py` 只是薄适配器。
  也就是说：**编队 D1（远程代发）的代码其实大部分在老脚本里，fleet 包只是登记**。
- `desktop.py`、`phone_ops.py`、`platform_*`、`compute_runner.py` 等也都是根目录老模块，
  `fleet-gui.spec` 的 hiddenimports 把它们全列进去，打包时一起塞。
- **风险**：两层（老脚本 + fleet 包）职责重叠，`commander.py` 里还留着
  `from fleet import jobs as J` 这种运行时 import，版本漂移时容易炸。

## 六、电脑端相对手机端的缺口 / 重叠

**电脑有、手机没有**
- 全屏 TUI / 单行 REPL 两种 CLI 形态（手机只有 App）
- pywebview 图形版（手机是原生 Android）
- 跨机编队控制面 `commander.py` / `enroll.py`（手机只是被控端）
- 计算节点/作业板/产物中心的**写者**（手机只读）

**手机有、电脑没有**
- 本地 LLM 推理（Termux llama-server；电脑靠免费后端 pollinations/ovh/llm7，或 Ollama）
- 本地出图 sd.cpp+Vulkan（电脑端 `image.gen` 走远端/后端，`render.*` 只出 HTML/帧）
- 语音输入主链路（电脑端 `voice.py`/`voice_stream.py` 有 `--selftest` 但**未接入门禁**）
- 配对 UI、审批弹窗的**接收端**（电脑是审批的发起端/闸门，手机是确认端）

**电脑端「只有声明没实现」的东西**
- `fleet/__init__.py:22` `VERSION = "0.1.0"` 死代码（见 §四）
- `fleet/catalog.py:127/130/133` `shell.exec`/`file.push`/`file.pull` —— D0 只登记，
  控制面代发口在老脚本 `commander.py` 里，fleet 包只登记 unsupported
- `fleet/catalog.py:265-275` `video.gen` —— P3 壳 + 远端路由，无 kind 声明
- `fleet/transports/base.py:3-4` rtsp/ssh/http/mqtt/ir 五条通道「留到 D2、D4 再建」
- `fleet/skynet_relay.py:13` `--lan` 模式无鉴权
- `fleet/mcp/schema.py:51-52` `json` 类型映射「留给以后」
- `fleet/model_catalog.py:9` 模型目录「真跑 LLM 对话见下一轮」，`:57` 北极星 URL 占位
- `fleet/kinds/card_store.py:134` 角色卡详情「暂不支持」非 aicc 源
- `fleet/gui/server.py:189-191` 审批闸门默认 None（W1 遗留注释，W2 已搭壳但 GUI 弹窗仍只在 MainActivity）

## 六、电脑端的真正短板

1. **版本号死代码**——发版时 exe 不知道自己的版本，只能靠 git tag。
2. **测试盲区和手机端一样**：CI build-only，门禁 67 项在本地跑，12 个 evals + 8 个 tools
   门禁 + 6 个模块自测全部游离。
3. **两层架构**（老脚本 + fleet 包）职责重叠，`commander.py` 运行时 import fleet，
   版本漂移时容易炸；hiddenimports 列了 40+ 老模块，打包体积 59MB。
4. **GUI 是浏览器壳**——pywebview 依赖 WebView2 运行时，目标机没装就起不来；
   这是 Windows 端的部署风险，手机端没有这个问题。

## 七、建议补的（给用户看的，和手机端 A 批次并行）

- **C0**：给电脑端加版本号 single source of truth（建议 `fleet/__init__.py:VERSION` 真正被读，
  `/api/health` 回版本，GUI 关于页显示），Android 那边的 `version.txt` 自增机制可以对齐。
- **C1**：CI 至少一条流水线跑 `run_selftests.py`（和手机端 B3 合并做）。
- **C2**：老脚本与 fleet 包的边界文档化（哪些是主、哪些是适配），避免 drift。
- **C3**：GUI 部署文档写清 WebView2 依赖与 fallback（或考虑纯 HTTP + 浏览器打开）。

---

**一句话**：电脑端不是「没做」，是「做了三套形态但版本号死代码、测试盲区、两层架构重叠」；
手机端的问题是「最后一公里」，电脑端的问题是「最后一层（版本/测试/部署）」。
