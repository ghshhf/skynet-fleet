## 〇、一句话结论

T 版（Textual）不是「差一点」，是**方向不对**：它本质是把终端表格换个皮，再怎么排版也还是文本流。日常入口必须换成一个**真正的 Windows 窗口应用**；界面照抄 WorkBuddy 这套经典布局（左侧导航 + 中间对话 + 底部输入）；耳朵（语音输入）用现成的 `polaris-audio-io` 外设接上，嘴（语音输出）用同一套双引擎；「说完 → 转写 → 动手」这条链子上，**最该先做的不是识音，而是闸门**——ASR 会误识别，误识别就是真鼠标真键盘乱动。

**选型一句话**：本地 Web UI（HTML/CSS/JS）＋ Python 本地服务，套一个 pywebview 窗口壳。后端一行不重写（`reg.call()` 原样暴露），麦克风白送（浏览器 `MediaRecorder`），界面还原度最高。

## 一、为什么放弃 T 版做日常入口（事实，不是感觉）

| 现象 | 根因 | 有没有救 |
|---|---|---|
| 「跟命令行一模一样」 | Textual 的 `Static`/`RichLog`/`DataTable` 都是**字符网格**控件，画出来还是行和列 | 救不了。换控件库不解决「它是终端」这个前提 |
| 长任务只能一行行长 | `RichLog.write` 是逐行追加，没有富文本、没有卡片、没有进度条 | 换不了。流式本身是对的，但呈现是文本 |
| 截图只能看盲文点阵 | 终端里没有位图 | 换不了。必须换渲染面 |
| 键盘驱动 | Textual 全靠按键绑定 | 鼠标交互需要真 GUI 事件循环 |

**但 T 版不是废品**——它是**第二个显影面**，继续留着：
- 它的价值在**无头/自动化/远程**场景：SSH 上去就能用、CI 里能跑、`--smoke` 自检、13 英寸小屏笔记本能用。
- 本轮新增的 `host.*`（本机操控）也只有在 T 版里能验证盲文预览那种降级形态。

⇒ **不是重写，是加第三个显影面**。三面共用一张注册表（这已经是仓库的既有架构，见 `fleet/core/registry.py`）。

```
                    ┌─────────────────────────┐
                    │  能力注册表（唯一真相）  │
                    │  Registry / DeviceResult │
                    └───────────┬─────────────┘
            ┌───────────────────┼───────────────────┐
      ┌─────▼─────┐      ┌─────▼─────┐      ┌─────▼─────┐
      │ 命令行 shell │      │  T 版 tui  │      │ 图形版 GUI  │
      │ (人/脚本)   │      │ (SSH/无头) │      │ (Windows)  │
      └───────────┘      └───────────┘      └───────────┘
```

## 三、技术选型：三案对比（这一节要你拍板）

| 方案 | 界面还原度 | 复用 Python 后端 | 麦克风能力 | 打包体积 | 新增工具链 | 主要风险 | 评分 |
|---|---|---|---|---|---|---|---|
| **A. 本地 Web UI + pywebview 窗口壳**（推荐） | ★★★★★ 现代前端直接抄 | ★★★★★ `reg.call()` 原样暴露 | ★★★★★ 浏览器 `MediaRecorder` 白送 | ~60–80MB | 零构建（纯手写 HTML/CSS/JS） | 多一个本地 HTTP 服务（须防裸奔，见红灯 4） | **★★★★★** |
| B. PySide6 / Qt 原生 | ★★★ 暗色布局要写一套 QSS | ★★★★★ | ★★ QtMultimedia 在 Windows 上设备枚举坑多 | ~70–90MB | 无 | 界面还原度低，QSS 学习成本 | ★★★ |
| C. Electron | ★★★★★ | ★★ Python 只能当子进程，状态要跨进程传 | ★★★★★ | 180MB+ | Node 全家桶 | 等于重造一个 WorkBuddy | ★★ |
| D. Tauri | ★★★★★ | ★★ 同上 | ★★★★★ | ~8MB | Rust | Rust 工具链本机没有，编译链长 | ★★ |

**选 A 的三条硬理由**：
1. **麦克风白送**。浏览器 `MediaRecorder` 拿音频是一行 JS；Qt 里要跟 `QtMultimedia` 的设备枚举和 WAV 编码搏斗（Windows 上尤其容易出「录到 0 字节」）。语音是这轮重点，麦克风必须零成本。
2. **后端一行不重写**。GUI 只做「显影面」，能力调用全部走 `Registry.call()`，拿到 `DeviceResult` 直接渲染。符合仓库既有铁律（唯一真相）。
3. **界面还原度最高**。要抄的就是这套布局，用 HTML/CSS 抄是最短路。

**选 A 的代价（诚实说）**：
- 需要一个本地 HTTP 服务（`127.0.0.1` + 随机端口 + 一次性 token）——这是**新引入的攻击面**，它能驱动你的鼠标键盘。所以红灯 4 写死防护。
- 需要一个前端资源目录。**不许用 CDN**（本仓有「断网可用」要求），依赖全部 vendor 到本地。
- pywebview 的 WebView2 运行时：Win11 自带；Win10 可能要装一次 Edge WebView2 Runtime（写进安装说明）。

**B 什么时候才对**：如果你明确不要「网页感」，或要求**单文件 exe、零 Web 依赖**，就走 B。我建议 A，但你说了算。

## 四、架构：GUI 壳 ↔ 本地服务 ↔ 设备层

```
┌───────────────────────────────────────────────────────────┐
│  pywebview 窗口（无边框，1440×900 起步）                     │
│  ┌──────────┬──────────────────────────┬────────────────┐ │
│  │ 侧边导航  │  主内容区（对话/设备/任务） │ 右侧折叠面板     │ │
│  └──────────┴──────────────────────────┴────────────────┘ │
│                          ▲ WebSocket 流式                  │
│                          │ HTTP  /call /cap /api          │
└──────────────────────────┼────────────────────────────────┘
                           │
        ┌──────────────────▼────────────────────────────────┐
        │  fleet/guiserver.py（新）                           │
        │  · 127.0.0.1 随机端口 + 每次启动一次性 token         │
        │  · /api/caps  /api/devices  /api/availability      │
        │  · /api/call  （强制走 Registry.call + 闸门）        │
        │  · /ws/chat    （ai.chat 的流式逐块回显）            │
        │  · /ws/voice   （录音 → ASR → 意图 → 执行）          │
        └──────────────────┬────────────────────────────────┘
                           │
        ┌──────────────────▼────────────────────────────────┐
        │  能力注册表（不动）  Registry / DeviceResult        │
        │  设备：host / android_phone / lan_scanner /         │
        │        internet / ai / fleet_node                   │
        └───────────────────────────────────────────────────┘
```

**三条设计纪律**（写进代码，不靠自觉）：
1. **GUI 不许自己实现任何能力**。它只能调 `Registry.call()`。要新能力，去 `catalog.py` 加一条 `Capability`。
2. **GUI 不许自己缓存设备状态**。面板上每个状态都来自 `reg.availability()`，来源唯一。
3. **闸门在服务端，不在界面**。审批弹窗只是闸门的**表现**，判定权在 `Registry` 那一侧——否则 GUI 绕开闸门就等于没有闸门。

## 五、语音接口：耳朵 → 脑子 → 手

### 5.1 目标场景（用户原话拆解）

> 「相当于我手机放在这里，我就跟你说话，然后音频自动语音转文字，然后操控电脑之类的」

拆成四个动作：**听**（采集一段语音）→ **转**（ASR 转文字）→ **懂**（文字→意图→能力请求，走 `reg.call` 过闸门）→ **做**（执行）。

### 5.2 链路

```
浏览器 MediaRecorder ──(WAV blob)──▶ /ws/voice 上传
        │
        ▼
  存临时 WAV ──▶ polaris-audio-io listen.hear(path, language="zh", beam=1)
        │                                    │
        │                            （简体 prompt 防繁体，见坑 3）
        ▼
  转写文本 ──▶ 意图/能力请求 ──▶ Registry.call(cap, args, gate=语音闸门)
        │                                    │
        │                              （动手能力要二次确认，见 5.4）
        ▼
  气泡回显原文 + 结果 ──▶ 可选 TTS 播放（edge-tts / SAPI 双引擎）
```

### 5.3 复用什么（都是已实测的资产，不重新造）

| 环节 | 资产 | 已实测数据（2026-10-19，本机 i5-12450H CPU） |
|---|---|---|
| 录音 | 浏览器 `MediaRecorder`（PC 麦克风） | 零成本，浏览器自带 |
| ASR | `D:/work/_local_ai/train_15b/modules/polaris-audio-io/listen.py::hear(path, language="zh", beam=1)` | whisper-small（244M，完整 encoder+decoder）→ **RTF 0.78**，闭环 **CER 0.125** |
| TTS | 同目录 `speak.py::speak(text, engine="auto", playback=True)` | edge-tts 神经音色（联网，~2s/次）／SAPI 离线回落（永远在） |
| 能力执行 | `fleet/core/registry.py::Registry.call` | 已有闸门/审批档/结果信封 |
| 手机操作 | `fleet/kinds/android_phone.py`（screen.read / input.tap / tree.read …） | 已有 |

**边界（必须先认账）**：
- **RTF 0.78 意味着「不能边说边出字」**。Whisper 的 encoder 要吃整段音频才能出字，所以交互形态是「**说完 → 转写 → 执行**」，不是「说一半就动手」。要真流式得上 chunked whisper，**这是后面的事，不混在第一版**。
- **CER 0.125 是自家 TTS 闭环的数字**（音色单一、无噪声无口音），真实麦克风会明显更差。**不许拿 0.125 对外宣称**。
- ASR 跑在哪要选（§十三-3）：本机后台线程（跟 GUI 抢 CPU）vs 编队节点（手机/盒子跑，PC 只收文字）。**我倾向后者**——总纲已定调「她的宿主机放手机，不放台式机」。

### 5.4 🔴 语音的安全闸：两段式确认（本计划最重要的一条设计）

**键盘点的鼠标**和**语音误识别的鼠标**，后果差一个数量级：
- 你说「帮我点那个」，ASR 可能听成「帮我点那个嘛」/「打开那个」/空串——一旦直连 `host.input.click`，就是**真的在乱点你的桌面**。
- 而且**声音可以来自环境**（电视、路人、视频会议），不需要你按任何键。

⇒ **定死**：语音路径触发的**动手能力**（`host.input.*` 及一切 `side_effect=True`）必须走两段式：

```
① 语音识别出意图 → 界面明确写出来： 「我将：单击 (842, 316)」
   同时用 TTS 念一遍
② 人在 5 秒内说「嗯 / 好 / 执行」→ 才真的执行
   超时或说别的 → 取消，什么都不做
```

- 「执行」词表要小：`嗯`/`好`/`执行`/`来吧`/`确认`。
- **只读能力不走两段式**（`host.screen` / `host.monitor` / `ai.chat`）——读东西没有副作用。
- 也可以弹一个**必须手动点**的确认框（等价甚至更严），但语音场景下人往往不在电脑前，所以**口头确认是主路**。
- 这条要写进 `fleet/core/registry.py` 的闸门层（不是写在前端），**前端绕不过去**。

### 5.5 手机当麦克风（缺口，写清再说）

用户原话是「手机放在这里」。但查了手机能力清单（`fleet/kinds/android_phone.py`）：
**手机现在没有音频采集能力**——只有 `screen.read` / `tree.read` / `apps.list` / `app.foreground` / `notify.read` / `state.read` / `bt.scan` / `input.tap|type|key` / `ir.send`。

⇒ 「用手机麦克风说话」是一条**新工程**，不是接线活。两条路：

| 路 | 做法 | 代价 | 建议 |
|---|---|---|---|
| **A. PC 麦克风**（第一版） | 浏览器直接录 | 几乎零成本 | **先做这个**，W4 阶段 |
| B. 手机麦克风（后续） | ① 手机装 `node_agent` 录 PCM 上传（走已有通道 + 凭据账本）；或 ② adb 录音类方案 | 新增 `audio.capture` 能力 + 传输 + 编码 | 排在 W4 之后，单独排期 |

第一版**不假装**支持手机麦克风——界面里麦克风按钮默认用 PC 麦克风，手机麦克风是后面的选项。

## 七、分阶段（顺序锁死，一步一验收，不许跳步）

> 每阶段的「验收」都是**可测的**，不是「看起来不错」。验收不过就不许进下一阶段。

### W0 · 窗口壳与静态布局（不碰任何能力）
- 产出：pywebview 窗口 + 静态 HTML 稿，**7 个部件全占位**（侧栏/标题栏/对话流/输入区/后端选择器/右侧面板/任务流），暗色 + §二 那套配色。
- 验收：①双击一个 .bat 能开窗，窗口不白屏；②布局与 §二 对照稿一致（**你先看图点头**）；③不写任何能力调用代码。
- **这一阶段的唯一目的是给你看排版。** 不通过就改到通过。

### W1 · 本地服务 + 注册表暴露（后端先立，界面后跟）
- 产出：`guiserver.py`（127.0.0.1 + 随机端口 + **一次性 token**）；`/api/caps`、`/api/devices`、`/api/availability`、`/api/call`（强制走 `Registry.call`）、`/ws/chat`（流式）。
- 验收：①**无 token 的 `/call` 一律 401**（红灯 4）；②GUI 点一个只读能力，能看到 `DeviceResult` 的真实字段；③动手能力**必须**弹闸门，不弹就是红的；④服务端日志能看到每次调用。

### W2 · 对话主区（把 T 版的 AI 页搬进气泡）
- 产出：消息列表（富文本：代码块/表格/列表）、输入区（Enter 发 / Shift+Enter 换行 / `+` 工具条）、后端选择器（真读 `ai.backends()`）、流式逐块回显。
- 验收：①问一句话，回复**逐块**长出来（不是等完一次性刷）；②选后端 = 真切后端（多后端同问时按 `[id]` 分气泡）；③后端选择器里的清单与 `ai.list` 一致。

### W3 · 设备页与「主机」可视化（图形化现有 host.*）
- 产出：资源条（CPU/MEM/DISK/网速做成真进度条，不再是盲文点阵）、进程表（可排序）、**屏幕预览真图**（PNG 直接显示）、应用清单。
- 验收：①屏幕预览是**真图片**（不是盲文）；②点「截屏」2 秒内出图；③每个面板的状态都来自 `reg.availability()`，界面不许自己算一套（红灯 5）。

### W4 · 语音入口（耳朵）
- 产出：麦克风按钮 → 录音 → WAV → ASR → 文字进输入框（**不自动执行**，先让你看转写对不对）→ 你确认后才发。
- 验收：①说一句中文，10 秒内出文字并落在输入框；②转写错字能手动改；③繁体问题已消（简体 prompt 生效）；④**转写这一步不许自动执行任何能力**。

### W5 · 语音 → 能力请求 → 执行（含两段式闸门）
- 产出：意图映射（关键词/句式 → `cap` + `args`）、两段式口头确认、TTS 播报「我要做什么」。
- 验收：①说「截图」→ 界面复述 + 口头确认 → 才截；②**误识别不会动手**（说「打开浏览器」在没确认时**绝无**任何点击发生）；③只读能力不要求确认；④超时自动取消。

### W6 · 语音出口（嘴）与「她」接线
- 产出：TTS 播放（edge-tts/SAPI 双引擎，断网回落 SAPI）、人格（天狼星/K423）接入 GUI、主动性（她主动开口）。
- 验收：①断网时仍能出声（SAPI）；②人格在 GUI 与命令行**是同一个人**（同一人设文件、同一份记忆，不许各长一个）；③她主动开口有频控/静默时段（沿用 `persona.py` 既有刹车）。

### W7 · 打包与分发（可选，最后做）
- PyInstaller + pywebview → 单 exe（含 WebView2 检测与提示）；安装说明、卸载、开机自启开关。
- 验收：换一台**没装 Python** 的机器能双击跑起来。

## 八、五道红灯（写在计划里，也写进代码）

| # | 红灯 | 怎么测 |
|---|---|---|
| 1 | **界面不许卡** | 长任务（web.papers 几分钟）在后台跑，界面必须还能打字/切页/滚动；帧率不掉。撞法同 T2 门禁（那次真撞过：post_message 冻死事件循环） |
| 2 | **能力只有一个真相** | GUI 调的每一项能力都进同一张 `Registry`；全仓 grep 不许出现 GUI 自己实现的第二套能力 |
| 3 | **动手必须过闸门** | GUI 路径和命令行路径调用同一个 `approval=ask` 能力，**都必须**被拦；语音路径也必须（§5.4） |
| 4 | **端口不裸奔** | 服务只绑 `127.0.0.1`；每次启动生成一次性 token；`/call` 无 token → 401；token 落进程内存不落盘 |
| 5 | **界面不许骗人** | 面板上每个状态字段都来自 `reg.availability()` / `DeviceResult`；界面不许自己缓存第二套状态（撞法同 T0 门禁：状态栏自己算一套） |

## 十、风险与坑（已实测的写实测，估的写「估」）

| # | 坑 | 依据 | 对策 |
|---|---|---|---|
| 1 | **GUI 最容易变成第二个大脑**——自己在前端实现能力，绕过注册表与闸门 | 仓库铁律「唯一真相」 | 红灯 2 + 3；代码评审专门查「前端有没有自己 fetch 数据后自己算」 |
| 2 | **本地 HTTP 服务 = 新的攻击面**（它能点你的鼠标） | 本计划新增组件 | 红灯 4：127.0.0.1 + 一次性 token + 无 token 401 |
| 3 | **Whisper 中文吐繁体**（「離線引擎測試」） | `polaris-audio-io/README.md` 实测 | 必须给简体 prompt（`listen.py: PROMPT_ZH`），不许省 |
| 4 | **prompt 吃掉 token 预算** → 报 `combined length exceeds max_target_positions 448` | 同上 | `max_new_tokens` 要减 `prompt_ids` 长度**再减 8** |
| 5 | **ASR 不能流式**（RTF 0.78） | 实测 | 第一版就定「说完→转写→执行」，不假装能边说边做 |
| 6 | **CER 0.125 不能对外宣称** | 同上 | 界面/文档里写「闭环自测值，真实更差」 |
| 7 | **长任务冻死界面**（真撞过：post_message 让事件循环整个停住） | T2 门禁的事故记录 | GUI 侧一律「后台线程 + 流式回显」，不许在 UI 线程跑活 |
| 8 | **WebView2 运行时** Win10 可能没装 | Windows 常识 | 启动自检 + 明确提示；W7 再考虑内嵌 |
| 9 | **不许用 CDN** | 本仓「断网可用」要求 | 前端依赖全部 vendor 到本地 `fleet/webui/vendor/` |
| 10 | **别把「她」写进 GUI** | 总纲 P6：单一存在 | GUI 只是显影面，人格/记忆只有一份（`persona_state.json` 属本体节点） |
| 11 | **Windows 上 subprocess 编码坑** | 仓库自测修复记录第 6 条（cp936 解 utf-8 中文乱码） | 显式 `encoding="utf-8", errors="replace"` |
| 12 | **本机推理天花板**：4B 只有 3.86 tok/s | 实测 | GUI 里的「她」连手机/盒子或远程，别指望本机跑大模型 |
