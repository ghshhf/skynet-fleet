# 计划书 · 无感验证与沙箱（2026-11-02）

> **一句话**：无感验证不是一道题，是一次**整机汇报的评分**。
> 所以这条线上唯一正确的动作不是「改属性」，是「让汇报内部不自相矛盾」，
> 而上限是「**真的换一台机器**」——那就是沙箱。

## 一、判断：检测方看什么

主人 11-02 给的原话：

> 无感打分本质上它是通过验证浏览器的历史记录，还有那个 IP，就是相当于整机汇报系列的。
> 相当于无感打分的逻辑是需要你整体伪装。伪装的最高境界就是说，临时起沙箱。
> 你要知道，网络上、理论上是没有秘密的。不可能有任何人说我检测什么。
> **检测的本质就是说，看你汇报什么，看你用什么连接。**

拆成三层：

| 检测方看 | 我们拿什么对 | 现状 |
|---|---|---|
| **用什么连接** IP / ASN / TLS 指纹 | `proxy.*` 10 条 + 自建内核 7891 + 中继 + 穿透 | ✅ 最厚的一层（早就有） |
| **汇报什么** UA / 平台 / 时区 / 语言 / GPU / Canvas / 字体 | `fp_profile` + `fp_inject` | ✅ 本轮从零建起 |
| **一致吗 + 来过吗** | `fp_profile.contradictions()` + `fp_sandbox` | ✅ 本轮 |

### 由此推出的一条反直觉结论

**质量标准不是「像不像人」，是「自不自洽」。**

检测方不需要知道你是什么，只需要知道你不矛盾。所以：

- 改 UA 不改 `navigator.platform` → 假
- 改时区不跟出口 IP 的地理对上 → 假
- 改 UA 语言不改 `Accept-Language` → 假
- 伪装了 GPU 却在 WebGL 里漏出 `SwiftShader` → 假，而且是最硬的一种
- UA 说 Chrome 142、UA-CH 说 138 → 假（这两个必须同源）

⇒ 模块的主功能不是「生成随机值」，是 **`contradictions()`：把矛盾喊出来**。
生成随便生成，能过校验的才叫档案。

## 二、三层零件

```
L1 出口    net.resolve_proxy() / proxy.*          连接层（已有）
L2 档案    fleet/fp_profile.py                   值 + 矛盾校验
L3 注入    fleet/fp_inject.py                    CDP 原生 + initScript
L4 历史    fleet/fp_sandbox.py                   profile 目录 + 出口绑定
```

### L2 · 档案（`fp_profile.py`）

一个档案 = 一组**必须互相吻合**的属性：

```
geo/tz/locale  ⇄  ua/platform/hardware_concurrency/device_memory
               ⇄  screen + dpr（联合）/ avail / viewport
               ⇄  webgl_vendor / webgl_renderer / fonts
               ⇄  ua_ch.brands 的版本必须等于 ua 的版本
               ⇄  age_days=0 不许有 cookie
```

`OS_SPECS` 只放**真实存在**的组合 —— 校验的力度来自「池子小」，不是「规则多」。
池子越小，随便编的值越容易被抓出来。

### L3 · 注入（`fp_inject.py`）—— 分工不能乱

| 手段 | 管什么 | 为什么 |
|---|---|---|
| **CDP 原生覆盖** | UA / UA-CH / 时区 / 语言 / DPR / 视口 + screen | 内核级。页面 `Object.getOwnPropertyDescriptor` 拿到的仍是**真原生 getter**，无法从「是不是 native code」反推 |
| **initScript 补丁** | screen 兜底 / `outerWidth` / `webdriver` / 核数 / 内存 / platform / WebGL `UNMASKED_*` / Canvas / Audio / fonts.check | CDP 管不到的才用 JS。每个被替换的函数都打 `[native code]` 的 toString |

**只做 JS 的后果**：UA 改了、UA-CH 没改，两边一比就露。
**只做 CDP 的后果**：WebGL 还报着 SwiftShader。

两个时机问题（都踩过）：
1. `connect_over_cdp` 接管已有 context 时，`add_init_script` **只对新页面生效** → 必须 reload。
2. CDP 覆盖绑在 **session** 上，`detach()` 就还原 → Session 对象必须持有引用。

### L4 · 沙箱（`fp_sandbox.py`）

**沙箱比伪装高一级**：伪装是「我假装是另一台机器」，会被抓矛盾；
沙箱是「我真的重新出生了一次」，矛盾天然不存在。

两种，别混着用：

| | ephemeral（一次性） | persistent（养号） |
|---|---|---|
| 做什么 | 抓一次就走 | 长期同一个身份 |
| 代价 | 零历史 = 风控里的「新访客」，需要登录态的站上分偏低 | **出口 IP 必须绑定，不许漂** |
| 清理 | ttl_days 到期由 `purge` 清 | 不参与过期清理 |

> ⚠️ **IP 一漂，历史全部作废。** 对方看到的是「同一台机器突然换了国家」，
> 比一个全新访客危险得多。所以 `check()` 把 `egress_drift` 单列一条，
> 措辞里必须说清「搬家比新访客更危险」。

## 三、真机实测抓到的四个问题（离线全绿但真环境里全露）

| # | 现象 | 根因 | 改法 |
|---|---|---|---|
| 1 | UA 是 `(Windows NT 10.0)` | `ua_marks` 一个字段兼两个用途（拼 UA + 校验） | 拆成 `ua_os`（完整段，含 `; Win64; x64`）+ `ua_marks`（校验子串）；顺手删掉 WOW64 选项（意味 32 位进程，跟 UA-CH `bitness=64` 冲突） |
| 2 | `inner` 1536×864 > `avail` 1536×816 | 把整屏当视口，地址栏没地方放 | 加 `viewport` 字段（= avail 减浏览器 chrome）；CDP 用 viewport 而不是 screen；加 `screenWidth/screenHeight` 参数把 screen 也提到内核级 |
| 3 | `ua_ch` 永远是 None | **不是注入失效** —— `navigator.userAgentData` 只在**安全上下文**暴露，`about:blank` 不算 | 真机验证起本地 http server 走 `127.0.0.1`。改完就看见裸 headless 的 UA-CH 写着 `HeadlessChrome/156` |
| 4 | `1366×768` 配 `dpr 1.5` | dpr 独立随机，与分辨率无关 | `screen` 池改成 `(宽, 高, 该分辨率下的真实 dpr 集合)`，校验变联合判断 |

另加一条**单向**规则（`fp.apply` 里）：

> **声称的版本高于真实引擎才危险** —— 新版才有的 API 我们报不出来，一问就露；
> 声称旧版本很常见（用户不更新浏览器），不算破绽。

真机实测：真引擎 156、档案 142 → 放行；档案改 999 → 精确拦下（`diff: ua_version`）。

### 真机结果（三种机型零差异）

| 项 | 裸 headless | 注入后 |
|---|---|---|
| UA | `HeadlessChrome/156.0.8078.4` | `Chrome/142.0.0.0`（括号完整） |
| UA-CH | `HeadlessChrome/156` | `Chromium/142 + Google Chrome/142 + Not?A_Brand/24` |

| screen / avail / inner | 1280×720 / 1280×720 / 1280×720 | 1536×864 / 1536×816 / 1536×729（三层递减） |
| Canvas | — | 同档案恒定、跨档案不同 |

## 四、边界（写死，别越界）

1. **不打分。** 分数的语义是「检测方会给多少」，我们不知道对方怎么算 ——
   返回一个分数就是拿猜测冒充事实。全部能力只报客观矛盾（期望 vs 实际）。
2. **不保证过。** 能保证的是「内部不自相矛盾」，不是「一定放行」。
   对方有权因为任何理由拒绝，那是他们的权利。
3. **不碰主人日常用的浏览器。** 沙箱一律在 `~/.fleet/sandbox/`，
   不碰 `~/.fleet/browser/p9222` 那个平时在用的。
4. **沙箱跟滑块是两条线。** 滑块是「有题给你做」，无感是「没题，只有背景打分」。
   混在一起就会指望滑块那套去解无感，那是错的。

### P1 落地记录（11-02）

`fp_egress.py` 三条纪律：

1. **探不出来不许当没问题** —— `ok=False` 时 `check()` 会单独报 `egress_unknown`，
   绝不因为「没发现不一致」就放行。这是整个文件里最重要的一条。
2. **强制显式代理，不吃环境变量** —— 本机注入过 `HTTP_PROXY=127.0.0.1:3067`，
   urllib 默认会吃到它，那会把「探出口」探成一条谁都不知道的线路。
   所以永远显式建 `ProxyHandler`，直连就传 `{}`。
3. **两个源互为冗余** —— `ifconfig.co` / `ip-api.com`，全挂才报错。

顺带一个判据：`looks_residential()` 只按 ISP 名里有没有云厂商字样**粗判**，
判不出来返回 `None`（不知道就说不出来，不许猜）。机房 IP 本身不是错，
但要知道代价 —— 无感打分看的是「像不像一个真人上网的线路」。

**实测当前环境的真实状况**：出口在新加坡 AWS 机房。
这意味着拿它配 `geo=CN` 的档案会立刻矛盾（时区说上海、IP 在新加坡）。
要跑 CN 档案，得先让出口回来。
