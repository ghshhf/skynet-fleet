## 〇、一句话结论

**下一步不是继续加界面，是把界面里那些「点了没反应」的东西变成真能点的。**

实测发现：当前 GUI 侧栏有 6 个导航项（新建任务 / 助理 / 专家技能·连接器 / 定时任务 / 资料库 / 更多），
`ui/app.js` 里**只绑定了 9 个元素的事件**——这 6 个导航项**一个都没绑**。
也就是说，界面上摆着 6 个入口，点下去**什么都不发生**。

这正是本仓反复吃过的那个亏的最阴版本：**界面骗人**。
- 之前进程 CPU 整列 0%（psutil 首采恒 0）——安静地骗你；
- 现在导航项摆着但不响应——同样是安静地骗你，因为它连报错都不报。

⇒ **本轮主线定为：X0「让界面上摆着的东西都是真的」**。
  把 6 个死导航项逐个接上真实视图（能力页 / 设备页 / 人格页 / 定时任务 / 资料库），
  把 WorkBuddy 那套「专家·技能·连接器」的产品形态用**本仓已有资产**长出来，
  而不是抄它的皮。

**为什么这一步排在语音和人格之前**：
1. 语音缺硬件（本机 `waveInGetNumDevs()==0`，无麦克风）⇒ 界面做了也验不了，**留到有硬件的机器上做**；
2. 人格（「她」）需要 SFT 模型到位 ⇒ 排在后面；
3. 界面死链**今天就能验、今天就能红**，而且它已经在骗你了。

### X1 · 「专家·技能·连接器」三 Tab 页（WorkBuddy 形态的核心）

**产出**：中栏主内容区支持三种视图切换，形态照 WorkBuddy：

- **技能 Tab** ← 本仓的 70 项能力，按**能力族**分卡片（`pcctl.` 14 / `adb.` 14 / `host.` 8 …）。
  每张卡：能力名、中文说明、**谁声明能做**（`registry.owners()`）、副作用档（`auto` / `ask`）。
  搜框按族/名字过滤（WorkBuddy 技能页有搜索框）。
- **连接器 Tab** ← 本仓的 9 台设备，卡片墙。
  每张卡：设备名、kind、探活状态点、**为什么不能用**（拿不到就写明原因，不许空着装作正常）。
  未连接的显示 `+`（WorkBuddy 的连接器卡就是 `+` 图标）——**本仓语义是「加入编队」**。
- **专家 Tab** ← 本仓的**能力组合包**（不是 WorkBuddy 的人格专家）：
  一个「专家」= 一组能力的白名单 + 一个人设引用（如「大肥鱼」）。
  底层就是 `catalog.py` 的能力子集 + `cards/*.json`。

**映射的一处诚实说明**：
WorkBuddy 的「连接器」= 外部服务（QQ邮箱/腾讯文档/企业微信）；
本仓的「连接器」= **设备**。这不矛盾——WorkBuddy 连的是**别人的服务**，
我们连的是**自己的硬件**。但卡片语义要改：WorkBuddy 的 `+` 是「接入这个服务」，
我们的 `+` 是「把这台设备纳入编队」。**不许照抄图标不抄语义。**

**验收**：
1. 三 Tab 切换**不重载页面**（纯前端视图切换，零 HTTP 往返 ⇒ 响应必须 < 100ms，肉眼可辨）。
2. 技能卡的数量 = `/api/caps` 的 `count`（**70**），少一张门禁红。
3. 连接器卡的探活状态与 `/api/devices` 的 `ok` 字段**逐个一致**；不一致 ⇒ 红灯 5 重犯，门禁红。
4. 每张连接器卡都带**「为什么不能用」**这一栏；设备在线时该栏写「可用」，不许留白。
5. 搜索框输入 `adb` → 只剩 `adb.` 族 + 名字含 adb 的卡。

### X2 · 人格抽屉（点左下角头像）

**产出**：点 `.sb-foot` 弹出右侧抽屉，形态照 WorkBuddy 人格抽屉（小路那张）：

- 「记忆与进化」：显示 L3 记忆条目数 + 逐条删（**E-7：个人数据绝不进模型参数，只进可寻址可删记忆层**）；
- 「外观」：明/暗切换（已有 `themeBtn`，接进抽屉）；
- 「关于」：版本 + 能力数 + 设备数 + 在线数（真数，不写死）。

**不做**：积分 / 套餐 / 加油站 / 成长计划（§六）。

**验收**：
1. 抽屉里的情绪值 = `persona_state.json` 的真值，改文件后刷新页面即变（不许前端硬编码）。
2. 删一条记忆后条目数立刻减 1，且**再刷新不回来**（真删，不是隐藏）。
3. 抽屉里显示的「在线设备数」= `/api/devices` 里 `ok=True` 的个数（实跑现值 **9/9**）。

### X3 · MCP 出口（注册表 → MCP server）

**验收**：

### X4 · 语音入口的界面那一半（**等硬件，不等排期**）

## 五、红灯（写进计划，也写进门禁）

| # | 红灯 | 怎么测（可执行） |
|---|---|---|
| 1 | **界面不许卡** | 长任务在后台跑，界面还能打字/切页/滚动；帧率不掉（撞法同 T2 门禁） |
| 2 | **能力只有一个真相** | GUI 调的每项能力都进同一张 `Registry`；全仓 grep 不许出现 GUI 自己实现的第二套能力 |
| 3 | **动手必须过闸门** | GUI / 命令行 / **MCP** 三条路径调同一个 `approval=ask` 能力，**都必须**被拦 |
| 4 | **端口不裸奔** | 只绑 `127.0.0.1` + 随机端口；一次性 token；无 token → 401；token 不落盘 |
| 5 | **界面不许骗人** | 每个状态字段都来自 `reg.availability()` / `DeviceResult`；界面不许自己算第二套状态 |
| 6 | **🆕 界面不许摆死链** | `ui/index.html` 里每个带 `id` 的可点元素，必须在 `ui/app.js` 里绑上事件（豁免仅 2 个，且写进代码注释） |
| 7 | **🆕 空状态不许装作有** | 拿不到值时写明原因，不许给假的 0 / 空表格 / 假「可用」 |
| 8 | **🆕 数字不许写死** | 能力数/设备数/在线数一律来自接口；改注册表后界面数跟着变 |
| 9 | **🆕 门禁红必须意味着代码坏了** | 离线 eval 一律把网络 I/O 假掉；不许让「本机服务没开 / key 过期」染红门禁 |

## 六、验收标准（X0 + X1 完成后）

1. 双击开窗，**左栏 6 个导航项逐个点得动**，每项都真换视图（渲染图对比，不是看 console）。
2. 「专家·技能·连接器」页三 Tab 切换，技能卡 **70 张**（= `/api/caps` 的 count），连接器卡 **9 张**。
3. 每张连接器卡显示探活状态 + 「为什么不能用」；不可用的设备**不许显示成正常**。
4. 点左下角头像 → 人格抽屉：角色卡名、情绪三值、记忆条目数，与 `persona_state.json` / `memory.py` 真值一致。
5. 删一条记忆 → 刷新后不回来（E-7：可寻址可删）。
6. GUI 与命令行调同一项能力，**结果字段一模一样**（同一张注册表的直接后果）。
7. 别的程序不带 token 打 `/call` → **401**。
8. `run_selftests.py` 全绿（现 51 项 + 本轮新增项）。
