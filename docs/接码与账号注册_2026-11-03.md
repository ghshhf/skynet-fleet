# 账号注册与接码平台 —— 把「注册」拆成四段

> 2026-11-03 · 起因：用内置浏览器手工点 OpenRouter 注册，连败三次，猜了三个原因
> （域名？IP？密码？），最后发现真正的卡点是**手机扫码**。
> 本文是那三次失败换来的判断，加上接码平台的实测行情。
>
> **定位**：这一份是 `总纲 §七` 里的技术专题，落地物是
> `fleet/signup_kit.py` + `fleet/sms_kit.py` + `evals/t70_signup_kit.py`。

---

## 一、结论前置

注册不是一个动作，是**四段流水**。每段的失败原因完全不同，混在一起谈就永远在猜。

| 段 | 问什么 | 谁来做 | 对应能力 |
|---|---|---|---|
| **L1 身份** | 有没有「能收码的地址」 | 机器 | `signup.mail_new` / `signup.disposable` |
| **L2 通道** | 站方要密码、邮件码、还是社交 OAuth | 机器（读站方公开端点） | `signup.profile` / `signup.recon` |
| **L3 闸门** | 有没有 captcha / 滑块 / 算力挑战 | 机器 | 复用 `slider.*` / `protocol.*` |
| **L4 兜底** | 要不要绑手机 | **人在回路** | `signup.handoff` / `sms.*` |

> 一句话：**「注册失败」这四个字没有信息量。必须报到 L1~L4 的哪一段，并带证据。**

---

## 二、那三次失败到底败在哪（复盘）

| 次 | 我当时的判断 | 实际原因 | 代价 |
|---|---|---|---|
| 1 | 以为是「三级域名被 Google 识别成临时邮箱」 | 假。用户用同一封域名却成功了 | 浪费一轮，还让主人以为在瞎猜 |
| 2 | 以为是「IP 被滥用了，得换 IP」 | 部分真（出口是共享机场节点），但不是主因 | 又是一轮 |
| 3 | 真因：**自动化输入把密码字符吞了** | `!` 被写成 `l`，两次密码对不上；换纯字母数字后立刻通过 | — |

三条教训，写进规矩：

1. **先看页面给的原文，再猜原因。** 那次页面一直写着「请重新输入密码」，
   而我盯着「无法创建账号」在猜 IP。两句话不是一回事。
2. **自动化输入的字符会变形。** 需要过密码框的地方，一律用**纯字母数字**。
   `! # @ $` 这些在模拟键盘事件里最容易被吞或替换。
3. **「换 IP」是最后一招，不是第一招。** 换 IP 的成本是真金白银，而且掩盖真因。

## 三、四段流水怎么用

### L1 身份：临时邮箱

```python
from fleet import signup_kit as SK

mb, err = SK.mailbox_new("mailtm")      # 或 "tempmail_lol"
print(mb["address"], mb["disposable"], mb["disposable_reason"])
```

**关键**：`disposable` 这个字段必须在建信箱时就告诉你，而不是等你注册被拒才发现。
判定方向是**宁可误报可疑**——反了会白烧一个账号。

实测：`mailchecker` 那份 57702 条公开名单**不够用**。`fldubai.com` 在名单里查不到，
Clerk 照样拒。所以判定不能只靠名单，得看**域名形状**（三级域名是典型一次性邮箱）。

### L2 通道：站点画像

```python
SK.PROFILES["openrouter.ai"]        # 已实测，带 checked 日期
SK.recon("some-new-site.com")       # 现场探
```

探测顺序按**信息密度**排，不是随便试：

| 顺序 | 端点 | 一次能拿到什么 |
|---|---|---|
| 1 | `/api/v1/settings/public`（Sub2API） | 全部注册规则：邮箱白名单、OAuth 开关、验证码开关 |
| 2 | `clerk.<domain>/v1/environment` | 全部登录方式、手机号开关、一次性邮箱策略 |
| 3 | 首页 HTML | 只剩面板类型和验证码厂商 |

读不到就报 `unknown`，**不许按经验编**。

### L3 闸门

不在这里重复造。滑块走 `slider.*`，协议走 `protocol.*`。

### L4 兜底：人工交接 + 接码

**这一段的正确形态是 `signup.handoff`，不是硬撑。**

```python
SK.handoff("openrouter.ai")
# -> {"why": "L4 —— Google 账号创建最后一步是手机扫码，纯脚本过不去",
#     "steps": [{"n":1,"url":"https://accounts.google.com/signup","do":"..."}, ...]}
```

Google 现在给的**不是短信，是扫码**：要求手机上已有一个登录着的 Google 账号来扫。
扫不出来才退到短信。**扫码这一关，机器过不去，这是事实不是缺陷。**

## 四、接码平台：能补短信，补不了扫码

### 行情（2026-11 抓的，价格会变，只当量级）

| 平台 | Google/Gmail 单价 | 成功率 | 接口风格 | 备注 |
|---|---|---|---|---|
| SMS-Activate | ~$0.08–0.15 | ~97.7% | `handler_api.php?action=...`，返回一行文本 | 20 分钟窗口；轮询式，无 webhook |
| 5SIM | ~$0.008 起（最低） | ~73% | REST `/v1/user/buy/activation/...` | 最便宜；东南亚号成功率差，美欧号 ~85–90% |
| SMSBower | ~$0.004 起 | — | REST | 「无码不收费」，失败自动退款 |
| SMSPool / HeroSMS / OnlineSIM | ~$0.10–0.12 | — | REST | 备选 |

**共同点**：一次性号码、无码自动退款、轮询间隔 3–5 秒、超时窗口 20 分钟。
**共同坑**：都没有 webhook，只能轮询。

### 三条硬规矩

1. **号码归属地必须和出口 IP 同国。** 号码在美国、IP 在香港，平台侧一关联就露馅。
   这是「买了号还是过不去」最常见的原因 —— **不是号的问题，是环境不一致**。
   `sms_kit.country_for_ip()` 干这个；未知国家**返回空并报错，不许兜底猜**。
2. **不替你花钱。** 默认只做 `sms.price` / `sms.balance`。`sms.buy` 标了
   `side_effect=True`，必须过一次审批闸门。
3. **失败要释放。** 不结单会让号码一直被占；失败的号及时取消，否则白扣。

### 为什么它救不了 Google 账号

Google 的 L4 现在优先要**扫码**（同一台设备上已登录的 Google 账号去确认），
短信是备选。接码平台能提供短信，**提供不了一个已登录的手机**。

所以：**Google 账号这一环是人在回路，别的站可以全自动。**
把这句话写死，比反复试要省钱得多。

## 五、OpenRouter 交接单（可照抄）

| 步 | 地址 | 做什么 | 拿到什么 |
|---|---|---|---|
| 1 | https://accounts.google.com/signup | 建 Google 账号。**密码只用字母+数字** | 能登录的 Google 账号 |
| 2 | https://openrouter.ai/sign-up | 点 `Continue with Google` → 选账号 → 走完 OAuth | 登录态 |
| 3 | https://openrouter.ai/settings/keys | `Create Key`，复制 `sk-or-v1-...` | API key |
| 4 | — | key 交给 fleet（或 `OPENROUTER_API_KEY`） | 一路货源 |

### OpenRouter 的免费额度（官方写死的数字）

| 累计充值 | 每分钟 | 每天 |
|---|---|---|
| < 9 刀 | 20 | **50** |
| ≥ 9 刀 | 20 | **1000** |

阈值实际是 9 刀（文档写 `FREE_MODEL_CREDITS_THRESHOLD - 1`，理由是「吸收四舍五入和充值手续费」）。

**三个坑**：

1. `models` fallback 数组里**混进付费模型**，免费的打不通时会自动切付费并记账。
   想保持免费，数组里只能放 `:free`。
2. **多开完全无效。** 官方原文：*"Making additional accounts or API keys will not
   affect your rate limits, as we govern capacity globally"*。多号多 key 都不涨额度。
3. `block_email_subaddresses: true` —— Gmail 的 `xxx+1@gmail.com` 别名被禁。

### 免费层有什么

14 个 `:free` 模型，其中 3 个上下文达 1M：

| 模型 | 上下文 | 模态 |
|---|---|---|
| `thinkingmachines/inkling:free` | 1M | 文+图+**音** |
| `nvidia/nemotron-3-ultra-550b-a55b:free` | 1M | 文（550B MoE） |
| `nvidia/nemotron-3.5-super-vl:free` | 1M | 文+图+**视频** |
| `google/gemma-4-31b-it:free` | 262K | 文+图+视频 |
| `cohere/north-mini-code:free` | 256K | 代码专用 |

还有个别名 `model: "openrouter/free"`：一条请求自动从这 14 个里挑支持所需功能的，
并在多个模型间轮换。**通的话它就是「一路顶十四路」的入口。**

## 六、边界

1. 这套东西是**注册自动化基建**，只用于本人/已授权账号。
2. 不猜站点规则；读不到就报 `unknown`。
3. 不产生假成功；没 key 报 `no_key`。
4. 花钱的能力必须过审批。
5. **人工交接是正式出口。** 把「这一段只有人能过」写清楚，比硬撑有价值得多。
