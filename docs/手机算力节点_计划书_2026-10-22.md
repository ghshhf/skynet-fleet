## 0. 结论前置

1. **可行，且方向正确**：这台 PC 的三大短板——无 NVIDIA 独显、16G 单通道内存、核显弱——恰好都是手机的强项。K80 至尊版的天玑 9400+（Immortalis-G925 MC12，1.5GHz）GPU 算力与 LPDDR5X 带宽都数倍于本机 UHD 核显 + 单通道 DDR4（估，附 §7 实测协议）。
2. **但要分层，不能一句话「手机跑电脑环境」**：
   - 🟢 **现在就能干**：图片生成（SD 1.5/Turbo/SDXS 512 档）、LLM 推理（llama.cpp Q4 7B）——Termux + Vulkan 有成熟开源实现和实测先例。
   - 🟡 **能干但是拼接流**：视频 = 分帧出图 + 插帧 + ffmpeg 拼装，不是一步到位的扩散视频模型；硬件插帧芯片（D2）Termux 摸不到。
   - 🔴 **想都别想**：NPU/D2 独显直通（QNN/NNAPI 要 Android app，Termux userspace 拿不到）、训练/微调。
3. **「运行电脑环境」的准确答案**：通用 Linux 环境用 Termux + proot-distro Debian 就行；但 **AI 推理必须在 Termux 原生 Bionic 层跑 Vulkan**（proot 的上下文切换会重罚 GPU 驱动调用，实测 SIGSEGV 风险）——这是调研实证，写进部署手册。
4. **顺序建议**：v1 先做「出图工人」闭环（PC 提交 → 手机排队 → 回传 PNG），因为它直接验证主人要的「批量排队 + 网络配对传送」主链路，且是最短可验收路径。LLM 是 v2，视频是 v3。

## 1. 硬件事实（2026-10-22 实跑快照 + 官网规格）

| 项 | 本机 PC | K80 至尊版（主人的手机） |
|---|---|---|
| SoC | i5-12450H（4P+4E，核显 UHD） | 天玑 9400+（台积电 3nm，8 核，X925 3.73GHz） |
| GPU | UHD 核显（无 NVIDIA） | Immortalis-G925 MC12 @1.5GHz + 独显芯片 D2 |
| 内存 | 16G **单通道** DDR4 | 12/16G LPDDR5X |
| 存储 | SSD | UFS 4.1 |
| 散热 | 笔记本风冷 | 6500mm² 3D 冰封循环冷泵 |
| 电池 | — | 7410mAh，**旁路充电 Plus**（插电玩时不走电池，正好给 sustained compute 用） |
| 现状 | ADB 当前**未连接**（`adb devices` 空） | 已装 Termux（主人原话），fleet-bridge 可注入 |

**为什么手机更适合推理（估，附 §7 验证）**：出图/LLM 是显存带宽敏感型。LPDDR5X 估 60–70GB/s vs 单通道 DDR4 估 19–21GB/s（约 3 倍）；GPU 算力估 4–5 TFLOPS FP16 vs UHD 估 0.3–0.5（约 10 倍）。本机跑 7B LLM 生成 token 是内存墙限速，手机同模型有真实提速空间。

## 2. 开源调研实证（2026-10-22 搜索）

- **stable-diffusion.cpp**（leejet，MIT）：纯 C/C++，Termux 可编译，**Vulkan 后端支持 Adreno/Mali**。有第三方打包 `termux-diffusion` 公布实测：512 档 SDXS 一步 3.8s / 10 步 32s（Galaxy S25，Adreno 830）——**这是商业包的自报数据，标注「待我方 K80U 实测复核」**。
- **反面先例**（无 GPU 时）：SD888 纯 CPU 跑 SD1.5 约 100s/step、一张图 20+ 分钟——所以 **Vulkan 绑定是否正确是生死线**：Termux 自带的 Mesa wrapper（`$PREFIX/lib/libvulkan.so`）会掉进软件光栅或 SIGSEGV，必须 dlopen 系统 ICD（`/system/lib64/libvulkan.so`）。
- **llama.cpp**：Vulkan 后端在 Adreno 上有社区验证，Q4_K_M 7B（约 4.4GB）在 16G 手机上可跑；功耗/发热可控。
- **RustDesk 模式**（前文已调研）：信令+打洞+端到端加密——本计划的传输直接复用已验收的 N+1b 配对通道，不重复造。
- **Mali/Immortalis 特有坑**：FP16 denormal 会导致绿图/NaN，需 FTZ 编译选项（我们的 G925 是 ARM 架构，命中此坑概率高，v1 实测盯这一点）。

## 3. 架构：手机当「算力工人」

```
┌────────────── PC（主人日常机，本计划里是「工头+客户」）──────────────┐
│ 出图/出视频/LLM 的调用方（技能、批处理脚本、GUI）                    │
│   └─ 任务提交 → fleet 任务队列（SQLite，优先级/取消/断点）            │
└───────────────────────┬───────────────────────────────────────────┘
                        │ N+1b 配对通道（已验收）：
                        │ UDP 广播找手机 → 6 位验证码握手 → TLS1.3 + 会话令牌
                        ▼
┌────────────── 手机 Termux（fleet-worker 常驻）─────────────────────┐
│ 拉任务 → 本地跑（sd.cpp / llama.cpp / ffmpeg）→ 结果回传（登记制）   │
│ 纪律：插电才接活 · 温度墙暂停 · 电量下限 · wake-lock · 失败回退 PC   │
└──────────────────────────────────────────────────────────────────┘
```

设计原则（全部继承已有纪律，不发明新机制）：
- **发现 ≠ 配对 ≠ 执行 ≠ 任意访问**：四道各自独立，任一环节都要显式授权。
- **文件走登记制**：结果像截图一样凭 `result_id` 回取，不开任意路径读。
- **白名单端点族**：`/api/job/*`（submit/status/cancel/fetch）与 `/api/remote/*` 平行，ai.chat/skill.* 等敏感面依旧 404。
- **fail-closed**：worker 不在/超时/温度超限 → 任务排队或回退本机，绝不静默吞任务。

## 5. 手机侧纪律（设备是耐用资产，不是耗材）

- **插电 + 性能模式才接活**：K80U 旁路充电 Plus 正好；未插电默认不接（可配，主人可放开）。
- **温度墙**：机身温度阈值默认 **42°C**（估，读 `/sys/class/thermal`），超限暂停出图排队，不硬扛。
- **电量下限**：默认 **20%** 以下不接新任务，进行中的任务跑完当前张即停。
- **Termux 三件套**：`termux-wake-lock`（防休眠降频）+ Termux 电池优化设为「无限制」+ 通知栏常驻（主人可见 worker 在干活）。
- **任务粒度**：单任务默认 ≤10 张图或 ≤5 分钟，超时即失败回退，防长时间独占。
- **主人一票否决**：手机上常驻「熔断」按钮（复用 N+1b revoke 机制），任何时候一键全停。

## 6. 诚实边界（写死，不许当卖点）

1. **D2 独显 / NPU 摸不到**： Termux 是 Linux userspace，MTK APU 与 D2 的硬件接口要 Android app + NNAPI/QNN。本条标红，v1 不做、不承诺。
2. **Vulkan 绑定是生死线**：绑错（Termux Mesa wrapper）= 软件光栅或崩溃；部署手册第一步就是验证系统 ICD 绑定，含 Mali/Immortalis 的 FP16 FTZ 编译选项。
3. **热降频必然发生**：持续出图 10 分钟后帧率曲线一定劣化（冷泵也压不住持续满载）——v1 实测记录曲线，调度器按曲线自适应降优先级，不假装恒速。
4. **第三方跑分是自报数据**：§2 里 S25 的 3.8s/32s 是商业包宣传口径，未经我们复测；K80U 真实速度以 v1 实测为准，**先测再承诺**。
5. **蜂窝大文件回传慢**：手机走 4G/5G 提交任务可以，但几十 MB 的结果回传受上行限制（估 1–5MB/s 量级），v3 视频优先走 WiFi/打洞直连。
6. **16G 单通道是 PC 自己的瓶颈**：如果某项在 PC 上本来就不堪重负，排队等手机比并行双端更快——调度要「择优」，不是无脑offload。

## 7. 实测协议（每期验收必跑，写进报告）

1. **出图基准**：固定 prompt/seed/512×512/10 步，PC 端记录 submit→首字节→完成三段耗时；手机端记录 queue→generate→upload；跑 20 张出分布（中位数 + P90），连续 10 分钟记录温度-帧率曲线。
2. **带宽基准**：双方跑同模型 llama.cpp pp512 + tg，记录 tok/s（v2 用；v1 可选先做，作为「手机到底快多少」的底数）。
3. **失败注入**：worker 杀进程 / 拔网线 / 温度桩超限，各验任务不丢、状态可见、可取消。
