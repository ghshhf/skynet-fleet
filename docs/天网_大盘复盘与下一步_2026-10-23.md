## 〇、结论前置

1. **地基已锁死且真机验证过**：设备层（9 设备 / 87 能力 / 58 门禁全绿）、技能自进化（P0-P4、p0_gate 11/11、p5_gate 9/9）、AudioSync v2（手机变音箱）、安卓 ADB 桥（fleet-bridge 16KB 常驻可注入）。

3. **最深、最远的缺口是「她」**：0.6B SFT 没训成（V10 三次停机作废）、全仓库只有一处调模型（无对话通道）。这是总纲 Phase A 的唯一红点，短期填不上。
4. **大方向推荐**：把安卓出图节点 **fleet 化**（接入 commander/orchestrator/node_agent），让"PC 调度手机算力出图"成真——这是 N+2（手机端算力调度）的实质落地，也是天网区别于"又一个人端聊天机器人"的关键。

## 二、主线判断：两条候选路线

### 路线甲（推荐）—— 安卓节点 fleet 化 = N+2 实质落地
- **是什么**：把 `SdBridge` / `QueueRunner` 封装成 `node_agent` 的一个 capability；`commander` 能向手机派发"出图"任务，手机跑完把 PNG 路径/结果回传 PC。复用已有 fleet 网络 + MCP 通道，**不新造编排层**。
- **为什么是下一步**：刚做的出图是最新、最硬的证据，顺手把它变成"天网的一部分"是性价比最高的收口；它正是 v4 主线 N+2 要的"从控制设备到调度设备上的算力"。
- **张力**：v4 锁了"N 没好不许进下一环"。但 N 是 GUI 诚实化（死链/对比度），与"安卓节点接入"不冲突——可并行，不破序。

### 路线乙（按 v4 官方主线）—— 先收口桌面端原点 N → N+1 → 再 N+2
- **是什么**：先做 X0（死链 14 清零 + 门禁）→ X1（三 Tab 页显影 70 能力 / 9 设备）→ X2 人格抽屉 → X3 MCP 出口。
- **为什么有人选**：让"人"先看清编队有什么，再开"机器"的口；符合已拍板顺序。
- **代价**：与刚做完的安卓出图脱节，能量不能立即沉淀进大盘。

**我的建议**：**路线甲为主、路线乙并行**。安卓 fleet 化是 momentum 所在、也是天网的差异化；桌面 N 的 X0/X1 是"让已有资产显影"，可同期推进不抢资源。两路都不过 v4 的序（N 的 GUI 诚实化与 N+2 的节点接入是不同维度）。

## 三、大方向主线（路线甲展开，三阶段）

> 每阶段带可测门禁；阶段间一步一验收，没证据不算完成。

### 阶段 1 · 安卓节点收口（先补齐松手项）
- 推送 `3079e05` 到 GitHub。
- 定掉出图计划书 §9.1 两个待拍板：① 默认档位（Turbo-only 过 3 分钟闸，SD1.5 标准 11 分钟）→ 建议默认 Turbo + UI 留 SD1.5「精细但慢」入口；② 33s/步 是否追（建议不追，SD1.5 即使追到 15s/步 仍 5 分钟，性价比低）。
- **门禁**：`git log` 见推送；UI 默认档位与耗时标注可见。

### 阶段 2 · fleet 化封装（N+2 落地）
- 在 `node_agent` 注册 `image.gen` capability，参数对齐 `QueueStore.Item`（prompt/neg/size/steps/seed/cfg/model）。
- `commander` 侧加派发入口：PC 发"出图"→ 手机 `SdBridge` 加载模型→`QueueRunner` 串行执行→结果（PNG 落 `Pictures/fleet/` + 日志）回传 PC。
- 复用 fleet 既有网络/MCP，不新写编排；动手能力照红灯 3 过审批闸门。
- **门禁**：PC 侧一条命令让手机出一张图，PNG 回到 PC 指定目录；掉线自动回退；不派 ECS 控制面。

### 阶段 3 · 多节点算力协同（N+2 终局）
- 电脑 A 重推理派手机 B 出图；三端（PC A / PC B / 手机）互为调度者与被调度者。
- **门禁**：派发 ≥99%；单任务不跨节点串味；掉线回退；不派 ECS 控制面。

## 四、发散型方向（跳出主线，供拍脑袋）

1. **手机算力对外服务化**：把刚做好的出图封装成自托管 API（类似 pollinations），手机闲时对外提供出图；接已积累的免费 LLM 端点（pollinations/llm7/kilo/OVH）做成"边缘出图网关"。
2. **边缘 AI 集群**：不止 SD——把 Whisper / TTS / 小模型都做成手机上"可调度微服务"，fleet 变成家里的边缘 AI 集群，PC 只当调度台。
3. **出图质量飞轮**：若 33s/步 根因（ggml Vulkan 在 Mali 低效）某天解决，SD1.5 标准档也能用 → 触发"画质 vs 速度"重新分配，Turbo 退为快速档、SD1.5 回归默认。
4. **视觉闭环创作**：天枢（VL）当眼 + 安卓出图当手 → "看一张图、改一张图"的迭代创作，直接接总纲 Phase D（能看见）。
5. **跨设备记忆一致性**：手机出的图 / 队列状态进 L3 记忆，PC 侧能检索 → 呼应总纲"换设备接着聊，她还记得昨天出的那张图"。
