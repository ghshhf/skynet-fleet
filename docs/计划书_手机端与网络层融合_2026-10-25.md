## 一、先把话说清：现在手里到底有什么

### 1.1 两个手机端（产品形态的参照）

| | Operit | pocketpal-ai | 天网 Next |
|---|---|---|---|
| 语言 | Kotlin + Compose | React Native + TS | Kotlin + Compose |
| 星数 | 8952 | 8795 | — |
| 本地模型 | ❌（塞在工具里的旁枝） | ✅ GGUF/llama.cpp | ✅ 已定接口，待接 JNI |
| 云端模型 | ✅ 主路 | ❌ 完全没有 | ✅ 已定接口，待接 SSE |
| 编队/多机 | ❌ | ❌ | ✅ 独有 |
| 界面厚度 | 21 个 feature 模块 | 9 个 screen | 4 个页面（原型） |

**结论**：它们各自瘸一条腿，这是主人当场的原话，不是我的判断。
天网 Next 的取舍点是 **`Model.kt` 里那个 `ModelBackend` 接口**——只要那个 `if (是不是本地)`
永远只出现在 `backendFor()` 一处，加第三个、第四个引擎都不用改 UI。

### 1.2 三个网络层（云端额度的来源）

| | freellmapi | zen-gate | dsh-our-free-model |
|---|---|---|---|
| 语言/形态 | TS 服务 / Docker | Go 桌面托盘 | JS 零依赖插件 |
| 星数 | 40910 | 227 | 41191 |
| 端点 | `:3001/v1` + 统一 Key | 面板可配端口 | 本机 `8326`、独立服务 `18900` |
| 覆盖 | 34 家 635 个免费端点 | OpenCode Zen 车道 + 14 家预设 | 10 个账号渠道 + Kilo + 匿名车道 |
| 局域网 | 需自行暴露 | 面板可配 | **自带中继（0.0.0.0 + 独立 LAN Key）** |
| 特点 | 额度跟踪、按 Key 计用量、自动 failover | 自动注入 Agent 配置、单模型体检、模态路由 | 零依赖、免登录免 Key、说 Anthropic + OpenAI 双协议 |
| 协议 | OpenAI | OpenAI + Anthropic | Chat/Responses + **`/v1/messages`（Anthropic 原生）** |

**关键判断：这三个不是三个系统，是同一种资源的三个实例。**
它们做的事完全一样——**把上游的免费额度，翻译成一个 OpenAI 兼容端点**。
差异只在「上游从哪来」「怎么轮换」「有没有局域网口」。

⇒ 所以融合的正确姿势**不是分别对接三次**，而是抽一层：

```
        ┌──────────── Provider 注册表（一层）────────────┐
        │  id / kind / baseUrl / key / 探测结果 / 模型表 │
        └───────┬──────────┬──────────┬────────────────┘
                │          │          │
           freellmapi   zen-gate    dsh        自付 Key    本地 llama.cpp
```

### 2.1 三个设计决定，以及为什么

**(1) 手机不直连那三家，只连天网路由层。**
理由不是"架构好看"，是三条硬理由：
- 密钥全在 1 号机，**手机丢了不泄露**；
- 手机换网/换 WiFi 不用重配（只记一个天网地址）；
- 三家网关的额度是**共享池**，手机直连就无法统一记账，会互相抢额度。

例外：dsh 自带 LAN 中继、且中继 Key 与本机 Key 互不通用——**离线应急时手机可直连 dsh**，
这是唯一允许的旁路，写进设置页当"应急通道"，默认关。

**(2) 降级链顺序，按"失效概率"从低到高排。**

**为什么本地排第一**：它不依赖任何上游政策，唯一会挂的原因是手机/机器性能。
**为什么自付 Key 排最后**：它是唯一会真花钱的，只在前面全挂时才动。

**(3) 额度按"上游账号"记账，不按 provider 记账。**
freellmapi 的教训：它按 Key 跟踪用量才能不超额。我们三家混用时，
**同一个上游（比如智谱）可能被 dsh 和 zen-gate 同时消耗**——
所以记账的键必须是 `上游厂商 + 账号`，不是 `网关名`。
这一条不做，就会出现"以为还有额度、实际早打满"。

## 三、风险，写在最前面而不是最后面

这三条不是免责声明，是**会让整个方案某天突然失效的现实**：

**R1 · 对抗性方案，随时失效。**
zen-gate 自己的 README 写着：v1.8.0 曾因上游按客户端指纹拦截（一律 403）**退役整条车道**，
v1.9.0 靠对齐官方客户端指纹恢复。这句话的意思是——**上游随时能再关一次**。
⇒ 应对：降级链必须至少有一环不依赖"伪装"，即本地模型或自付 Key。**不能只有白嫖。**

**R2 · 免费池可能记录提示词。**
zen-gate 明说「免费池提示词可能被上游记录，别交机密内容」。
⇒ 应对：`SettingsScreen` 里那个「优先本地」开关不是装饰，是**隐私闸门**。
涉及本机路径、密钥、私人内容的对话，强制本地；网关层只许过"公开可查"的问题。

**R3 · 账号风险。**
这类方案本质是蹭免费车道，可能违反上游 ToS。
⇒ 应对：**只挂小号**，不绑支付方式，不与主账号同设备指纹；一旦某渠道开始 403 就停用，
不反复重试（重试会把账号推到风控前面）。

## 四、分批路线（每批都有可验证的判据）

### P0 · Provider 注册表 + 探测（本机 CLI，先能看见）

- 新增 `fleet/providers.py`：`Provider` 数据类 + 注册表 + `discover()` + `probe()`
- `discover()` 三路并行：**扫候选端口**（3001/8326/18899/18900/8080/8090）、
  **读各自配置文件**（`%APPDATA%\zen-gate\channels\`、`~/.our-free-model`）、**手填**
- `probe()` 打 `/v1/models`，记录：存活 / 首字延迟 / 模型数 / 是否需要 Key / 上次成功时间
- 兼容 `re_llm.py` 已有的 `~/.workbuddy/models.json` 形状，产出同一份文件

**判据**：`python -m fleet.providers` 一条命令列出所有网关，
每行带 `[活/死] 延迟 ms 模型数`，缺哪个能说清缺的原因（不是"不可用"三个字）。

### P1 · 手机端接进来（看得见）

- `ModelsScreen` 的"云端引擎"分组升级为**网关分组**：每个网关一张卡，
  显示 存活灯 / 延迟 / 模型数 / 额度剩余（能拿到的才显示，拿不到就写"未知"）
- 加"应急直连"开关（连 dsh LAN 中继）
- 设置页暴露降级链顺序，可拖动

**判据**：手机上能看见至少 2 个网关的真实状态，并能用其中一个跑通一轮完整对话
（不是假流式，是真 SSE）。

### P2 · 路由与降级（用得起）

- `route(task)`：按 模态需求（图/音/长上下文）+ 降级链 + 当前额度，选一个 provider
- 失败自动换下一个，**响应里标注实际用了谁**（学 zen-gate 的响应头做法）
- 额度记账按 `上游+账号`，落 sqlite，按天聚合

**判据**：手动关掉降级链第一环，同一轮对话不中断，日志能指认"从 A 换到了 B"。
额外：连续 50 轮不同任务，额度记账与上游面板数字对不上时能报警。

### P3 · 随时随地（隧道）

- dsh 的 LAN 中继已有，先复用它验证"手机在外网也能用"
- 再上 `trycloudflare` 隧道（已有 handoff 隧道经验）把天网控制面暴露给手机
- 记住 1 号机是 `0.0.0.0` 还是仅 LAN 的取舍：**默认只绑 LAN**，隧道按需开、带独立 Key

**判据**：手机关掉 WiFi 走 4G，仍能对话；关隧道后 30 秒内手机侧显示"离线"而不是转圈。

### P4 · 工具调用统一（真 Agent）

这一步才轮到"像 Operit"：
- 把天网 149 项能力（`catalog.py` 那份唯一真相）投影成模型可调用的 tool schema
- 工具调用走天网自己的闸门（`tg_mcp.py` + `policy.json` 那套代码级闸门，不靠提示词约束）
- 手机端 `ToolCard` 显示的是真的执行过程，不是 Demo 数据

**判据**：手机上说一句"看下 2 号机的 model 目录"，卡片里出现真的 `node.exec` 与真的目录输出。

## 五、明确不做什么（防止范围失控）

- **不 fork 那三个网络层仓库**。它们是外部依赖，跟着上游走；
  我们只在 `providers.py` 里写适配器。一 fork 就要跟三家同步，是纯负债。
- **不把 Operit 的 21 个 feature 全抄**。只抄三件：Agent 任务流、工具卡片、思维链折叠。
  其余（包市场、工作流编辑器、Ubuntu 用户空间）不在移动端做。
- **不追求"完全离线可用"**。本地模型是隐私闸门和最后兜底，不是主力——
  手机算力摆在那，4B 在 8G 内存机上就是 6 tok/s 的水平，这一点不能自我欺骗。
