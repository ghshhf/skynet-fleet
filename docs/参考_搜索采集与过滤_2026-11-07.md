# 第一部分 · 怎么问：X 搜索语法

## 一句话

X 搜索**默认就按最新排序**，不需要额外设置。真正决定结果好坏的是 `min_faves:`——
不加它，前几十条全是零粉小号的垃圾。

## 运算符

| 类 | 写法 | 作用 |
|---|---|---|
| 人 | `from:someone` / `to:someone` / `@someone` / `list:ID` / `filter:verified` | 某人发的 / 回某人 / 提到某人 / 列表成员 / 只要认证号 |
| 时间 | `since:2026-11-01` / `until:2026-11-03` / `within_time:2d` / `since_id:<推文ID>` | 之后（含）/ 之前（不含）/ 最近 N 天 / 比这条新 |
| 质量 | `min_faves:50` / `min_retweets:20` / `min_replies:10` / **`-min_faves:500`** | 点赞/转发/回复下限；**取反即成上限**，用来找冷门好帖 |
| 类型 | `filter:links` / `url:github.com` / `filter:media` / `-filter:retweets` / `-filter:replies` | 带链接 / 链到指定域名 / 带图 / 去转推 / 只要原创 |

**语法硬规则**：空格 = AND · `OR` **必须大写**（小写当普通词）· 冒号后**不能有空格** ·
括号括 OR 组 `(webflow OR framer) pricing` · 日期只能 `YYYY-MM-DD`。

## 四个模板（直接复制，换 `KEYWORD`）

```
KEYWORD filter:links url:github.com min_faves:20 -filter:replies   # 1 找带仓库的高质量帖（最主力）
("looking for" OR "recommend" OR "found this") KEYWORD min_faves:10 lang:en   # 2 找别人在推荐的
from:someone min_faves:100 -filter:replies                          # 3 挖某人精华帖
KEYWORD min_faves:50 since:2026-10-26 lang:en                      # 4 近期窗口内的热帖
```

浏览器直接用：`https://x.com/search?q=<URL编码后的查询>&src=typed_query&f=live`。
`f=live` = Latest；不写就是 Top（按互动排，会漏最新）。

**实测**：`free ai api key since:2026-11-01` + Latest 能拿到 14 分钟前的推文，
但前 8 条里 6 条是 0 粉小号。⇒ **关键词越泛，越必须加 `min_faves:` 和 `filter:links`**。

# 第二部分 · 怎么筛：垃圾的形状

## 方法（可复用的那部分）

`tools/ad_harvest.py` 用 18 条**正常用户真会搜的查询**（社保/减肥/直播/贷款/比特币/安卓版本…）
撞搜索模块，保留过滤前的全部原始命中；`tools/ad_classify.py` 把 112 条命中批量喂免费 LLM
（Beam 1.0，42.5s / 10 批）做定性；域名与标题形状统计全部本地确定性计算。
**纪律：只采元数据（标题/URL/域名），不抓广告页正文、不点跳转、不登录。**

## 结论

1. **主端口是「高信誉域名寄生 SEO」**：112 条里 63 条（56%）在 github.com，
   LLM 判定的 12 条违法/垃圾**全部**是 GitHub 寄生仓库。手法是一次性小号批量建仓，
   仓库名/描述直接写导流词，借 GitHub 的搜索权重抢排名。
2. **当时的规则对这 12 条全部放行**——因为标题里**确实含查询词**，这正是 SEO 垃圾的设计目的，
   「标题与问题无字面重叠」那条规则失效。
3. 六个端口：GitHub 寄生 / 假交易所 APK / 博彩 App / 盗版影视 / 成人内容 / TG 镜像。
4. 搜索模块自身三个病：Bing RSS **串味**、DDG 限流、`Hit` **无摘要字段**（话术最密集的
   description 在引擎层就被丢了）。

## 六个端口（各留一个形状样例）

| 端口 | 样例 | 识别特征 |
|---|---|---|
| GitHub 寄生 SEO | `20261618-tech-resources-91ok3gob`、`dianyingwangzhan`、`nba` | 通用词 + 无意义随机串 / 仓库名本身就是品类词 / 名称即关键词 |
| 假交易所 APK（诈骗） | `最新 OKX APK 教程：如何安全下载 OKX 官方 APK` | 真品牌词 +「官方」+ 下载/安装/APK/教程 |
| 博彩 App | `米兰app官方入口网站-(lyiwush.com)…` | **标题嵌裸域名** + 博彩惯用名 |
| 盗版影视 | `2026免费影视在线观看网站（持续更新）` | 免费 + 在线观看 + 官网/网站入口词 |
| 成人内容 | `chenguanyou/porn_movie` | 仓库名即品类 |
| TG 镜像 | `在这里下载 Telegram 官网最新版…纸飞机…` | 黑话 + 官网 + 下载 |

## 由此固化的五条形状规则

1. **品类词 × 入口词组合**：直播/影视/观看/破解/网盘 × 官网/入口/网址/最新网站。
   正常技术页描述功能（「集成热门资源站实现离线下载」），导流页只堆入口。
2. **标题内嵌裸域名**：`(lyiwush.com)`、`-xxx.com`（知名站点白名单除外）。
3. **真品牌 +「官方下载」**：交易所品牌词 + APK/下载/安装/教程 = 诈骗前置。
4. **GitHub 仓库名即导流词**：拼音串/品类词/随机后缀 + 描述含品类词。
5. **问号堆砌**（已有规则覆盖）：96 字 6 问号抢排名。

## 已落地的加固（都已进代码，别当待办重做）

## 边界

- **未抓任何广告页正文**：品类判定只凭标题/URL/列名字面；落地页内容、跳转链、收款方式未验证（也不去验证）。
- **样本偏差**：112 条里 56% 是 GitHub，与「正常搜索的广告构成」有差；5 条生活服务查询零命中
  （引擎层就没给结果），结论按此权重读。
- **Bing RSS 串味不修 URL**（加 mkt 实测更坏），只记录：Bing 的产出必须过相关度闸门才可用。
- **站群域名**（bingquiz.com 等）未深挖，留作下一轮样本。
