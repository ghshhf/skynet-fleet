# 信息获取层（下一代进化方向）调研 — 天网要真正「看见」，先得「感知」

> 日期：2026-10-24
> 背景：天网（device-fleet）已完成「一眼/一手/一哨/一网/一幕」5 项创意能力（见 `创意能力企划_天网之眼与信号外放`）。
> 但 5 项本质都是「**已暴露信息的再组织**」：WiFi/蜂窝/BLE/局域网发现、红外码库发射、热点、宏。
> 真正的天网差距在 **信息获取（acquisition）**，不在推理（reasoning）——大模型是分析器、不是信息源。
> 本文按「感知层」分类梳理开源/逆向工具，并给出接回本编队架构的进化路线。

---

## 一、核心判断（结论前置）

1. **模型不生产信息，只消费信息。** 编队再聪明，喂不进原始信号就永远是个「局域网的旁观者」。
2. **感知层有 4 个梯度**，从「零成本」到「需硬件」，逐个把环境变成可读数据：
   - **L1 射频/空气层**：直接听懂空中的私有协议（最硬核、最像天网）
   - **L2 近场无线/网络层**：BLE/WiFi 指纹 + 流量解剖（DPI）
   - **L3 手机传感/执行层**：手机本身就是最便宜的全功能传感节点（**0 成本，本周可做**）
   - **L4 外部情报层（OSINT）**：把「世界模型」从局域网扩到互联网
3. **架构零改动即可接入**：每个新能力都封装成一个 `Capability` → 注册表派发 → `DeviceResult`，与现有 `scene.scan`/`ir.command` 同构。决策模型经 `agent_tools.TOOLS` 自动发现。
3.5 **核心 thesis（用户的洞察）**：大模型本质「困在互联网文本里」——它有海量公开知识，却对**此时此地、此人此身**一无所知。L3/L5 的意义不是再多爬点网页，而是给编队**具身化（embodiment）**：让它能看见你的房间、感知你的状态、读出你眼前的字。这才是离「天网一部分能力」最近的一步——**从互联网智能变成具身智能**。
4. **诚实原则不变**：本编队「支持就真做、不支持直说」的纪律必须延伸到感知层——**扫描/分析/逆向你拥有或授权的设备**；发射/重放/中间人涉及法规与授权边界，结果里如实标注「仅限自有设备/授权实验室」。

## 二、感知层分类 × 开源项目清单

### L1 · 射频 / 空气层（听懂私有协议）⚠️ 需外部硬件

> **手机原生干不了 L1。** 手机只有红外**发射**（无接收/学码），没有任何 SDR/Sub-GHz 射频前端。L1 必须外接硬件（Flipper Zero 或 RTL-SDR/HackRF 棒）才能做。故 L1 不是「手机进化方向」，而是「外挂节点扩展」——优先级低于 L2/L3/L4/L5，且依赖是否愿添置硬件。

| 项目 | 一句话定位 | 关键能力 | 成本/门槛 |
|---|---|---|---|
| **URH** (Universal Radio Hacker, `jopohl/urh`) | 无线协议逆向全套工作台 | 捕获 IQ→自动解调(ASK/FSK/PSK)→自定义解码(CC1101 白化)→字段推断→fuzz→仿真发射；支持 RTL-SDR/HackRF/LimeSDR/USRP；Python 可写插件 | 软件免费；需 SDR 硬件 |
| **rtl_433** | 433MHz ISM 设备开箱即解 | 天气站/TPMS/智能传感器数百种解码器；输出 MQTT；可移植到 ESP32+CC1101（家用自动化直接可用） | 免费；RTL-SDR 棒 ~¥80 |
| **rf-signal-analyzer** (`craig-rueda`) | Python 版 300–433MHz 遥控逆向工作流 | scan/capture/listen/analyze/replay 五命令；HackRF 回放 | 免费；需 RTL-SDR+HackRF |
| **Flipper Zero** (+ Momentum/Unleashed 固件) | 口袋多工具节点 | Sub-GHz(CC1101,≤50m)/125kHz RFID/13.56 NFC/红外收发(可学可发)/GPIO/iButton；**开源固件** | 硬件 ~$170 |

> 价值：把「邻居的智能灯泡在聊什么」「旧遥控的私有协议」变成可读字节。这是离「天网」最近的一层。

### L2 · 近场无线 / 网络层（指纹 + 流量解剖）

| 项目 | 一句话定位 | 关键能力 | 成本/门槛 |
|---|---|---|---|
| **bettercap** (`bettercap/bettercap`) | Go 写的一体化侦察/MITM 框架 | 模块化：WiFi/BLE/Ethernet/HID 侦察；`events.stream`→WebSocket 可推给 agent；**能在 Android 上跑** | 免费；单机/手机即可 |
| **Ubertooth One** | BLE 监听/注入 | BLE 层抓包与重放研究 | 硬件 ~$125 |
| **killerbee / Zigbee Analyzer** | Zigbee(802.15.4) 网状分析 | CC2531 抓包；MAC/Network/APS/ZCL 深解；拓扑图；PCAP→Wireshark | 免费；需 CC2531 棒 |
| **Wireshark / tshark / pyshark** | 协议解剖引擎 | 数百协议 dissector；pyshark 包 tshark，支持 WPA 解密；输出 JSON/字段表，直接喂 LLM | 免费；本机装 tshark |

> 价值：现有 `discovery.py` 只做端口扫描；pyshark 加上 **DPI（深度包检测）**，把「谁在和谁说话、什么协议、有没有明文凭据」变成结构化实体。

### L3 · 手机传感 / 执行层（0 成本，最该先做）

| 项目 | 一句话定位 | 关键能力 | 成本/门槛 |
|---|---|---|---|
| **Termux:API** (`termux-api`，~83 个 verb) | 手机原生传感/执行面 | **感知**：`location`(GPS)/`camera-photo`/`microphone-record`/`sensor`(accel/gyro/light…)/`battery-status`/`telephony-cellinfo`/`wifi-scaninfo`/`nfc`/`fingerprint`<br>**执行**：`tts-speak`/`sms-send`/`call`/`infrared-transmit`/`torch`/`vibrate`/`notification` | 免费；装 Termux+API 即可 |
| **ROS2Sense / ros2_android** | 手机当 ROS2 传感中枢 | accel/gyro/mag/GPS/cam/light/mic/IR；自带 Madgwick IMU 融合；热词检测 | 免费；概念参考「传感融合→世界模型」模式 |
| **Seven-of-Nine mobile sensors** | 17+ 传感器枚举→状态映射 | 传感器质量评分、实时流引擎、情绪/战术就绪映射 | 免费；**架构参考**：sensor→state 管线 |

> 价值：我们已有 `android_device.py` 走 adb 驱动。**termux-api 是比 adb 更原生、更全的传感面**，且天然适合封装成 `phone.sense` 一类 cap。手机就是编队里最便宜、最全能的节点。

### L4 · 外部情报层（OSINT，扩世界模型）

| 项目 | 一句话定位 | 关键能力 | 成本/门槛 |
|---|---|---|---|
| **SpiderFoot** (`smicallef/spiderfoot`) | 自动化 OSINT 框架 | 200+ 模块：IP/域名/邮箱/用户名/暗网；Web GUI | 免费(MIT) |
| **maigret / sherlock** | 用户名跨站档案 | 数千网站用户名枚举，拼出人物侧写 | 免费 |
| **OpenOSINT** | **AI agent + MCP 服务** | 包 ~20 个 OSINT 工具(holehe/Sherlock/PhoneInfoga/HIBP/Shodan)；Claude 或本地 Ollama；MIT v2.31(2026-10) | 免费；**最像我们要建的东西** |
| **Shodan / Censys** | 互联网设备搜索引擎 | 暴露设备/端口/漏洞检索 | 部分免费 |

> 价值：把「世界模型」从局域网扩到互联网。OpenOSINT 的「MCP 包 OSINT 工具」模式，正是我们 `agent_tools.TOOLS` 该借鉴的接法。

### L5 · 视觉生活流（手机摄像头 = 天网的眼睛）★ 手机原生、零成本、最高性价比

| 项目 | 一句话定位 | 关键能力 | 成本/门槛 |
|---|---|---|---|
| **Qwen3-VL-4B**（本机已有） | 手机上的视觉语言模型 | 看图说话、OCR、场景/物体/活动理解；`/sdcard/Download/本地模型` 已装机（2.5G + mmproj 454M） | **免费、已就绪** |
| **termux-camera-photo** | 手机原生拍照 | 随时抓一帧世界画面 | 免费 |
| **`screen.read`（已存在）** | 截图→VLM 分析 | 已有 VLM 管线，L5 是它在「世界摄像头」上的对应物 | 已落地 |

> **这是用户提出的关键层。** 大模型困在互联网文本里，对「此时此地此人」无知；L5 用手机摄像头 + 本机 VLM 给编队**具身视觉**——不必上云，隐私可控。
> 它能分析什么（按可信度分三档，见第五节），本质是把 `sentinel.watch` 的「只报变化」逻辑搬到**生活域**：拍照→抽取结构化事实→按时间存成 life-stream→聚合成日报/周报→基线偏离告警（"你这周外食偏多/房间 10 点后一直很暗"）。
> **隐私边界**：这是**本人自愿共享的自我数据**，与「监控他人」严格区分；结果只在本地/授权范围，遵循诚实原则。

**L5 能分析出什么（按可信度分三档，诚实标注）**

- **高可信（单帧直接可见）**：场景/地点（家/办公室/街道/咖啡馆）、在场物体（桌上有电脑、杯里有水）、活动（吃饭/工作/走路）、人数（独处/有人）、光照（暗/亮→昼夜节奏）、文字 OCR（文档/白板/屏幕/标签/药盒说明）
- **中可信（需时序聚合，跨多天）**：日常节律（你典型的一天长啥样）、基线偏离（某天异常=可能状态不对）、消费/饮食模式（外食频次、冰箱存货）、房间整洁度趋势、屏幕时间/久坐
- **低可信 / 不可靠（绝不声称）**：真实情绪与心理健康、主观感受、未出镜的信息、因果关系（"你抑郁了"这种结论不能下）。诚实标注「看不出」。

> 本质：L5 把 `sentinel.watch` 的「只报变化」逻辑搬到**生活域**——不是逐帧解读，而是建基线、报偏离、出周报。价值在**长期聚合**，不在单张照片。

## 三、接回本编队的进化路线

> 原则：每个新能力 = 一个 `Capability`（写进 `catalog.CAPABILITIES`）+ `android_phone.py` 或新 kind 的 `_do` 分支 + `agent_tools.TOOLS` 一条 + 结果走 `DeviceResult`。与现有 5 能力同构。

### 阶段 0 · 0 成本，本周可做（最高杠杆）
0. **`phone.see` — 视觉生活流（L5，最该先做）**
   - 借：`termux-camera-photo` + 本机 **Qwen3-VL-4B**（已装机）+ 复用 `screen.read` 的 VLM 管线
   - 输出：拍照 → VLM 出结构化描述 JSON（scene/objects/activity/people/light/ocr_text）→ `DeviceResult`
   - 接法：新 cap `phone.see`（无副作用，auto）；后续接 `life.log`（帧事实时序化）+ `life.digest`（日报/周报）+ `life.sentinel`（基线偏离告警）。**硬件现成、模型现成，是性价比最高的一步**
1. **`phone.sense` — 手机传感融合**
   - 借：`termux-api`（在 `android_device.py` 现有 adb 通道上加一层 termux-api 调用）
   - 输出：环境光→房间 5 级亮度/昼夜/粗略 occupancy；运动传感器→身体活动(静止/携带/手持/遮盖)；电池温度→热状态
   - 接法：新 cap，结果 `DeviceResult`，决策模型可问「现在房间亮不亮」「人在不在动」
2. **`net.dissect` — 流量解剖**
   - 借：`pyshark`/tshark（本机装 tshark）
   - 输出：捕获一段 → 提取「设备对话对 / 协议占比 / 明文凭据告警」JSON
   - 接法：`discovery.py` 已有端口扫描，加 DPI 分支；补 `Capability` + `Tool`

### 阶段 1 · 小成本硬件（便携节点化）
3. **`net.survey` — BLE/WiFi 结构化普查**
   - 借：`bettercap`（含 Android 构建）；`events.stream` 喂 WebSocket → 编队事件总线
   - 输出：BLE/WiFi 设备清单 + 实时事件流（出现/消失/信号）
4. **Flipper Zero 入编队**
   - 借：`flipperzero-firmware`（GPLv3 开源）+ Momentum
   - 定位：便携 Sub-GHz/RFID/NFC/IR 节点，走 `fleet/kinds/` 新 kind（如 `flipper_node.py`）
   - 复用现有 cap 模型：Sub-GHz 发射/学码、IR 收发、RFID/NFC 读仿

### 阶段 2 · 深度（真正的「天网之耳」）
5. **`rf.re` — 射频协议逆向**
   - 借：`URH` + `rtl_433`（ESP32+CC1101 版可常驻）
   - 输出：未知 433MHz/Sub-GHz 设备 → 解调比特流 → 字段推断 → 可重放脚本
6. **`osint.*` — 外部情报接入决策**
   - 借：`OpenOSINT` 的 MCP 包法 + `SpiderFoot`/`maigret`
   - 输出：对给定目标（用户名/域名/IP）产出结构化情报卡，进 `agent_tools.TOOLS`

**`phone.sense` + `net.dissect`**，零新硬件、零新依赖（termux-api 我们本来就在用；tshark 本机可装）。
它们把编队从「局域网拓扑观察者」升级为「**能感房间明暗、能读流量内容**」的节点——
这是距离「天网一部分能力」最近、最便宜的一步，且完全落在现有 `Capability/Registry/DeviceResult` 骨架内。

## 五、边界（诚实原则 + 授权范围）

- 本编队「支持就真做、不支持直说」的纪律延伸到感知层。
- **扫描 / 分析 / 逆向仅限你拥有或明确授权的设备与网络**；URH/bettercap/Flipper 官方文档均强调这一点。
- **发射 / 重放 / 中间人** 涉及频谱法规与授权边界：`ir.command` 已有的 `dry_run`/闸门机制应复用到 RF 层；结果 `note` 必须标注「仅限自有设备/授权实验室」。
- 不协助对任何第三方系统未授权的访问、嗅探或控制。

- 全链 `catalog.build()` 通过，新设备 `osint`/`lan_scanner`/`android_phone` 均注册；**11 个新能力全部进注册表（总能力 125 项）**。

### 活体测试待用户在真机/真 PC 跑（沙箱到不了手机 LAN、无 Npcap）

- **L3/L5**：手机需装 **Termux:API** 插件（termux-camera-photo / termux-sensor / termux-battery-status），且本机 llama-server 带 **Qwen3-VL + mmproj** 在跑（`PHONE_LLM_BASE` 指向手机 IP）。`registry.call("phone.see", ...)` 即派发。
- **L2 net.dissect**：Windows 需 **Npcap**（装 Wireshark 时勾选），Linux 需 root；无则诚实报「需 Npcap/root」。
- **L2 net.survey**：PC 需 bettercap 二进制 + monitor 模式网卡；否则诚实报 unavailable。
- **L4 osint.shodan**：设 `SHODAN_KEY`（仅查自有资产）；无 key 如实说不可用。

### 诚实边界（写在每台能力 note 里）

- L3/L5 是「本人自愿共享的自我数据」，不上云、不出本地圈；模型只描述画面、不推断主观情绪/心理。
- L4 只查你拥有/授权的资产；crt/rdap 为被动公开源；Shodan 需 key 且限自查。
- 本层只做「读/拍/抓」，绝不发射/重放/中间人——那是 `ir.command`/`phone.hotspot` 那档动手级（过闸门 + 受法规约束）。

## §七 L6 · 远程可触达（反向隧道）—— 打破「方寸之限」

> 用户定调：手机「能联网才能和你说话」；过去一切调用都被限定在「手机与电脑同 WiFi」的方寸之间。L6 就是拆掉这堵墙：**电脑在家常开，手机不管在哪，都能被远程操控/对话。**

**核心设计（2026-10-24 落地）**：
- **反向连接**：手机几乎永远在 NAT/蜂窝 CGNAT 后，外面连不进来，但**出站永远通**。所以手机主动拨家里（`PhoneClient`），隧道由内向外建——不依赖家里有没有公网 IP。
- **隧道只做传输，手机本地执行**：手机收到 CALL，在**自己的本地 registry** 跑能力（`android_phone` / `acquire` / `creative` 全复用），只回传 `DeviceResult`。→ 已建的 L2–L5、红外、场景宏**一个不用重写**就远程可用。
- **鉴权复用 `device_auth` 配对**（6 位码 → sha256 secret，电脑重启不变）。只认自己配对的设备；错密钥/未知 id 一律 403，不区分（防枚举）。
- **入口可插拔**：relay 只绑 host:port（默认 127.0.0.1）。cloudflared（TLS 终止，推荐，数据不出户）/ Tailscale（wireguard 全加密，最省心）/ frp / 端口转发都能把那个端口暴露出去。**relay 本身明文跑内层，加密交给入口层**——绝不明文 adb/凭据裸奔公网（cleanyourtv/REMOTE.md 血训：bot 全网扫开放 5555）。
- **手机拨入即入编队**：`sync_remote_devices` 自动增删 `remote_phone` 设备，`registry.call("phone.see", device="phone:<id>")` 与本地调用同构（仅 via 不同）。

**新增文件**：`fleet/remote_link.py`（RelayServer + PhoneClient，复用 `common.py` 帧协议）、`fleet/kinds/remote_phone.py`（RemotePhone/RelayNode 设备）、`phone_reverse_client.py`（Termux 常驻）、`relay_ingress.py`（cloudflared 启动器 + Tailscale/frp 说明）、`skynet_app_bridge.py`（1.0.20 App 远程模式集成点）。`catalog.build` 加 `FLEET_RELAY_ENABLED=1` 开关起中继；决策面加 `relay.status`。

**验证**：`python -m fleet.remote_link` 自测 7/7（含认证拒绝、未知设备、能力透传）；端到端 5/5（success 往返 / unsupported / denied+side_effect 透传 / 编队同步 / relay.status）。沙箱已跑通；**活体需家里 PC 起中继 + 手机 Termux 跑反连 client**（沙箱到不了手机 LAN）。

**两条腿（用户要求）**：手机端先做 Termux 脚本打通，SkyNet App（1.0.20）在「远程模式」开关上扩（`skynet_app_bridge.py`），本地能力执行逻辑不改，只把「谁来下令」从本机电脑换成家里中继转来的 CALL。

**诚实边界**：远程控制的是**你自己配对过的手机**；入口 token + 设备凭据双鉴权；只做「手机出站反连」，relay 不反向连任何东西。加密强度取决于入口（cloudflared/Tailscale），别用裸端口转发。

## §七 逆向拆解层（L7）：不拆就没有的数据

用户原话：「为什么让你找逆向呢？因为很多东西。你必须拆解啊，否则根本得不到一些相关数据。」——L2-L6 拿的都是**已暴露**的数据（扫到的 SSID、拍到的画面、crt.sh 吐的子域）；L7 拆的是**不拆就没有**的数据：脉冲里编码的协议、广播字节里的设备自称、固件里硬编码的地址。

**两段式（与 webtool.py「服务端先搜后排」同一条纪律）**：
1. **确定性拆解**（`fleet/reverse.py`，纯计算、答案唯一、不许模型编）：
   - `decode_pulses` 脉冲时序→协议判定：NEC / NEC-ext / Samsung / SIRC / RC5-like / PWM / 未知。判据是**反码结构**不是 lead 时长（lead 因遥控器而异，反码不会）；与 `infrared.py` 四个编码器编→拆往返一致；confidence=high 仅当反码校验通过或时序完全吻合规范。
   - `parse_flipper_ir` / `parse_flipper_sub`：真实捕获格式（Flipper .ir parsed/raw、.sub RAW_Data/data 两种写法）。
   - `parse_ble_adv`：BLE 广播原文 hex→AD 结构遍历（flags/名称/16-32-128bit UUID/服务数据/厂商数据），厂商 ID 查蓝牙 SIG 常见表，iBeacon 拆 UUID/major/minor/measured_power。
   - `binary_strings` + `binary_report`：固件/APK/可执行→strings 分类（URL/IP/邮箱/64位hex/版本横幅/路径）+ ELF/PE/zip/dex 魔数。只读、只在本机、原文不外传。
   - `codebook_crossref`：拆出的 (proto, addr, cmd) 对照 `ir_codes/` 码库——命中即报「小米/电视/power」；新码给 proposal 片段，**人工确认后才入库**（编错的码比没有码更糟）。
2. **LLM 假设层**（`fleet/re_llm.py`）：读 `~/.workbuddy/models.json`（网关池同步的选择器文件，★ 最快在前，「待刷新/已下线/锁区」跳过）按序 failover；没有则回退 `llm.complete()`。模型只读事实 JSON 输出人话假设，系统提示强制区分「事实/推断」，推断必须标『推断』。无额度时返回带「会自己恢复」的降级说明，不假装有假设。

**接入**：`fleet/kinds/reverse.py`（kind=re，4 能力）+ catalog 注册 + agent_tools 4 工具（工具枚举 41→45，总能力 126→130）。每个能力 note 写明只读边界。

**验证**：`fleet.reverse` 离线自测 21/21（四种协议往返 + 码库命中/新码 + Flipper 两种格式 + BLE/iBeacon + strings 六类 + ELF 魔数 + 垃圾输入诚实报错）；`fleet.re_llm` 6/6（假端点 + <think> 剥离 + apiKey/model 透传）；进门禁 `run_selftests.py fleet_re` 4/4。活体（沙箱真跑）：`re.ir` 拆 NEC 4/8 → 码库命中 generic+小米/电视/power → Beam 1.0 出假设「可能是小米电视电源键（brand 未唯一）」；`re.ble` 拆出 Apple iBeacon；`re.binary` 对 webtool.py 抽 717 条 strings（3 URL/8 版本/1 路径）且 LLM 诚实识别「Python 文本脚本（非二进制）」；`re.ask` 答 NEC 反码作用并自带事实/推断标注。

**诚实边界**：只拆**你自己捕获/拥有**的数据；re.* 全部只读，不发任何报文、不发射、不重放（那是 ir.command/phone.hotspot 那档动手级）；LLM 输出一律标「假设/模型回答」，可能错，关键结论要交叉验证。

## §八 自建逆向引擎（搜索×逆向 正式合流，2026-10-24 P0 第一枪）

用户原话：「过去我的思想就是搜索叠加逆向。再叠加通用规则……要不然就只能花钱去买那些搜索 API。相当于自己造，丰衣足食。」

**判断依据（同日实测）**：公共引擎池已封顶——github 278/293（95%）、ddg 237/330（72%，中文查询说限流就归零）、bing 中文桶 76/460（17%，RSS 端投喂串味缓存全靠相关度闸门硬扛）、searx 0/0。加公共引擎是陪跑，胜场只能建在付费 API 结构上给不了的东西上。

**落地**：`fleet/re_site.py`（约 620 行）——「站点 → 私有接口 → pseudo-engine」三件套：
- `probe(url)` 端点发现：抓页面 → 提 JS bundle → 四类模式认 API 端点（绝对接口/取数调用/相对接口/JSONP），每条带证据行可回原文件核对。**这是通用工具，任何新站点第一跳都用它。**
- `quote(query)` 三个适配器（全部只读公开接口，注释里写清「谁为了做生意不得不暴露」）：
  - 腾讯 `qt.gtimg.cn`（A股/港股富字段：市值/市盈率/振幅；GBK；无 Referer 校验——本次限流期的顶梁柱）
  - 东财 `push2`（结构化 JSON 行情；Referer 认站内）
  - 东财 `f10/lsjz`（场外基金净值）+ `searchapi/suggest`（名称→代码，返回的 QuoteID 正好是 push2 的 secid，一个接口喂两只适配器）
- `hit_from()/as_hits()`：转成与 skynet Hit 同形状的 `(url, title, desc)`，`score=999` 恒压公网泛结果。

**接入**：`fleet/kinds/internet.py` 新增能力 `web.quote`（总能力 121 项）；`web.search` 聚合层做前置注入——行情查询先把精确答案顶到最前，公网引擎照样跑（一个答「现在多少钱」，一个答「网上怎么说」）。适配器异常一律降级不炸主搜索。进门禁 `fleet_re_site` 21/21 离线断言（真机采集的 GBK 负载/JSON 当向量，--live 才联网，符合「门禁不许依赖外网」纪律）。

**实测（2026-10-24 盘中）**：`平安银行股价` → 平安银行（000001）11.20 -0.88%·深A，摘要带开高低量额换手；`腾讯控股股价` → suggest→腾讯兜底 386.00 +0.94%；`基金 000001` → 华夏成长混合 净值 1.046。push2 连续请求约 6 次后被限流，腾讯无缝兜底——**多源互为备胎是这个架构的第一块回报**。

**踩到并修掉的坑**：
1. **解码顺序会静默出错**：gb18030 几乎不抛异常，UTF-8 中文被它解成错字（「华夏成长混合」→「鍗庡鎴愰暱娣峰悎」）。修法：Content-Type 声明 > utf-8 严格 > gb18030。
2. 港股 secid 是 `116.` 前缀、腾讯符号要 5 位补零——猜错就是查无此码。
3. push2 限流是暂时状态（铁律）：标「待刷新」不删适配器。
