## 0. 结论前置

| 主人的问题 | 答案 |
|---|---|
| 手机需要下载什么？ | 只有 **SD1.5 量化模型 q8_0（约 1.1GB）**，由 APP 内首次使用时**卡确认闸后下载**；sd.cpp 编成 `.so` **打进 APK**（不单独下载）；Vulkan 驱动系统自带 |
| 手机手动选出图 + 投递 PC？ | APP 内已有出图界面（`ImageActivity`）：输 prompt/尺寸/步数 → 点生成 → **手机本地出图** → 经 N+1b 配对通道（TLS1.3+会话令牌，已验收 `c576f1b`/`cf1f474`）**推送投递 PC** → PC 端登记回取展示 |
| 融进自己软件，不借 Termux？ | **v1 即 JNI 直集成**（不再绕道 Termux RUN_COMMAND）：`sd_jni.cpp` 薄封装 + CMake 静态链 sd.cpp/ggml/ggml-vulkan 成**单 `.so`**，完全复刻本仓库已验证的 `whisper_jni.cpp` 模式 |

**为什么 v1 就上 JNI 而不是先子进程**：① whisper 的 JNI 链路本仓库已跑通（模式零风险迁移）；② 主人说未来命令行工具「多到爆」，子进程方案每个工具都要管二进制提取/执行权限/ABI，JNI 是统一形态；③ llmedge 用同一路线把 llama.cpp+sd.cpp+whisper.cpp 全集成，可抄作业。

## 1. 开源调研实证（扒来的东西，不猜）

| 来源 | 扒到的关键模式 | 用在哪 |
|---|---|---|
| **llmedge**（CCE-Li, Apache-2.0） | `add_subdirectory()` 引入 stable-diffusion.cpp 源码树 → 编 `stable-diffusion` 静态库 → JNI 层链接；`-fvisibility=hidden -ffunction-sections -fdata-sections -Wl,--gc-sections -flto`；统一链 `android log`；Vulkan 条件链接 | sd 的 CMake 结构与 JNI 写法直接参考 |
| **Termux RunCommandService** | 安全网关：`allow-external-apps` 检查 + 可执行路径/工作目录权限验证 → 转发执行 → 结果回传 | 不整体借，但其「外部调用必须过显式开关 + 路径校验」的纪律已体现在 N+1b 配对（显式开配对 + 白名单） |
| **本仓库 `jni/whisper_jni.cpp`** | 薄 JNI 封装 + 单 `.so`（免 `loadLibrary` 顺序坑）+ NDK 交叉编译 + strip 13.9MB→1.6MB | **主模板**，sd 照此办理 |

**许可纪律**：stable-diffusion.cpp 是 MIT，按主人规则「开源了就能搬」——构建时 clone 到 `/d/tmp/stable-diffusion.cpp`（与 whisper 现行做法一致，仓库不吞 52MB 源码），**不 vendoring 进 git**，保持单真相源在上游。

## 2. 架构（三层，路已验收，只补「货」）

```
┌──────────────── 手机（总控）────────────────┐
│ ImageActivity（已有，改后端）                 │
│   ↓ JNI                                     │
│ sd_jni.cpp → libfleet_sd.so                  │  ← 本计划新建（第 1 步）
│   （sd.cpp + ggml + ggml-vulkan 静态链一起）   │
│   ↓ 模型                                     │
│ ~/files/sd/q8_0/...gguf（APP 内下载，确认闸）   │  ← 第 3 步
└──────────────┬───────────────────────────────┘
               │ 出图完成，手动点「投递」
               ▼
┌──────────────── PC（被控端）─────────────────┐
│ N+1b TLS 监听器（已有 0.0.0.0:24561）          │
│   POST /api/remote/push（新，白名单+登记制）    │  ← 第 4 步
│   → fleet-results/<result_id>.png 回取展示      │
└──────────────────────────────────────────────┘
```

**不新建协议、不新开监听面**：投递走已验收的配对通道，只在受控端白名单里加一个 `push` 能力（登记制回取，和现有 screenshot 同一纪律）。

## 3. 分期（一步一闸，过闸再走）

### 第 1 步 · 构建链（真编译即门禁）
- `jni/sd_jni.cpp`：照 `whisper_jni.cpp` 写薄封装——`init(model_path, threads, vae_tiling)` / `txt2img(prompt, neg, w, h, steps, seed, cfg)` → 回 PNG 字节或错误字符串；**每一条错误路径都回可读原因，不静默**（llmedge 同款纪律）
- `jni/CMakeLists.txt` 加 `fleet_sd` 目标：`SD_VULKAN=ON`（不开就是 CPU 慢到没意义，宁可不编）；链接 `vulkan`、`android`、`log`
- `jni/build-sd.sh`：clone sd.cpp（`--recurse-submodules` 拿 ggml）→ NDK 27 + API 26 + arm64-v8a 交叉编译 → strip。产物 `libfleet_sd.so` 进 APK `lib/arm64-v8a/`
- **验收**：`.so` 实编出来（`nm -D` 查到全部 `Java_com_...` 导出符号）；估编译 5–15 分钟、估体积 15–40MB（以 `wc -c` 实测为准，写进验收）

### 第 2 步 · APP 出图改走原生
- `SdBridge.java`：`loadLibrary("fleet_sd")` + native 方法声明
- `ImageActivity.java`：Termux RUN_COMMAND 整段**删除**（不保留兜底，单真相源），改调 `SdBridge`；进度用简单回调轮询；失败文案直显 JNI 回的原因
- 删除 `termux/fleet-img.sh`、`setup-termux-img.sh` 及 t20 里对应的 RUN_COMMAND 契约测试（门禁随之瘦身，不留死代码）

### 第 3 步 · 模型管理（下载什么在这里答）
- `ModelManager.java`：启动检查模型在不在；不在则弹确认闸（明示 **1.1GB**、用途、可取消）→ 下载到 APP 私有目录 → 校验字节数；损坏/缺失时给出**精确原因 + 重试入口**，不静默失败
- 默认 SD1.5 **q8_0**（约 1.1GB，Mobile 端画质/速度平衡）；SDXL/turbo 列为以后，v1 不做

### 第 4 步 · 远程投递（手机 → PC）
- PC 侧（`fleet/gui/server.py`）：受控端白名单加 `POST /api/remote/push`——会话令牌鉴权、**只收 image/png、单包 ≤20MB、登记制**（落盘 `fleet-results/<result_id>.png` + journal 审计），不给任意路径
- GUI：结果列表（缩略图 + 时间 + 来自哪台手机）+ 打开/保存
- 手机侧：出图完成后「投递到 PC」按钮 → 持会话令牌 POST
- **验收**：t19 活线家族加用例——无令牌 401、超限 413、非 PNG 拒、登记后可回取、令牌不进 journal body

### 第 5 步 · 门禁 t21 + 全量回归
- 静态扫：CMake 里 `SD_VULKAN`/`GGML_VULKAN` 确实为 ON；JNI 无空 catch、错误全回字符串；无写死模型路径；manifest 无新增危险权限
- 行为：`nm -D libfleet_sd.so` 符号完整；APK 里 `.so` 就位
- t20 瘦身后全量回归必须全绿

### 第 6 步 · 真机实测（收尾闸）
- 装 APK → 首次确认闸下模型（1.1GB）→ 出一张 512 图 → 点投递 → PC 收到展示
- 记录：**sd 日志里的 Vulkan 设备名**（没有就明说在 CPU 上跑，不假装）、单张耗时、投递耗时——写进 `docs/手机命令行集成_验收_2026-10-23.md`
