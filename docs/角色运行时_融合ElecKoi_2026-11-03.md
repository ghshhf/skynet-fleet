# 角色运行时：融合 ElecKoi（电子爱）_2026-11-03

> 来源项目：<https://github.com/eleckoi/ElecKoi>（AGPL-3.0-or-later，89★，Electron + React + TS）
> 融合方式：**读它的语义与算法，用天网口径重写成零依赖 Python**，不搬 TS 代码、不引 JS 运行时。
> 落点：4 个纯算法模块 + 1 台设备 + 13 条能力 + 1 条门禁。

## 一、为什么融它

盘点天网的角色能力时，缺口很整齐：**能读卡，不能把卡跑起来**。

| 卡里写着 | 天网原来 | 后果 |
|---|---|---|
| `[InitVar]` 初始好感/背包/时间线 | 当普通世界书条目，读了就丢 | 每轮靠模型猜「现在好感多少」，越聊越飘 |
| 世界书 `scan_depth` / `selectiveLogic` | 只做「命中就全塞」 | 十几条设定一起注入，把最近对话挤掉；NOT_ANY 型排除条目被演反 |
| `extensions.regex_scripts` | 完全不认 | 正文带着 `*动作*`、`[状态:…]` 原始标记进模型 |
| `{{char}}` / `{{user}}` | 只有 `mes_example` 做了裸 `str.replace` | 中文变成「她 说」，多一个空格模型就跟着断句；description / system_prompt 里的占位符原样喂给模型 |
| 变量宏 `{{get_message_variable::…}}` | 不认 | 模型照着念「大括号 get_message_variable」 |

ElecKoi 把这五件事都解了，而且解法是**可移植的算法**，不是靠前端框架兜的。

## 二、融了什么（五层）

### 1. 宏引擎 `persona_macro.py`

- `{{char}}` / `{{user}}` 按 **CJK 边界**修剪：替换值是中文时吃掉相邻水平空白（「{{char}} 说」→「她说」），英文保持原空格。
- 变量宏：`{{get_message_variable::stat_data.好感}}`、`{{format_message_variable::stat_data}}`（后者输出 YAML 风格块，比 JSON 省 token、模型更好读）。
- ST 命名空间：`{{getvar::}}` / `{{setvar::}}` / `{{addvar::}}` / `{{incvar::}}`，写操作返回变量表、不产生副作用。
- 显示标记清理：`<FINAL>`、`</FINAL>`、`<StatusPlaceHolderImpl/>`。
- **不执行 EJS/JS**；`looks_like_ejs()` 供上层降级判断。

### 2. 变量状态机 `persona_vars.py`

- 初始化三层顺序：世界书 `[InitVar]` → 开场白 `<initvar>` → 开场白 `<json_patch>`。
- 路径寻址支持点号、数组下标、JSON Pointer（`stat_data.背包[0].名字` / `/stat_data/好感`）。
- 补丁：`replace / add / remove / increment / append / merge`，**事务语义**——任一失败整体回滚，不留半截状态。
- 快照与历史：每次改动记 before/after，可按消息存快照并回到任意一张。
- 宽松 JSON：卡作者手写的注释、尾逗号都能读。

### 3. 世界书引擎 `persona_book.py`

- `scan_depth` **四级回退**：`entry.extensions.scan_depth` → `entry.scanDepth` → `book.scan_depth` → 默认 2，最小 1。语义是「只看最近 N 条」，不是整段对话匹配。
- `selectiveLogic` 四模式全实现：AND_ANY / NOT_ALL / NOT_ANY / AND_ALL。
- `match_whole_words` 整词匹配（`art` 不命中 `partial`）。
- `probability` + `group`（同组只留一条）。
- **token 预算裁剪**：常驻先占位，其余按 `insertion_order` 填；丢掉的条目在 `dropped` 里写明原因（超预算 / 概率没过 / 同组被顶）。

### 4. 正则层 `persona_regex.py`

- 认 ST `extensions.regex_scripts`，`placement` 位掩码（用户输入 / AI 输出 / 世界书 / 推理）。
- `$1..$9` 与 `{{match}}` 展开（`$n` 先翻成 `\g<n>`，Python 的 expand 不认美元符）。
- `markdownOnly` / `promptOnly` 两档分开跑。
- replace 里含 `<% %>` 的规则**显式跳过并报告**，不静默半执行。

### 5. 设备与能力 `fleet/kinds/persona_device.py`

`kind=persona`，13 条能力：

| 能力 | 干什么 | 副作用 |
|---|---|---|
| `persona.cards` | 列卡库（同 id 的 .md/.json 归并，坏卡单列） | 只读 |
| `persona.card` | 卡档案：字段字数 / 世界书 / 正则 / 初始状态键 | 只读 |
| `persona.lint` | 体检：空条目 / 死键 / 短关键词 / 坏正则 / 重复键 | 只读 |
| `persona.system` | **主菜**：人设 + 命中设定 + 世界状态 + 宏渲染，输出这一轮的 system prompt | 只读 |
| `persona.state` | 看状态（给 path 取单值） | 只读 |
| `persona.patch` | 改状态（事务，失败一点不动） | 写 `var/` |
| `persona.rollback` | 按 note 回退上一次改动 | 写 `var/` |
| `persona.snapshot` | save / list / restore 快照 | 写 `var/` |
| `persona.regex` | 跑正则（提示词档 / 显示档） | 只读 |
| `persona.tools` | 创作动作清单（ElecKoi 创作矩阵的中文对照，17 项） | 只读 |
| `persona.lore` | **分层设定库**：目录 / 搜索 / 读单条——角色自己查，不等关键词命中 | 只读 |
| `persona.export` | 卡 + 状态 + 世界书 + 正则 → 作品包 | 只读（只打包） |
| `persona.import` | 读作品包并校验 | 只读（不落盘） |

**分工边界**：`card.*` 是「找卡 / 下卡 / 入库」（改 `cards/`，过审批闸门）；`persona.*` 是「把卡跑起来」（只写 `var/persona_states/`，可重建的运行态，不过闸门）。

## 三、没融什么（明确不做的）

| ElecKoi 有 | 天网为什么不做 |
|---|---|
| EJS 模板 / `registerMvuSchema` 的 Zod 求值 | 要跑 JS。天网是 Python 侧，为一条规则引 Node 运行时不合算。遇到显式标记「不支持」 |
| 角色前端沙箱（HTML/CSS/JS 组件） | 天网有 `render.*` 出成品 HTML，不需要一个常驻前端运行时 |
| 创作工作室 UI | 天网是总线，UI 由终端/她那一层决定 |
| MVU 远程加载（jsdelivr 上的引擎包） | 天网能离线跑，不引外部 CDN 依赖 |

## 四、怎么用

```python
# 起局：卡里的初始状态自动落地
reg.call("persona.state", args={"card": "ansying"})

# 每轮：拿到这一轮的 system prompt（世界书已按 scan_depth 选好、宏已渲染）
r = reg.call("persona.system", args={
    "card": "ansying",
    "messages": ["今天下雨了", "你还记得那把钥匙吗"],
    "budget": 1200,
})
prompt = r.data["system"]

# 模型回复后改状态：要么全成，要么一点不动
reg.call("persona.patch", args={"card": "ansying", "ops": [
    {"op": "increment", "path": "stat_data.好感", "value": 3},
    {"op": "append", "path": "stat_data.背包", "value": "旧车票"},
], "note": "雨后那段对话"})

# 演崩了：退回上一次
reg.call("persona.rollback", args={"card": "ansying", "note": "雨后那段对话"})

# 交付：卡 + 这一局的状态打成作品包
pkg = reg.call("persona.export", args={"card": "ansying"}).data["json"]
```

## 五、门禁守什么

`evals/t73_persona_bus.py`（88 条断言，全离线）：

1. 13 条能力在总表、设备在册、参数归一成元组、副作用标注正确
2. 宏：中文边界 / 英文不破空格 / 变量寻址 / 显示标记清理 / setvar 写回
3. 世界书：constant 恒在 / scan_depth 只看最近 N 条 / NOT_ANY 与 AND_ALL 分得开 / 整词不误中 / 超预算被丢且说得出原因
4. 状态：initvar 覆盖 InitVar 的顺序对 / 坏补丁一点不改 / 快照能回
5. 正则：`$1` 与 `{{match}}` 展开 / markdownOnly 不进提示词 / EJS 显式跳过
6. 设备：空卡库不崩 / 坏卡计入 broken / 找不到的卡结构化回答
7. 设定库分层：目录带 token 估算 / 搜索不给全文 / 读单条 / 坏 action 被拒
8. 作品包：导得出 / 读得回 / 坏包不认
