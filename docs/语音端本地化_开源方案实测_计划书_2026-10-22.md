# 语音端本地化_开源方案实测_计划书_2026-10-22

> 起因：主人明确「语音走本地/系统，不要每次云端合成；云端只留给大模型」。
> 本文件只写**跑出来的数**。估的标「估」。没测的一律不写成结论。

## 一、结论先行

| 判断 | 依据 |
|---|---|
| **语音本地化完全可行，而且比现在的云端 edge 更快** | Piper huayan 热态 RTF **0.09**，41 字长句 **675ms**；edge 首包就要 0.9s |
| **「系统语音」这条路不通** | Windows 只有一个中文系统音色 Huihui（2013 年代），机感重；OneCore 的 Kangkang/Yaoyao SAPI 调不到 |
| **`sherpa-onnx` 是唯一合适的运行时** | 单个 wheel 同时给 CPU 推理 + 中文模型 + Android 支持，不引入 torch，不碰北极星链路 |
| **音质最好的不是最快的，要分两条用** | MeloTTS 44.1kHz 最好但 RTF 0.75；huayan 22.05kHz 但 RTF 0.09 |
| **aishell3 不能要** | 采样率只有 **8kHz**（4kHz 以上全无），且 RTF ≈ 1.0 |

## 二、系统语音实测（先排除这条路）

```
SAPI5（普通 TTS）：
  Microsoft Huihui Desktop - Chinese (Simplified)      ← 唯一中文
  Microsoft Zira Desktop - English (US)
OneCore（现代语音）：
  Microsoft Huihui / Kangkang / Yaoyao (全部 zh-CN)
```

- 实跑 `SAPI.SpVoice` 只有 **Huihui** 一个中文可用，Kangkang/Yaoyao 属 OneCore，SAPI 枚举不到。
- Huihui 输出 **22050Hz / 单声道 / 16bit**，同一句话念 **7.74s**（Piper 同句 5.98s）。
- 这是 2013 年那代拼接式语音，正是「机器味」的来源。
- Windows 11 有「自然语音」包（ONNX，质量接近 edge），但**本机一个都没装**：
  - build 26200，`Get-WinUserLanguageList` 里 Speech 字段为空
  - `C:\Windows\System32\Speech_OneCore\Engines\TTS` 无 `.onnx`
  - 且它走 WinRT `Windows.Media.SpeechSynthesis`，Python 侧需额外桥接，不如直接用 sherpa

## 四、需要主人拍板的唯一一件事

**Piper huayan 的训练数据集许可标注为 Unknown**（模型卡原文：`License: Unknown`，数据来自 `PlayVoice/HuaYan_TTS`）。
模型代码本身是 MIT，但权重来源不明 ⇒ **自用无风险，对外分发/商用有风险**。

三条路，我按「快 + 干净」排序：

| 选项 | 速度 | 音质 | 许可 | 代价 |
|---|---|---|---|---|
| **A. huayan 主力 + Melo 可选**（推荐） | 0.09 | 中上 | 数据集存疑 | 什么都不用等，今天就能接 |
| **B. 只用 MeloTTS** | 0.75 | 最好 | MIT 干净 | 每句话要等 1.8~5.2s，对话会顿 |
| ~~C. 等 Kokoro~~ | — | — | — | **已测，排除**：语速只有正常 0.42 倍 |

> **建议 A**。理由——自用为主、不开源分发；真到要商用那天，把模型文件换成 MeloTTS 即可，
> 接入层是按 `sherpa-onnx` 抽象写的，换模型只改一个路径，不改代码。
>
> 若你对 Unknown 这个标注不接受，那就选 B，代价是对话会明显变顿——
> 这两者只能二选一，没有「又快又许可完全干净」的现成中文模型（这是本次实测的硬结论）。

## 五、接入方案（改哪里、怎么改）

### 5.1 PC 端（`voice.py`）

```
现在：say() → kokoro(本地) → edge(云端) → none
改成：say() → sherpa(本地主力) → kokoro(本地备选) → edge(云端兜底) → SAPI(最后)
```

| # | 文件 | 改动 | 为什么 |
|---|---|---|---|
| V1 | `voice.py` | 新增 `_say_sherpa()`，按 `VOICE_PROFILES` 的 `sherpa_voice` / `rate` 出音 | 本地优先，断网也能说 |
| V2 | `voice.py` | `say()` 顺序改成 sherpa 最先 | 现在的顺序是 kokoro 先，但 kokoro 没装，实际一直走 edge |
| V3 | `voice.py` | 新增 `_sherpa_engine()` **进程内缓存**，只加载一次 | 加载 2.7s，每句都加载等于每句卡 2.7s |
| V4 | `voice.py` | `caps()` 增加 sherpa 探测与模型路径回显 | 现在体检只报 edge/kokoro，看不到本地能力 |
| V5 | `voice.py` | 新增 `_say_sapi()` 作为最后兜底 | 模型文件丢了也不至于哑 |
| V6 | `requirements.txt` | 加 `sherpa-onnx==1.13.8` | 钉版本，和冻扁包一致 |
| V7 | `tools/build_gui.py` | `--collect-all sherpa_onnx` + 模型不走打包（走外置目录） | 模型 64MB 不进 exe，放 `%LOCALAPPDATA%/fleet/tts/` |
| V8 | `VOICE_PROFILES` | 每个角色加 `sherpa` 字段 + `speed` | Piper 只有 1 个音色，靠 speed/pitch 区分角色有限，需如实说明 |

**必须如实说明的限制**：Piper huayan 只有 **1 个音色**。现在 `VOICE_PROFILES` 里 8 个角色
（鲸鱼娘/北极星/天枢/…）在本地模式下会**听起来是同一个人**，只能靠语速区分。
要保留角色差异，只有两条路：① 保留 edge 云端做角色音色（违反本地化要求）；② 走 MeloTTS/其他多音色模型（慢）。

### 5.2 手机端

| 选项 | 依赖 | 延迟 | 音色 | 结论 |
|---|---|---|---|---|
| **Android 系统 TextToSpeech** | 零 | 即时 | 跟随系统（小米自带引擎） | ✅ 首选，先做这个 |

## 八、不做的事（避免范围膨胀）

- 不装 CosyVoice2 / IndexTTS2 / Qwen3-TTS：4.6~5.6GB，本机无独显，且 CosyVoice 会把 `transformers` 钉回 4.51.3，威胁北极星链路
- 不追「情绪化 TTS」：edge_tts 不开放 style；带 style 的只有付费云 API，与「语音不走云端」冲突
  ⇒ 情绪只能靠**文本层**（提示词写语气词/停顿）和**语速**，不假装能做到
- 不动 `web.py` 那条浏览器线

## 九、更正与增补（2026-10-22 13:40，实测后续）

### 9.1 更正：上面「没有又快又许可干净的中文模型」这句话不准确

查了 sherpa-onnx 官方模型清单里逐包的 upstream / license 说明后，情况是：

| 模型 | 采样率 | 实测 RTF | 许可（查证结果） | 能不能对外发布 |
|---|---|---|---|---|
| `vits-piper-zh_CN-huayan-medium` | 22.05 kHz | **0.09**（旧测） | **未声明**（上游 `License: Unknown`，且微调自非商用音色） | ❌ 不建议 |
| `matcha-icefall-zh-baker` | 22.05 kHz | 未测 | 训练集 Databaker **非商用许可**，模型本身未声明 | ❌ 不可商用 |
| `vits-icefall-zh-aishell3` | **8 kHz** | **0.067（33字）/ 0.144（3字）** | **Apache-2.0，Open** | ✅ 可以 |
| `vits-zh-aishell3`（旧包） | 8 kHz | ≈1.0（旧测） | Apache-2.0 | ✅ 但太慢 |

**新结论**：`vits-icefall-zh-aishell3` 是唯一「运行时 Apache-2.0 + 模型 Apache-2.0 + 能实时」的中文组合，
代价是 **8 kHz 采样率**——4 kHz 以上没有能量，听感发闷。旧测的 `vits-zh-aishell3` 慢是因为用了非 icefall 的导出，
同一个数据集换了导出版本后 RTF 从 ≈1.0 降到 0.067，这条要记下来：**同一个数据集的不同导出，速度可以是十倍差**。

实测命令与数据（可复现）：
```
模型 D:/tmp/tts/vits-icefall-zh-aishell3/model.onnx  30MB  174 个音色
加载 3.02s，采样率 8000
短句 3 字：137ms / 音频 0.95s / RTF 0.144
长句 33 字：522ms / 音频 7.85s / RTF 0.067
sid 0/40/90/173 都能出音（174 个音色可换人设）
```

### 9.2 增补：手机端已经改成本地系统语音（已落地）

之前手机是「让电脑合成一遍 → 下载音频 → 播放」，每句话都过一次网络，正是主人说的「不用每次都合成」要改的。

已改为：`Speaker.java` 用 `android.speech.tts.TextToSpeech` 走**手机本地引擎**，几毫秒起播、断网也能念。
起不来时不静默降级：字幕上写清原因（缺中文离线包 / 引擎不支持中文 / 引擎没起来），再走电脑合成兜底。

> 为什么系统语音能做默认：ROM 自带引擎的中文音色采样率通常 16~24 kHz，比 aishell3 的 8 kHz 好听，
> 而且零下载、零流量。它不是「开源的」，但它也不需要我们分发任何模型——这是「用系统能力」而不是「搬模型」。

### 9.3 最终三条路的分工（不再纠结）

| 场景 | 用什么 | 理由 |
|---|---|---|
| 手机日常对话（默认） | **系统 TTS** | 离线、即时、音色不差、零成本 |
| PC 端 / 想要好音色 | `piper huayan` | 22 kHz、RTF 0.09；**自用可以，对外发布前须换** |
| 要能发布 / 要合规 | `vits-icefall-zh-aishell3` | 双 Apache-2.0；接受 8 kHz 发闷 |
