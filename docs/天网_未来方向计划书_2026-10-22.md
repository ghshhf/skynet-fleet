## 一、结论前置（连续主线，语音后置）

**一句话**：天网的下一阶段是一条**连续演进线**，重心三个：

## 四、各环节细化

### 第 N 环：桌面端原点收口（必须先好）

**4.1 修界面骗人五例（死链 + 对比度）**
- 死链 14 条（明细 `docs/桌面端工具链_2026-10-21.md`）：逐一核对，死则删/改/补。
- 对比度：`tools/uicheck/a11y.js`（axe-core）扫，达标才过。
- 门禁：全站零死链、关键文本对比度 ≥ WCAG AA（4.5:1）。

### 第 N+1 环：桌面端技能机制（重点之一）

**目标**：让技能进化机制在桌面端**真正可用**，而不是只在仓库里有模块。

- **列出/选用**：桌面 GUI/TUI 能列出技能（`summary()` 已剔除 body，38 张卡正文不外发，安全）；用户/模型可选用。
- **执行留痕**：技能被使用时写 `use:` 证据；能力调用写 `exec:` 证据（`fleet/execute.py` 已具备）。
- **记分**：`skill_stats()`（使用次数 / 影子成功率 / 证据充分性）在桌面可见。
- **提交 / 回滚**：promote=提交（快照+回执+噪声守卫）；rollback 是提交的**产物**（内在能力，不单立项目）。
- **新能力纳入**：凡有利于进化的新证据源（感知事件、算力调度结果、跨端 exec 回执）都可列入，不预设红线堵死。
- 门禁：桌面端真跑出技能 done 回执；回滚后技能仍可加载、四闸仍过。

### 第 N+2 环：手机端算力调度（重点之二，多设备共享升级版）

**定性（已认同）**：算力调度 = 设备层编队的**能力升级**——从"控制设备"到"调度设备上的算力"，**不必从零新建编排层**，是在 fleet 已有编队/网络通道上长出"算力委托"。

**连续性路径**：
1. **起点（已完成）**：设备层编队——9 台设备探活、87 能力、MCP 4 文件、node1/node2/ECS 远程节点已在网。
2. **升级一：两台电脑网络共享算力**：走 fleet 已有网络协议（MCP / 端口转发 / 远程节点通道），A 机重推理派到 B 机空闲核。⚠️ 远程节点纪律：4 核规划、线程开多反慢；**ECS 单线程挤死控制面、通道拥堵，重推理不派 ECS 控制面**。
3. **升级二：手机调度手机**：安卓 fleet-bridge 已可无障碍注入；手机既是被控载体，也可作算力/能力节点被调度。
4. **终局：三端互为调度者**：电脑 A、电脑 B、手机三者互为调度者与被调度者，协同身边智能设备。
- 门禁：派发 ≥99%；单任务不跨节点串味；掉线自动回退；不派 ECS 控制面。

## 五、AudioSync v2 深化线（用户点名"手机插数据线当音箱"技术）

> 诚实边界：**当前"插数据线"不是 USB 音频类通道**——是 USB 网络共享/ADB 转发建 IP 链路，音频仍走 TCP:24627 裸 PCM（≈1.5Mbps 未压缩）。深化项：
1. **Opus 实时编码（高优先）**：≈1.5Mbps → ~30kbps，弱网可推。⚠️ README 已列待办、**未实现**，真实缺口。
2. **真·USB 音频类 UAC（中优先）**：手机以 USB Audio Device 被 PC 识别，免 IP"插线即播"。⚠️ Android 受 USB 外设角色限制，**可行性待探**（标"估"）。
3. **upfile 通道加 PIN（安全）**：当前 :24628/:24629 无 PIN，补白名单门禁。
4. **双向组网**：手机配手机（已有）+ PC 配 PC 互推（新增）。

## 六、边界与纪律

### 6.1 隐私：带边界地做（不堵死探索）
- 不写"因为隐私所以不做"。落地带最小安全边界：凭证已打码（memguard）、来源签名、回滚熔断；跨设备交换先补鉴权边界再放开。

### 6.2 沿用铁律（不许破）
1. **顺序锁死**：桌面端（原点）没好，扩散不成立；任一环无门禁验收不许进下一环。
2. **静默失败零容忍**：跨端派发、推流、回滚，失败必须带原因。
3. **界面骗人五例禁止**：死链/空状态装作有/数字写死/不响应/看不清——N 环必须修。
4. **证据不混级**：`exec:` 强证据支撑 propose；跨端后不变。
5. **诚实边界**：凡"估/待测"（sherpa 首字、UAC 可行性）附验证方式，不许写成结论。
6. **远程节点纪律**：ECS 单线程、通道拥堵，重推理不派控制面；按 4 核规划。
