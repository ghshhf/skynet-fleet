## 一、结论

UU远程 拆开是三件：**串流（编码/传输/解码）+ 连接管理（ID/验证码/中继）+ 外设延伸（键位/手柄/文件/剪贴板）**。对天网（设备编队 + 手机 Agent）真正值钱的不是「远控桌面」本身，而是这四格：

1. **远程唤醒（WOL）**——设备层从「能连」升级到「能叫醒」，几十行，收益立刻可见
2. **隐私屏/无痕接入**——天网控手机时被控端黑屏，省电 + 隐蔽，adb 就能做
3. **被控端授权 UI（弹窗 + 验证码 + 一键禁止）**——arbiter 现在只有「审批人侧」的闸门，缺「被控人侧」的可见性；UU远程 整套安全 UX 是现成答案
4. **低延迟串流 + 群控**——「显影面」从截图轮询进到硬编码串流；群控与天网「编队」概念天然同构

| # | UU远程功能 | 天网现状 | 判定 | 优先级 |

## 四、融合路线（一个功能一 commit）

- **P0-a `device.wake` 远程唤醒**：`fleet/` 新增 wake 能力（UDP 广播 magic packet，子网 + 跨子网两种）；门禁：伪造 MAC 单测 +  loopback 广播不报错；验收：`web.status` 同级出现 `device.wake`，能唤醒同段一台真机
- **P0-b 隐私屏 + 无痕**：控制会话建立 → 被控端熄屏/静音/锁屏，断开恢复原状；随 arbiter 会话生命周期走；验收：投屏操控期间被控手机全黑，断开自动亮回
- **P0-c 被控端授权 UI**：arbiter 增加「被控弹窗」通道（App 端）；请求方 ID + 批准/拒绝 + 永久禁止；验收：一次远程请求在手机弹窗，点「永久禁止」后同来源再请求直接被拒
- **P1-a 传输续传复用**：Range 续传从 web.download 抽到传输层，adb push/pull 与局域网传输共用；验收：大文件中途杀进程，重传从断点继续
- **P1-b 串流升级（最大项）**：设备端 MediaCodec 硬编码 + 主机解码，替换截图轮询；基准线：≤70ms、≥30fps、首帧 ≤1s；先 USB 后无线
- **P1-c `fleet.broadcast` 群控**：操作类能力对编队广播、逐台回执、部分失败可重试；验收：一条「装包」指令广播 3 台，回执 3/3
- **P2**：keymap 脚本（手机变键鼠）、剪贴板双向、多屏映射

天网是 **MIT**。RustDesk / Sunshine / Moonlight / Aspia 是 **GPL/AGPL**——**架构可以学，一行代码不搬**（搬了 = 整个仓库被传染，MIT 不保）。可安全参考实现的只有 Apache-2.0 一系：**scrcpy / QtScrcpy / MeshCentral / Guacamole**——参考时保留版权与许可声明，并在 commit message 注明参考来源。WOL 是标准协议（magic packet 无版权问题）。此条与 netforce 的「只 import 不复制」是同一纪律的两个面。
