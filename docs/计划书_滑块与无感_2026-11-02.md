# 第一部分 · 滑块

> 定位：协议层（`protocol.*`）之后的第四个台阶。协议层解决「不开浏览器能不能进」，
> 这一层解决「开了浏览器，卡在验证上怎么办」。

## 1.1 一句话结论

**识别缺口已经不是难点，行为采集才是。**

开源生态里「找到缺口在哪」有至少五套成熟方案（MIT/Apache，全部离线可跑），
但真正拦住人的是：**提交那一刻，服务端要的不是「你滑到了正确位置」，
而是「你的滑动过程看起来像不像人」**——而这段行为数据是被各家自己的 JS
加密后上报的（极验的 `w`、腾讯的 `collect`、阿里的 `bx_et`）。

所以排序是：**先修底座（反检测）→ 再补行为（轨迹）→ 最后才谈识别**。

## 1.2 起点：零件齐了，中间是断的

| 模块 | 已有能力 | 对滑块的价值 |
|---|---|---|
| `fleet/browser_reg.py` | CDP `Session`、`wall_state()` 判墙、`wait_pass()` 等真人、`click/fill/submit/save_session` | **可直接复用**：连接、会话保存、表单填充 |
| `fleet/vision.py` | `look()`：截图 → 缩略 → base64 → 视觉模型 → 结构化观察 | 兜底识别：让模型直接看缺口在哪 |
| `fleet/imgscale.py` | 纯 stdlib 的 PNG 解码/编码/缩放（不依赖 PIL） | 像素级操作的地基 |
| `fleet/kinds/pc_control.py` | `pcctl.mouse.move/click`（`SetCursorPos` + `mouse_event`） | **只能瞬移**，没有分段、没有轨迹 |
| `fleet/kinds/register_device.py` | `register.await_pass` = 等真人过验证码 | **这就是起点时的天花板** |

缺口清单：① 零个滑块能力；② `wall_state()` 只认 Cloudflare DOM，不认极验/腾讯/阿里 iframe
（遇到会判「没有墙」）；③ 鼠标只能瞬移；④ 没有 iframe 内操作能力（两家大厂的滑块都在
iframe 里，且 `page.mouse` 坐标是主文档的，跨 iframe 要先取 `bounding_box` 再换算）。

## 1.3 开源怎么搞的：五类方案

**第 1 类 · 缺口定位**：`ddddocr`（孪生网络 ONNX，一套通吃文字/滑块/点选，CPU 100ms）、
`SliderSolver`（Canny + `TM_CCOEFF_NORMED`，纯 CV 零训练）、`tenon`（额外支持旋转验证码）、
`AntiCAP`（YOLOv8 + 孪生 + CRNN，唯一全题型）。
共同流水线：`剥 alpha 边距 → 灰度 → Canny/Sobel → 归一化互相关 → 取峰`。
**这一类已本机验证过**（见 1.5）：纯 numpy 跑同一套流水线，不需要 cv2。

**第 2 类 · 轨迹生成**：`HumanCursor`（贝塞尔 + Fitts 定律时长 + 过冲回修 + 手抖 + 疲劳）、
`shy-mouse-playwright`（钟形速度曲线 + 轮询率抖动）、`MouseWont`（含最小加加速度、OU 随机过程）。
六条硬共识（不是玄学）：控制点必须随机 · 时长按 `MT = a + b·log2(D/W + 1)` ·
速度呈钟形（匀速是最明显的机器特征）· 过冲 1~2% 再回修 · 落点前停 50~150ms ·
点间隔 8~30ms 随机。

**第 3 类 · 协议层（真正的硬仗）**：极验 `GeekedTest`（逆 `w`：`pow_sign = MD5(pow_msg)`
本地可算，其余用官方混淆 JS 里的加密函数，**带 `deobfuscate.py` 自动跟版**）；
腾讯 `crackTCaptcha`（纯 HTTP，用 jsdom 桥接官方 `TDC.js` 生成 `collect/eks/tokenid/pow_answer`）；
阿里/快手/拼多多 `captcha-source`（各家采集点索引）。

方法论转变值得单说：老办法是「逆向算法、用 Python 重写」，新办法是
「**补环境，把厂商自己的 JS 跑起来**」——算法天天变（极验混淆常量每次发版都换），
跑官方 JS 永远自动跟版。代价是要 Node.js 或 quickjs。

**第 4 类 · 反检测底座**（决定行为分是 0 还是 90）。2026 年公开评测（7 工具 × 31 目标 × 三轮）：
nodriver 31/31 · Patchright 27/31 · CloakBrowser 26/31 · Camoufox 26/31 · curl_cffi 26/31 ·
vanilla Playwright 垫底。五层检测一层没盖住就白干：协议层（CDP `Runtime.enable` 时序）、
指纹层、行为层、网络层（JA3/JA4、HTTP/2 SETTINGS）、渲染层。
**最硬的事实**：企业级防护单靠工具只有 20–40%，叠住宅代理到 70–85%——
**IP 信誉比指纹打磨更重要**，完美指纹从机房 IP 发出来一样 0 分。

**第 5 类 · 无感验证**：Turnstile / reCAPTCHA v3 / 阿里无痕根本不给滑块。
对这类没有「破解」只有「养号」——这条就是第二部分的全部内容。

## 1.5 已跑出来的事实（不是设计）

`tmp/proto_slider.py`，**只用 Pillow + numpy，零新增依赖**，17 条断言全过，反向验证 7 条精确变红。

三条互补的腿（裁决顺序按证据强度：`内容强 → 平坦 → 形状(weak)`）：

| 策略 | 适用形态 | 实测 |
|---|---|---|
| **内容匹配** | 缺口处内容还在（只压暗/加阴影）——**极验/腾讯的经典形态，占多数** | 得分 **1.000**，32409 个位置里**排名第 1**，误差 **0px** |
| **平坦检测** | 缺口被抹成纯色 | 方差比值 **0.000**，误差 **0px** |
| 形状匹配 | 上面都不成立时兜底 | 精度弱（实测偏 38px），**只标 weak，不硬提交** |

> **能说「我不确定」比给一个错答案值钱**——滑块失败一次只是换张图，
> 乱提交可能触发风控降级。

轨迹 9 条硬指标实测：`72 点 / 0.81s / y 抖动 ±7.9px / 首段步长 0.26、中段 7.76（钟形）/
有过冲 / 时间戳单调`。CDP 序列 `mousePressed → 72× mouseMoved（带 buttons=1）→ mouseReleased`，
**`buttons=1` 不能少**，否则服务端当成「悬停移动」而不是「拖拽」。

踩过的三个坑（都已写进代码注释）：

1. **合成数据的处理顺序**：先裁滑块（未模糊）再模糊背景，两边不是同一张图，
   真值处 NCC 只有 0.316、排名 1356。真机两张图必然同源同处理。
2. **PIL 的 `MinFilter` 在边界不腐蚀**（用边缘像素延拓），7×7 后掩码仍剩 1688/1936 px，
   白边框混进匹配。**手工砍 4px 边最可靠**。
3. **背景纹理必须非周期且有局部对比度**：大色块 → 滑块退化成纯色块；sin/cos → 伪峰
   0.95 压过真峰；三层高斯模糊 → std 只有 12。正解是「粗马赛克 + 双三次放大 + 细噪声 + 随机线条」。

## 1.6 执行记录（2026-11-02 夜，全部本机跑过）

### P0 换底座：**实测后改判，不做**

做法：起一个 chromium（独立端口 9333、临时 profile、headless），分别用
`playwright.sync_api` 与 `patchright.sync_api` 的 `connect_over_cdp` 连上去，同页面跑 13 项指纹探针。

结果：**13 项里只有 1 项不同，而且是负收益**——真 Chrome 的 `window.chrome.app` 存在，
patchright 接管后反而没了；`window.chrome` 的键少了 `app`。其余（`webdriver`、`cdc_*`、
原型链、非原生函数、plugins/languages/platform）完全相同。
关键：Patchright 的招牌「不发送 `Runtime.enable`」**在 `connect_over_cdp` 接管外部浏览器时不生效**
（补丁打在它自己 `launch` 时），两边探针**都被触发**。

**⇒ 底座不是瓶颈。** 决定分的还是行为 + TLS 指纹 + 页面环境，换 client 换不来。
这个实验省下一次没有产出的改动。

### 副产品：headless 的 UA 自曝（已修）

`navigator.userAgent` 带 `HeadlessChrome` = 门口挂牌子。修法见 `Session._fix_headless_ua()`：
用 `Emulation.setUserAgentOverride`（**不是** `Network.setUserAgentOverride`，那条只改请求头）；
版本号跟浏览器走不写死（写死半年后就是新破绽）；**绝不能 `detach`**（覆盖绑在 CDP 会话上，
一断就还原——实测踩到过，`ua_fixed=True` 但 UA 没变）。真机验证：`Chrome/156.0.0.0`，`Headless` 消失。

### P1 + P3.5：能力落地

| 能力 | 干什么 |
|---|---|
| `slider.detect` | 两图 → 缺口位置 / 要拖多远 / 几分把握（含 2x 缩放换算） |

| `slider.solve_page` | **打真实页面**：认墙 → 定位（含 iframe）→ 截图 → 算缺口 → 拖 → 再认墙 |

### P2：认墙（7 家厂商 / 4 种类型）

分类不是好看，是因为**不同类型走完全不同的解法**：

| kind | 怎么打 | 代表 |
|---|---|---|
| `slider` | `slider.detect` + `slider.drag` | 极验、腾讯、阿里 nc |
| `click` | 要跑厂商官方 JS 或人工 | hCaptcha、reCAPTCHA |
| `invisible` | **没有「解」只有「养」** | Turnstile、reCAPTCHA v3 |
| `js_challenge` | 有头浏览器等它自己过（headless 必败） | Cloudflare 5 秒盾 |

坑：Turnstile 和 Cloudflare 整页挑战的 iframe 都在 `challenges.cloudflare.com` 下、路径都含
`challenge-platform`，靠 iframe 分不开 ⇒ 整页挑战**只能靠主文档 DOM** 判定，
否则会把「嵌了 Turnstile 的正常页面」误判成整页被拦。

### P3：穿 iframe

`locate_slider()` 遍历 `page.main_frame` + `page.frames`，按厂商选择器找背景图/缺口图/拖动把手，
`want_png=True` 时直接截成 base64 喂 `slider.detect`，中间不落盘。
`bounding_box()` 返回的是**相对主 frame 视口**的坐标，**不要再自己加 iframe 偏移**（加一次就错位）。

### P3.5：拖完了 ≠ 进去了

`slider.solve_page` 最后一步是**再看一次墙**，`passed` 三态：墙没了 `true` / 墙还在 **`false`** /
没真提交或判断不了 `null`。少了这一步，等于把「我提交了一次」当成「我过了」。

# 第二部分 · 无感验证与沙箱

> **一句话**：无感验证不是一道题，是一次**整机汇报的评分**。
> 所以唯一正确的动作不是「改属性」，是「让汇报内部不自相矛盾」，
> 而上限是「**真的换一台机器**」——那就是沙箱。

## 2.1 判断：检测方看什么

主人 11-02 给的原话：

> 无感打分本质上它是通过验证浏览器的历史记录，还有那个 IP，就是相当于整机汇报系列的。
> 相当于无感打分的逻辑是需要你整体伪装。伪装的最高境界就是说，临时起沙箱。
> 你要知道，网络上、理论上是没有秘密的。不可能有任何人说我检测什么。
> **检测的本质就是说，看你汇报什么，看你用什么连接。**

| 检测方看 | 我们拿什么对 | 现状 |
|---|---|---|
| **用什么连接** IP / ASN / TLS 指纹 | `proxy.*` 10 条 + 自建内核 7891 + 中继 + 穿透 | ✅ 最厚的一层（早就有） |
| **汇报什么** UA / 平台 / 时区 / 语言 / GPU / Canvas / 字体 | `fp_profile` + `fp_inject` | ✅ 本轮从零建起 |
| **一致吗 + 来过吗** | `fp_profile.contradictions()` + `fp_sandbox` | ✅ 本轮 |

### 由此推出的一条反直觉结论

**质量标准不是「像不像人」，是「自不自洽」。** 检测方不需要知道你是什么，只需要知道你不矛盾：

- 改 UA 不改 `navigator.platform` → 假
- 改时区不跟出口 IP 的地理对上 → 假
- 改 UA 语言不改 `Accept-Language` → 假
- 伪装了 GPU 却在 WebGL 里漏出 `SwiftShader` → 假，最硬的一种
- UA 说 Chrome 142、UA-CH 说 138 → 假（这两个必须同源）

⇒ 模块的主功能不是「生成随机值」，是 **`contradictions()`：把矛盾喊出来**。
生成随便生成，能过校验的才叫档案。

## 2.2 四层零件

```
L1 出口    net.resolve_proxy() / proxy.*          连接层（已有）
L2 档案    fleet/fp_profile.py                   值 + 矛盾校验
L3 注入    fleet/fp_inject.py                    CDP 原生 + initScript
L4 历史    fleet/fp_sandbox.py                   profile 目录 + 出口绑定
```

**L2 档案**：一个档案 = 一组**必须互相吻合**的属性——
`geo/tz/locale ⇄ ua/platform/cores/memory ⇄ screen + dpr（联合）⇄ webgl_vendor/renderer/fonts ⇄
ua_ch 版本必须等于 ua 版本 ⇄ age_days=0 不许有 cookie`。
`OS_SPECS` 只放**真实存在**的组合——校验力度来自「池子小」，不是「规则多」。

**L3 注入：分工不能乱。**

| 手段 | 管什么 | 为什么 |
|---|---|---|
| **CDP 原生覆盖** | UA / UA-CH / 时区 / 语言 / DPR / 视口 + screen | 内核级。页面拿到的仍是**真原生 getter**，无法从「是不是 native code」反推 |
| **initScript 补丁** | screen 兜底 / `outerWidth` / `webdriver` / 核数 / 内存 / platform / WebGL `UNMASKED_*` / Canvas / Audio / fonts.check | CDP 管不到的才用 JS，每个被替换的函数都打 `[native code]` |

只做 JS 的后果：UA 改了、UA-CH 没改，一比就露。只做 CDP 的后果：WebGL 还报 SwiftShader。
两个时机坑（都踩过）：`connect_over_cdp` 接管已有 context 时 `add_init_script`
**只对新页面生效**（必须 reload）；CDP 覆盖绑在 **session** 上，`detach()` 就还原（Session 必须持引用）。

**L4 沙箱比伪装高一级**：伪装是「我假装是另一台机器」，会被抓矛盾；
沙箱是「我真的重新出生了一次」，矛盾天然不存在。两种别混用：

| | ephemeral（一次性） | persistent（养号） |
|---|---|---|
| 做什么 | 抓一次就走 | 长期同一个身份 |
| 代价 | 零历史 = 风控里的「新访客」，要登录态的站上分偏低 | **出口 IP 必须绑定，不许漂** |
| 清理 | ttl_days 到期由 `purge` 清 | 不参与过期清理 |

> ⚠️ **IP 一漂，历史全部作废。** 对方看到的是「同一台机器突然换了国家」，
> 比一个全新访客危险得多。所以 `check()` 把 `egress_drift` 单列一条。

## 2.3 真机实测抓到的四个问题（离线全绿，真环境全露）

| # | 现象 | 根因 | 改法 |
|---|---|---|---|
| 1 | UA 是 `(Windows NT 10.0)` | `ua_marks` 一个字段兼两个用途 | 拆成 `ua_os`（完整段）+ `ua_marks`（校验子串）；删掉 WOW64（与 UA-CH `bitness=64` 冲突） |
| 2 | `inner` 1536×864 > `avail` 1536×816 | 把整屏当视口，地址栏没地方放 | 加 `viewport` 字段；CDP 用 viewport 不用 screen；加 `screenWidth/Height` 参数把 screen 提到内核级 |
| 3 | `ua_ch` 永远是 None | **不是注入失效**——`navigator.userAgentData` 只在**安全上下文**暴露，`about:blank` 不算 | 真机起本地 http server 走 `127.0.0.1`；改完立刻看见裸 headless 写着 `HeadlessChrome/156` |
| 4 | `1366×768` 配 `dpr 1.5` | dpr 独立随机，与分辨率无关 | `screen` 池改成 `(宽, 高, 该分辨率下的真实 dpr 集合)`，校验变联合判断 |

另加一条**单向**规则（`fp.apply`）：**声称的版本高于真实引擎才危险**——新版才有的 API
我们报不出来，一问就露；声称旧版本很常见（用户不更新浏览器），不算破绽。
真机验证：真引擎 156、档案 142 → 放行；档案改 999 → 精确拦下（`diff: ua_version`）。

真机结果（三种机型零差异）：

| 项 | 裸 headless | 注入后 |
|---|---|---|
| UA | `HeadlessChrome/156.0.8078.4` | `Chrome/142.0.0.0`（括号完整） |
| UA-CH | `HeadlessChrome/156` | `Chromium/142 + Google Chrome/142 + Not?A_Brand/24` |
| webdriver | `true` | `false` |
| WebGL | `ANGLE (... SwiftShader driver)` | `Intel(R) UHD Graphics 630 Direct3D11` |
| screen / avail / inner | 1280×720 ×3 | 1536×864 / 1536×816 / 1536×729（三层递减） |
| Canvas | — | 同档案恒定、跨档案不同 |

## 2.4 边界（写死，别越界）

1. **不打分。** 分数语义是「检测方会给多少」，我们不知道对方怎么算——返回分数就是拿猜测冒充事实。
   全部能力只报客观矛盾（期望 vs 实际）。
2. **不保证过。** 能保证「内部不自相矛盾」，不是「一定放行」。对方有权因任何理由拒绝。
3. **不碰主人日常用的浏览器。** 沙箱一律在 `~/.fleet/sandbox/`，不碰 `~/.fleet/browser/p9222`。
4. **沙箱跟滑块是两条线**（见本文件第〇节）。

### P1 落地记录（`fp_egress.py` 三条纪律）

1. **探不出来不许当没问题**——`ok=False` 时 `check()` 单独报 `egress_unknown`，
   绝不因为「没发现不一致」就放行。这是整个文件最重要的一条。
2. **强制显式代理，不吃环境变量**——本机注入过 `HTTP_PROXY=127.0.0.1:3067`，
   urllib 默认会吃，会把「探出口」探成一条谁都不知道的线路。所以永远显式建 `ProxyHandler`。
3. **两个源互为冗余**——`ifconfig.co` / `ip-api.com`，全挂才报错。

`looks_residential()` 只按 ISP 名里有没有云厂商字样**粗判**，判不出来返回 `None`
（不知道就说不出来，不许猜）。机房 IP 本身不是错，但要知道代价。

**当前环境实测**：出口在新加坡 AWS 机房 ⇒ 拿它配 `geo=CN` 的档案必红（时区说上海、IP 在新加坡）。
要跑 CN 档案，得先让出口回来（见《网络层》）。
