# 天网（device-fleet）桌面端迭代计划

> 生成日期：2026-10-24。唯一真相源：`fleet/__init__.py:VERSION`（当前 0.2.0）。
> 本计划只覆盖**桌面端**（Windows 主力；Linux/macOS 次要）。手机端另见 `docs/整体盘点与下一步计划_2026-10-24.md`。

## 〇、现状一句话

桌面端不是"没做"，是"做了三套壳（CLI / TUI / GUI）但版本号死代码、测试盲区、两层架构重叠"。
本轮已收口：CLI 合并 TUI（`--tui`）、版本号单点真相、CI 加 `run_selftests`、控制面胶水 `fleet/controlplane.py` 就位。

## 一、形态终态（用户最终只留两个）

| 形态 | 入口 | 定位 | 状态 |
|---|---|---|---|
| **CLI（终端版）** | `python -m fleet.shell`（`--tui` 起全屏） | 键盘党 / 无 GUI / CI 冒烟 | 已合并，统一入口 |
| **GUI（客户端版）** | `python fleet_gui.py` / `fleet-gui.exe` | 主力用户，pywebview 套本地 Web UI | 可用，WebView2 依赖 |

`fleet-tui.bat` / `fleet-cli.bat` 保留为兼容 shim，内部转调统一入口。

## 二、下一轮迭代批次（按优先级）

### P0 · 架构收口（D1 真正落地）—— 一周
- **目标**：把 `commander.py`（2704 行）的 PSK 注册 / 心跳看门狗 / 离线命令队列迁进 `fleet/` 包，根目录脚本退化为 CLI shim。
- ** owned API**：`fleet/controlplane.py` 已就位（`available` / `send_to_node` / `registry_nodes`），fleet 包只认它。
- **迁移顺序**：① 节点注册表（enroll.py 487 行）→ `fleet/enroll.py`；② 心跳看门狗 `watchdog_loop` → `fleet/watchdog.py`；③ `send_to_node` + 命令队列 → `fleet/dispatch.py`；④ `commander.serve` → `fleet/controlplane_serve.py`。
- **验收**：`commander.py` 变成 30 行 shim（只调 `fleet.controlplane_serve.main()`）；hiddenimports 从 40+ 老模块降到 ≤10；`run_selftests` 全绿；exe 体积 < 40MB。
- **风险**：两层 import 方向（老脚本 import fleet）要反向；迁移时务必保留 `from fleet import jobs` 这类运行时 import 的语义。

### P1 · 测试盲区填平 —— 3 天
- **目标**：CI 不再 build-only。
- **动作**：`build-gui.yml` / `build-tui.yml` 已加 `run_selftests.py`；补 `build-android.yml` 同步；给 `fleet_tui.py --smoke` 加进 CI（headless Textual）。
- **验收**：三条流水线任一红就挡合并；本地 `python run_selftests.py` 与 CI 结果一致（避免 cp1252 编码陷阱，已设 PYTHONUTF8）。

### P2 · 版本号 exe 自报 —— 1 天
- **目标**：`fleet-gui.exe --version` 打印 `0.2.0`；CI 断言。
- **动作**：`fleet-gui.spec` 的 `datas` 或 runtime hook 注入 `FLEET_VERSION`；`fleet_gui.py` 加 `--version` 参数。
- **验收**：`dist\fleet-gui.exe --version` 输出 `天网 device-fleet 0.2.0`。

### P3 · GUI 部署风险收口 —— 2 天
- **目标**：WebView2 缺失时的 fallback。
- **动作**：`_require_webview()` 失败时自动打开系统默认浏览器指向 `http://127.0.0.1:<port>`（GUI 服务本体已跑）；文档写清 WebView2 安装方式。
- **验收**：无 WebView2 的干净 Windows 虚拟机能用浏览器打开 GUI。

### P4 · D1 远程代发真正落地 —— 1 周
- **目标**：`shell.exec` / `file.push` / `file.pull` 从"只登记"变成"真能跑"。
- **前置**：P0 完成（控制面迁进 fleet 包）。
- **动作**：`FleetNode.invoke` 对接 `fleet.controlplane.send_to_node`；加 `--device node:xxx` 路由；审批闸门对远程 destructive 操作生效。
- **验收**：在 GUI 控电脑面板选 `shell.exec` → 选 node → 输入命令 → 看到远端输出。

### P5 · 老脚本 shim 化 —— 与 P0/P4 并行
- **目标**：`desktop.py` / `phone_ops.py` / `platform_*` / `compute_runner.py` 等 37 个老模块，逐步加 `fleet/` 包装，根目录只留薄入口。
- **节奏**：每轮迁移 3-5 个，不搞大爆炸。

## 三、明确不做的（避免 scope creep）

- **不**继续给 GUI 加 Tab/功能——功能面已够，短板在"最后一层"。
- **不**重写 TUI——它和 CLI 已合并，只维护一个。
- **不**做跨平台打包（macOS/Linux exe）——Windows 主力，其他靠 `python -m fleet.shell`。
- **不**引入 Node/React——GUI 是 pywebview 套本地 Web UI，够用。

| M2 测试盲区填平 | +10 天 | 三条 CI 全跑 selftests |

## 五、风险与回滚

- P0 迁移失败：保留 `commander.py` 原文件不动（git 历史），新代码走 `fleet/controlplane.py` 胶水，随时可切回老脚本。
- CI 加 selftests 后若大量红：先标 `continue-on-error: true` 观察一周，再挡构建。
