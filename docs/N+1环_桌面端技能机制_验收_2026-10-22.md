## 二、抓到的三个后端真 bug（本轮最实的产出）

t18 不是为了「证明自己对」写的，是为了**抓错**写的。一上手就抓到三个，
其中第一个是**线上已经坏着但从没被跑过**的。

### bug ① rollback 在线上实际是坏的（最严重）

**症状**：`verify()` 直接抛 `TypeError: %d format: a real number is required, not str`。

**根因**（实测定位，不是猜）：
- `parse_frontmatter` 用 `_parse_inline_list` 解析 `evolved_from: [2, 4, 6]`，
  返回的是**字符串** `["2","4","6"]`（同一个函数还要解析 `caps` 这种字符串列表，
  没法在里面分类型）；
- `_done_events` 拿这些 id 去 SQLite 查，而 id 列是**整数** ⇒ 全部「证据不存在」；
- 于是回滚后重过四闸时**闸1 必红** ⇒ `rollback()` 的自验③永远失败
  ⇒ 工作区被改回原样并抛错 ⇒ **rollback 从来没能成功过一次**。

**为什么从没暴露**：`local-inspect` 只有一个已提交版本，`rollback` 在
「只有一个提交」那道就诚实拒绝了，根本走不到自验。
**没被跑过的代码不等于能跑的代码。**

**修法**（三处，全在取数链路上）：
- 新增 `_coerce_ids()`，在 `_done_events`（唯一取数入口）归一化成 int；
- `_candidate_from_disk` 重建候选时也过一遍（源头就对齐）；
- `verify()` 里报错格式 `%d` → `%s`：报错路径自己崩掉比报不出错更糟。

### bug ② 落盘失败的真实原因整条丢失

**症状**：GUI 点「确认落盘」被拒时，前端只显示「落盘被拒：四闸不过」——
到底哪闸红、是不是同名，永远看不到。

**根因**：`promote()` 返回的键叫 `"error"`，而 `_post_skill_promote` 读的是
`rep.get("err")` ⇒ **err 恒为 None**。两处命名不一致，且没有任何测试覆盖到
失败路径，所以一直静默。

**修法**：`promote` 统一返回 `"err"`；GUI 端点两侧兼容（`err` / `error` 都认），
防以后再漏改。

### bug ③ `force` 是一个同时绕两道关的后门

**症状**：`promote(candidate, force=True)` 既绕过四闸、又绕过同名守卫。

**为什么是设计缺陷而不只是参数问题**：
- 计划书§七「自动改技能并直接生效」明确不做，而 `force=True` 正是那条路；
- 更要命的是：**GUI 只会传「不覆盖」⇒ 桌面端永远产不出第二个版本
  ⇒ 回滚永远碰不到**。rollback 机制做了却从 GUI 够不着，等于没做。

**修法**：`force` → `allow_overwrite`，语义收窄成「只放开同名守卫」；
**四闸永远先跑，红就拒绝**。GUI 端点接受 `overwrite` 并在「同名已存在」时
回 `can_overwrite=true`；前端不自动覆盖，弹确认让人明确点头后才带 `overwrite` 重发。

> t18 §⑨ 专门钉这条：造一个必红候选，连 `allow_overwrite=True` 也必须被四闸挡下。

## 三、额外抓到两处无障碍违规（N 环的 axe 扫不到）

N 环的 a11y 只扫默认聊天视图，而**资产视图根本没渲染** ⇒ 技能页的违规一直没暴露。
本轮对技能页单独补扫（两个主题），抓到 2 条：

| 违规 | 严重度 | 内容 | 修法 |
|---|---|---|---|
| `aria-required-children` | critical | `#tabBar` 声明 `role="tablist"`，但刷新按钮 `<button>` 直接挂在里面——tablist 只允许 `role="tab"` 的子元素 | 4 个 tab 收进专用 `.tablist` 容器，刷新按钮移到容器外 |
| `color-contrast` | serious | 激活的「技能」tab 前景 `#2f6bd8` / 背景 `#f2f3f5` = **4.48**，差 0.02 不达标 | 见下 |

顺带把 N 环「实心底/文字色分离」的思路延伸了一层：

**新增 `--accent-text`**（light `#2d66cf` = 4.834，dark 沿用 `#5b8def` = 4.711）。
核算过全部 4 种浅底：白底 5.367 / panel-2 4.834 / accent-soft 4.912 / bg 4.688 全过。
`--accent` 一个字节没动（仍用于边框等无对比度要求处），14 处文字色切到新变量。

> 踩的坑：用 `sed` 全局替换时，`border-color:var(--accent)` 里含
> `color:var(--accent)` 子串，12 处边框被误改。已定向改回并用精确匹配核对。

## 三·补、t7 的 id 契约检查漏了「运行时创建」这一类

第一轮全量回归 58/59，挂在 `eval_t7_gui_backend`：

```
x  app.js 用到的 id 在 index.html 里都有（缺 ['esDesc','esGates','esName','esPromote','esTrace']）
```

这 5 个 id 全是 `evolvedForm()` 里 `el(...)` 之后 `.id = "..."` **运行时创建**的，
点点就有反应，报「缺 id」是**假的**——检查只认 index.html 里静态写着的。

**修法（不是放松，是补全契约）**：
契约从「每个 `$("id")` 必须在 index.html 里」改成
「每个 `$("id")` 必须**有着落**：静态写着，或被 app.js 自己创建」。
另外加一条反向检查：声称动态创建的 id，其 `.id = "..."` 赋值必须真在代码里
（防止靠加一行赋值把检查糊弄过去——那样 `$("xxx")` 还是拿到 null）。

**反向验证**：往 `app.js` 注入一个拼写错误的 id（`esTrace` → `esTraceTYPO`），
门禁照红；恢复后 0 失败。⇒ 抓拼写错的原意没丢。

> 教训跟 N 环同源：**门禁的口径比现实窄时，报出来的红是假的**；
> 但放宽必须连反向验证一起做，否则就是放水。

## 五、诚实边界

1. **技能页的 axe 扫描是一次性探测，没固化成工具**。`a11y.js` 仍然只扫默认视图。
   本轮两个主题各扫过一次（修前 2/1、修后 0/0），但**以后改技能页还得再扫**。
   要固化就得给 `a11y.js` 加 tab 参数——没做，因为不想在这一环顺手改验收工具的结构。
2. **clickaudit 不覆盖技能页按钮**。它的相位会把 tab 复位到「专家」。
   所以「按钮→端点」改由 t18 的 Node 侧验，两条链路互补但不重叠。
3. **像素回归对技能页是瞎的**：`shot.js` 只拍默认视图。本轮是另写探测脚本
   滚到自写区单独截图确认的（`skills_tab.png` / `skills_evolved.png`）。
4. **覆盖率 92%**（N 环 91–92%，属同类抖动）：6 个跳过项里 3 个是审计工具对
   审批遮罩 `RESTORE` 清理不彻底（不是界面缺陷），1 个是「拒绝」按钮被关弹窗后
   消失，1 个是 `#sendBtn` 空输入时 disabled（正确行为），1 个是「专家」tab
   已是当前选中项（正确行为）。
5. **像素基线本轮重切过一次**：旧基线是 N 环 17:35 切的，到本轮右侧实时面板
   （CPU/内存/进程表）数据漂移已达 **2.627%**（用还原到 HEAD 的无改动代码实测），
   超 2% 阈值。属于**实时数据漂移**，不是代码问题——已用「同代码连跑两次 = 0.313%」
   与「还原到 HEAD vs 基线 = 2.627%」两组对照确认后才重切。
6. **`evolved_summary()` 不外发正文**（同 `skills.summary()` 纪律），
   所以 GUI 里看不到技能正文——要看请按目录自己看，这是刻意的。
