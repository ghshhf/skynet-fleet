## 0. 结论前置（先给答案）

1. **这台手机是谁**：截图里的 `Mali-G925-Immortalis MC12` + 11285MB RAM，正是我们
   `tianwang_android/jni/build-sd.sh` 注释里锁定的目标机 **Redmi K80 Ultra（天玑 9400+）**。
   它**不是另一台设备**，就是天网手机原生端的目标硬件。我们自己的 App 已经装在这台机上跑通出图。
2. **算力结论**：旗舰级。本地已能跑 **SD 出图**（`SdBridge`/JNI/`stable-diffusion.cpp`/Vulkan）、
   **Whisper 语音识别**、**TTS**。但图像生成本身**偏慢**（界面报 179s/步，疑似冷启动异常，待稳态复测）；
   **视频生成本地不可行**——移动 GPU + 11GB 跑扩散视频模型，交互速度撑不住。
3. **视频生成**：本地不推。先做 `video.gen` **能力壳 + 路由到 PC/云端节点**（走 relay 端口转发思路），
   真·本地视频等轻量模型（animatediff 小模型等）资产到位再说。
4. **模型下载地址**：你拍的"可下载列表 + Hugging Face 添加"UX 很对。我们 `ModelManager` 现在
   只登记了 2 个 SD 模型地址；按你"增加下载地址"的要求，**扩 ModelManager 的 SD 模型档 +
   在 fleet 侧新建 `model_catalog`（集中 URL 注册表）**，手机节点能拉、PC 能推。
5. **夜间传模型**：沿用现有 `file.push`（adb 通道）把 GGUF/SD 模型推到手机 `models/`，
   推完 `chmod 777`（代码里已记此坑）。
6. **打磨手机软件**：`tianwang_android`（SdBridge 出图 / Whisper / TTS / ModelManager / QueueRunner）
   和 `android_bridge`（无障碍桥）有一批 backlog。
7. **代码完善**：device-fleet 桌面侧也有一批**可离线修**的 backlog（见 §6）。

## 1. 手机现状盘点（双证据）

### 1.1 硬件（截图实拍）
- GPU：`Mali-G925-Immortalis MC12`（天玑 9400+ 旗舰 Immortalis 系列）
- RAM：`11285 MB`（≈11GB）
- 后端：`vulkan`（Mali-G925）
- 实测：`SD2.1 Turbo q8_0`，512，6 步，报 **179s/步 + VAE 10s**，TAESD 解码（快，画质略软）
- 模型目录（截图"本地模型"）：
  - `北极星-V7-Q8_0.gguf`（639MB，中文 LLM）
  - `mmproj-Qwen3VL-4B-Instruct-Q8_0.gguf`（454MB，视觉投影）
  - `Qwen3VL-4B-Instruct-Q4_K_M.gguf`（2.5GB，多模态视觉语言）
- 模型管理（截图"模型"tab）：从 Hugging Face 添加 / 添加本地模型 / 添加远程模型；
  "可下载"：`Gemma 3 4B`(2.37GB)、`Gemma 4 E4B`(5.83GB)、`Gemma 4 E2B`(4.03GB)、
  `LFM2.5 8B-A1B`(4.84GB)、`Ministral 3 3B`(2.05GB)

### 1.2 我们的代码（`tianwang_android`，已较成熟）
- `SdBridge.java` + `sd_jni.cpp`：JNI 调 `stable-diffusion.cpp`（Vulkan, arm64-v8a），
  `nativeInit/Generate/Cancel/Free/ListDevices` ⇒ **本地 SD 出图已通**
- `ModelManager.java`：**SD 模型档注册表**，现仅 `SD15`、`SD21_TURBO` 两个；URL 写死在代码；
  缺模型弹窗给地址 + adb 命令（主人 2026-10-23 定：**不搭镜像、不做 APP 内下载器**）
- `QueueRunner.java` / `QueueStore.java`：出图队列（多行 prompt 排队）
- `Whisper.java`：本地语音识别
- `Speaker.java` / `WavRecorder.java`：TTS / 录音
- `Net.java` / `MainActivity.java` / `ImageActivity.java` / `DeviceCheckActivity.java` /
  `SelfTestActivity.java` / `BenchRunner.java` / `OrbView.java` / `DeviceProfile.java`

### 1.3 关键矛盾 / 待核实
- **179s/步 真实性**：旗舰 D9400+ 的 Vulkan 算力本不该这么慢。需稳态基准（连出 3~5 张取均值）。
  若稳态仍 >10s/步，应查 ggml-vulkan 是否误回退 CPU / 缓冲。
- **LLM/VL 模型归属**：截图"本地模型"的 北极星/Qwen3VL 是 LLM/VL GGUF，但我们的 `ModelManager`
  只管 SD。这些 LLM 模型**大概率跑在第三方 App**（或我们尚未集成的引擎）。要把"手机 LLM/VL"
  纳入天网节点，需补 LLM 引擎（llama.cpp JNI）或包第三方 App（`android_bridge` 无障碍）。

## 3. 架构与落地方案

### 3.1 模型下载地址（你拍的 UX 落地）
- `tianwang_android/.../ModelManager.java`：扩展 `SPECS`，加：
  - **SDXL-Turbo q8_0**（1024 原生，1~4 步，cfg=1.0, LCM）→ 提分辨率主路
  - 社区 SD1.5 变体（动漫/写实）q8_0
  - `北极星-V7`、`Qwen3VL`、`Gemma 3/4`、`LFM2.5`、`Ministral 3` 的 **LLM/VL 档**
    （标注 `backend=llm`，现阶段仅登记 URL，引擎待补）
- 复用 `showMissingDialog` 的"给地址 + adb 命令"模式（保持主人"不搭镜像、不做下载器"的定）；
  若你改主意要"可下载一键下"，再开开关。
- fleet 侧新建 `fleet/model_catalog.py`：模型名 → `{url, 量化, 体积, 适配后端, 适用设备}` 集中管理；
  `node_agent --models` 上报手机已装 + 可下；commander 能查"某节点能下什么"。

### 3.2 夜间传模型
- 沿用 `node_agent` 的 `file.push`（adb 通道）或 adb 直推：
  `adb push X.gguf /sdcard/Android/data/app.skynet.tianwang/files/models/ &&
   adb shell chmod 777 <dir>`（代码已记 chmod 坑：adb 建目录属 shell，APP 读不进）。
- 写 `push_models.py`（PC 侧）：读 `model_catalog` 目标 + 本地已下模型，批量推到指定手机节点；
  可挂定时任务（你"晚上传"）。

### 3.3 视频生成（video.gen）
- `fleet/catalog.py` 登记 `video.gen`（side_effect，参数 `prompt/duration/fps/...`），
  本地无引擎时如实说"未配置"。
- 路由：本地无视频引擎 ⇒ 返回"未配置 / 路由远端"；PC/云端节点有视频后端时经 relay 派发
  （复用 `skynet.relay.fetch` 同套端口转发思路，方向相反：PC 把结果回传手机）。
- 真·本地视频：暂不做；等 animatediff / 轻量视频模型 + 手机算力验证。

### 3.4 手机 LLM/VL 纳入天网（更大的一块，本轮回登记不落地）
- 选项 A（推荐先不做）：包第三方 App 经 `android_bridge` 无障碍读屏/点按调 LLM/VL
  （已有《天网手机端_借力Operit_计划书》）。
- 选项 B（重）：给 `tianwang_android` 加 llama.cpp JNI 引擎，`ModelManager` 管 LLM/VL GGUF，
  节点上报 `llm.chat` / `vl.ask` 能力。
- 这轮先**只登记 URL + 明确归属**，引擎落地放下一轮。

## 5. 手机软件打磨 backlog（`tianwang_android` / `android_bridge`）

- `ModelManager`：扩模型档（§3.1）；加"按体积/量化筛选"；缺模型弹窗补 SDXL-Turbo 地址。
- `SdBridge`：稳态性能（查 179s/步 是否误回退 CPU）；加 `nativeBench()` 连续出图取均值；
  支持 SDXL 分辨率分支（1024）。
- `QueueRunner`：失败重试 / 断点；与 fleet 的 `image.gen` 派发对齐
  （PC 经 `android_bridge` 调 `SdBridge.enqueue` —— `image_gen_runner._default_backend` 的 TODO）。
- `Whisper` / `Speaker`：与 fleet 语音层对接（已有计划书）。
- `android_bridge`：无障碍桥加 UI 感知（`getRootInActiveWindow` 递归 + 剪枝），
  支撑包第三方 App 调 LLM/VL。
- 稳定性：`SelfTestActivity` / `DeviceCheckActivity` 跑通；`BenchRunner` 出标准报表。
