## 二、N+1 动手范围（五处改动，两个新文件）

### 2.1 后端 `fleet/skills_evolve.py`（加两个函数，不动现有）

**`rollback(name, to_sha=None)`** —— 回滚 = 提交的产物（v4 原话），用 git 当快照（P3 定的"不自己造快照机制"）：

1. `git log -- skills_evolved/<name>/SKILL.md` 取历史；`to_sha` 给了就滚到那一版，默认滚到**上一版**（当前 HEAD 的父）；
2. `git checkout <sha> -- skills_evolved/<name>/SKILL.md`；
3. 重生成 `_audit.json`（回滚后的文本必须重新过审查，不能沿用旧审计结论）；
4. `EVOLVED.jsonl` 记 `op=rollback`（p5 门禁白名单里已有这个 op，**只写不回写**——append-only 不动）；
5. **自验**：回滚后 `SK.load_skill()` 能加载 + `verify()` 四闸仍过；任一不过就**把工作区改回原样并报错**（回滚不许把仓滚坏）。
6. 没有历史可滚（就一版）→ 明确报错，不静默成功。

**`evolved_summary()``** —— 给 `/api/skills/evolved` 的清单：每张自写技能的 name/description/caps/evolved_from/ledger 最近一条/audit 结论。**正文不外发**（与 `skills.summary()` 同一纪律：38 张卡正文加起来不小，且 GUI 只是看清单）。

### 2.2 后端 `fleet/gui/server.py`（五个新端点，全走 `_authorized`）

| 端点 | 方法 | 后端 | 备注 |
|---|---|---|---|
| `/api/skills/evolved` | GET | `evolved_summary()` | 只读清单 |
| `/api/skill/stats?name=` | GET | `skill_stats(name)` | 记分；`verdict` 里"证据不足"字样**原样带给前端**，不许前端自己解读 |
| `/api/skill/use` | POST | `note_use(name, ok, detail)` | 选用留痕。body：`name/ok/detail` |
| `/api/skill/promote` | POST | `propose(trace,name,desc)` → `verify` → **前端确认后**才 `promote` | 提交。**GUI 不给 force 开关**——计划书§七"自动改技能并直接生效"明确不做；四闸不过就返回 gates 明细让前端显示哪闸红 |
| `/api/skill/rollback` | POST | `rollback(name)` | 回滚。前端二次确认后才发 |

**两步提交（人际确认才 promote，计划书§七）**：
- 第一步 `POST /api/skill/propose`（新端点，不落盘）：返回候选 SKILL.md 全文 + 四闸逐条结果；
- 第二步 `POST /api/skill/promote`（落盘）：body 带 `trace/name/desc`，服务端**重新 propose + 重新过闸**再落盘——不信任前端传来的候选文本（前端传什么就落什么 = 绕过闸门）。

### 2.3 前端 `ui/app.js` + `ui/app.css` + `ui/index.html`

技能 tab 从一区变三区：**本仓 / 用户级 / 自写（skills_evolved）**。

自写技能卡（新增 `.eskill` 系列样式，不动现有 `.card` 体系）：
- 元信息行：caps 数、evolved_from 条数、ledger 最近一条 op、audit 结论徽章；
- 记分区：使用次数、影子成功率（逐 cap 一行：`done/open/百分比`）、**verdict 原文**（"证据不足，分数不可信"就照显示，不打掩护）；
- 操作行：**「选用」**（成功/失败两个小钮，走 `note_use`）、**「提交」**（展开表单：trace + 名字 + 描述 → 先出四闸预览 → 「确认落盘」钮）、**「回滚」**（`confirm()` 二次确认 → 显示滚到哪个 sha）。

交互纪律：
- 所有 POST 走 `requireToken()`（没令牌就说清楚为什么，不发注定 401 的请求）；
- 按钮点了置灰 + 文案变"处理中…"，防连点；
- 结果用现有 `toast/showResult` 通道，不自造提示。

### 2.4 新门禁 `evals/t18_skill_desktop.py`（注册进 `run_selftests.CASES`）

离线、全本地（不起外网、不调模型），照 t7 的写法真起 `FleetServer`：

1. **端点存在性**：5 个端点各打一次，401/200 符合预期（缺 token 必须 401）；
2. **done 回执**：`POST /api/skill/use` 后，证据库里能查到 `topic=skill:use:<name>` 且 `status=done` 的事件（v4 门禁原话"真跑出技能 done 回执"）；
3. **端到端**：造一条真 exec trace（复用 p0_gate 的做法：临时库 + `execute.py` 真跑只读能力）→ `propose` → 四闸 → `promote` 落盘 → `rollback` 回滚 → **回滚后 `SK.load_skill()` 能加载 + `verify()` 四闸仍过**（v4 门禁原话"回滚后仍可加载、四闸过"）；
4. **红线**：四闸不过的候选（假溯源）`promote` 必须拒绝并指出哪闸红；
5. **前端**：`node --check ui/app.js` 语法 + 起服务拉首页冒烟（t7 已有同款，照抄结构）。

## 五、风险与回滚

| 风险 | 挡它的东西 |
|---|---|
| rollback 把仓滚坏（checkout 到坏版本） | 回滚后自验加载 + 四闸，不过就改回原样并报错 |
| 新端点没鉴权 | 5 个端点全走 `_authorized`；t18 第 1 项打缺 token 必须 401 |
| 前端连点产生重复 use 记录 | 按钮置灰；且 use 记录本就是"打点"，重复打点是数据不是事故 |
| 技能数上限（>30 先淘汰） | P4 已有约束，N+1 不新增技能只做机制，本轮不触及 |
| 整层回滚 | 三个目录/文件独立：`skills_evolved/` + `EVOLVED.jsonl` + t18；`git revert` 即回到今天 |
