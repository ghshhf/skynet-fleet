# 桌面端（Windows 图形版）工具链盘点与新装（2026-10-21）

> **本轮性质**：装工具 + 造验收工具，**不改产品代码**（`ui/` 一行未动）。
> 起因（你的原话）：「开发软件的时候缺少什么工具？UI 的时候有时候需要一些专业的
> 工具或者画图工具，你自己下载安装，要不然总感觉做的还不够完美。要么就总感觉
> 你直接是复制我拍照的。」

---

## 〇、一句话结论

**缺口不是「不会画 UI」，是「没有能判定 UI 好坏的尺子」。**

本机原有的能力：手写 HTML/CSS/JS + pywebview 窗口 + `mss`/`pillow` 截屏 + 一张
拍出来的参考图。缺的三样：

| 缺口 | 以前怎么办 | 现在怎么办 |
|---|---|---|
| 没有「改完到底变好还是变坏」的判据 | 靠人眼描述 + 感觉 | **Playwright 真渲染 + pixelmatch 像素级回归**（差异百分比是数字） |
| 没有「看着清楚」的判据 | 靠屏幕上看 | **axe-core 扫真实 WCAG 对比度比值**（3.65 vs 4.5 这种数字） |
| 没有「点了有没有反应」的判据 | 靠记忆 | **真浏览器点一遍 82 个可点元素**（有反应/没反应是二值事实） |
| 没有画线框图/对齐布局的手段 | 照抄照片 | **draw.io 桌面版**（离线） |

**「复制你拍照的」这个感觉，根因也在这**：只靠一张静态照片做参照，改完没有任何
东西能说明「更接近了」。现在有了基线图 + 像素差异百分比，**接近与否变成可核验的数**。

## 二、造出来的三个验收工具（`tools/uicheck/`）

**这是本轮最值钱的产出**：把「界面好不好看」从主观感受变成**三个可执行的判据**。

### 2.1 `shot.js` —— 真截图 + 像素级回归

```bash
node tools/uicheck/shot.js --out baseline        # 存基线
node tools/uicheck/shot.js --out current --diff  # 与基线像素级对比
node tools/uicheck/shot.js --theme dark --out dark
```

- Playwright + Chromium 以 **1440×900** 真渲染（和 pywebview 窗口同尺寸）；
- 自动起真本地服务（127.0.0.1 + 随机端口 + 一次性令牌），**不依赖外网、不依赖 pywebview**；
- 同时抓页面 JS 错误（`pageerror` / `console.error`）；
- `--diff` 用 pixelmatch 出**差异百分比 + diff.png**。

**实测**：连跑两次，差异 **0.412%**（来自 CPU/内存/进程表的实时数据波动）⇒
阈值设 2% 是合理的（真实回归改动会远超 0.5%）。

### 2.2 `a11y.js` —— 无障碍 + 对比度体检

```bash
node tools/uicheck/a11y.js --theme light
```

axe-core 扫 WCAG 2.0/2.1 A+AA，给出**真实比值**（不是"感觉偏灰"）。

**实测结果（这是本轮抓出的真问题）**：

| 主题 | 违规 | 典型证据 |
|---|---|---|
| light | **2 项 serious，32 处** | `.kbd` 快捷键标签 `#8f959e`/白底 = **3.01**（要 4.5）；`#verline` 版本号 = **2.76**；选中项 `#2f6bd8`/`#e8effc` = **4.31**（差 0.19 就达标） |
| dark | **2 项 serious** | 次要文字 `#6f7681`/`#1b1e22` = **3.65**；主蓝 `#5b8def`/`#1e2a3f` = **4.45**（差 0.05！） |
| 两者共有 | — | `#dpProcs` 进程表可滚动但**不能键盘聚焦**（`scrollable-region-focusable`） |

⇒ **这些是"截图上看挺好、实际看不清"的部分**。以前没人能判定，因为肉眼在
1440×900 截图上判断 10.5px 灰字的对比度极不可靠。

### 2.3 `clickaudit.js` —— 运行时点击体检（**替代 AST 扫 id 的正确口径**）

```bash
node tools/uicheck/clickaudit.js --json tools/uicheck/shots/clickaudit.json
```

真浏览器里**点一遍每个可点元素**，靠「点前点后 DOM 指纹是否变化」判定有反应。
指纹包含：可见元素数、文本长度、`body.innerHTML` 长度、`data-theme`、class/disabled 状态。

**为什么必须真点**（纠正计划书 `整体路线图` §五-X0 的门禁口径）：

| 计划书原口径 | 实测问题 |
|---|---|
| AST 扫 `index.html` 找带 `id` 的可点元素 | **漏报**：6 个 `.sb-item` 导航项**根本没有 id**（纯 class）⇒ 扫 id 抓不到，而它们恰是最大死链源 |
| 看它在 `app.js` 里「出现过」 | **误报**：`barCpu` 这类是 `setBar("barCpu",…)` 字符串传入，没有独立绑定 |
| —— | **正解**：真浏览器点一遍，「有没有反应」是二值事实，不用猜口径 |

**实测死链清单（14 条，与计划书估的 11 个吻合且更准）**：

| # | 元素 | 判定 |
|---|---|---|
| 1–6 | `.sb-item` × 6（新建任务/助理/专家技能·连接器/定时任务/资料库/更多） | 死链 |
| 7 | `.sb-foot`（人格入口） | 死链 |
| 8 | `.hbtn` 搜索（`⌕`） | 死链 |
| 9 | `.cbtn` 添加附件（`＋`） | 死链 |
| 10 | `.cbtn` 浏览访问权限 | 死链 |
| 11–13 | `.tb-win i` × 3（最小化/最大化/关闭） | 死链（**计划书漏了这三个**） |
| 14 | `#sendBtn` 发送 | **合理**：空输入时按钮 `disabled` ⇒ 不是死链（工具应记为「跳过」而非死链） |

> 工具自己也踩了两个坑并已修：①点之前把能力面板关掉 ⇒ 面板内 70 个「执行」按钮
> 全被判死链（其实是被遮挡）；②指纹只算 `body.innerHTML` 长度 ⇒ 明暗切换
> （只改 `<html data-theme>`）被误判死链。修法都在 `clickaudit.js` 注释里。

### 2.4 `run_all.bat` —— 一条龙

```bash
tools/uicheck/run_all.bat              # 截图+对比 / 无障碍 / 死链
tools/uicheck/run_all.bat --baseline   # 重设基线
```

实测退出码语义正确：`shot=0 a11y=1 clicks=1` ⇒ **红 = 真有问题**（沿用仓库老规矩
「门禁红必须意味着代码坏了」）。

## 三、画图工具（你提的「画图工具」）

| 工具 | 位置 | 用途 | 特点 |
|---|---|---|---|
| **draw.io 桌面版 32.5.5** | `D:/tools/drawio/draw.io.exe` | 画 UI 线框图、布局草图、信息架构图 | **完全离线**（不联网上传），导出 PNG/SVG/XML |
| 产物落点 | `ui/design/`（线框稿）、`tools/uicheck/shots/`（视觉基线） | | |

**为什么是 draw.io 而不是 Figma**：Figma 要账号 + 联网 + 商业条款；draw.io 桌面版
**离线免费**，且它的 `.drawio` 是 XML 文本文件 ⇒ 稿子能进 git、能 diff、能改。

**建议的用法（对齐「学 UI 而不是抄照片」）**：
1. 用 draw.io 画**结构稿**（三栏比例、卡片分组、信息密度）⇒ 你拍板结构；
2. 我按结构稿写 HTML/CSS；
3. `shot.js` 出真渲染图 → **与线框稿并排比对**（结构对不对）；
4. `shot.js --diff` 确认改动范围（改 A 没碰 B）；
5. `a11y.js` 确认对比度达标。

## 四、这套工具**不能**做什么（诚实版）

| # | 不能 | 说明 |
|---|---|---|
| 1 | 不能替代「这界面好不好看」 | 工具只给**客观判据**（差异%、对比度、反应与否）；审美还是要你拍板 |
| 2 | 不能自动修对比度 | axe 只报不修；改色板要人定（涉及品牌色） |
| 3 | 不能证明「学得像 WorkBuddy」 | 参照物是**你的照片**，照片有透视/裁切/反光；要比结构得先画线框稿 |
| 4 | 像素对比会因实时数据抖动 | 实测 0.412% 来自 CPU/内存/进程表；**阈值不能设 0**，2% 是实测定的 |
| 5 | 依赖仓库外 `node_modules` | 换机器要重装（命令已写进 `tools/uicheck/README.md`） |
| 6 | 没装 ImageMagick | 官网 404；Pillow + pixelmatch 已覆盖实际需求 |
